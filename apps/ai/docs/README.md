# PAYSE 공유 AI 모듈

Java 21 라이브러리이며 API Gradle의 `:ai`로 빌드한다. 별도 서버·포트·DB 없이 Spring Boot JAR에 포함된다. [개발 규칙](../AGENTS.md)은 코드 수정 전에 필수 참조한다.

```text
API: 인증·현재 원천 확인·재사용/예산/시도 관리
  → AnalysisService
    → AnalysisContract (구조·근거·기존 분류 검증)
    → InputMapper (최소 필드·요청별 짧은 ID)
    → ModelFactory → ModelGateway (계수 후 생성 1회)
    → InputMapper.restore (ID 복원·완결 결과 검증)
  → API: 현재 자격 재검증·결과 채택·암호화 저장·응답
```

## 파일 책임

| 경로                                 | 책임                                                                            |
| ------------------------------------ | ------------------------------------------------------------------------------- |
| `src/main/java/.../analysis/service` | 호출 순서. 정상 unknown과 실패를 구분하며 자동 재시도하지 않음                  |
| `analysis/mapper`                    | 요청마다 투영·ID 대응을 격리. 모델에 버전/세션 문맥·불필요한 금액을 보내지 않음 |
| `analysis/validation`                | 기존 두 업무 규격의 제한형 Schema·관계·완전성 검사. 소유권 증명은 아님          |
| `provider`                           | 공급자 중립 경계·실패 단계·사용량. HTTP 구현을 업무 서비스에 노출하지 않음      |
| `provider/openai`                    | OpenAI 전용 주소·자격·계수 요청·생성 옵션·응답/사용량 해석                      |
| `transport`                          | 제한 응답 크기·시간·리디렉션 금지 HTTP. API의 KMS 어댑터도 사용                 |
| `contracts`                          | 기존 41개 의미 기준과 네 개 Schema 원본. 합성 예시 포함 원본 자체는 배포 제외   |
| `src/main/resources`                 | 공개 프롬프트. 빌드는 기준표의 코드·표시명·필요/부족 근거만 추가                |
| `src/test`, `testing`                | 실제 Java 서비스 테스트·Python 대조 자료 생성. 운영 의존성으로 사용하지 않음    |

API의 `GoogleKms`, `EnvelopeCipher`, `MemoryPolicy`, 인증·DB·예산 책임은 이동하지 않는다. Flutter의 금액·기간·반복 계산과 공개 금융 v4 응답도 그대로다. 공급자별 차이는 `ModelFactory`로 주입하며 요청별 지침·스키마를 다른 요청과 공유해서 덮어쓰지 않는다.

## 사용과 검증

API 실행부가 인증·소유권·현재 원천·재사용·예약·동시성·설정 승인을 먼저 확인한 뒤 `AnalysisService.analyze`를 호출해야 한다. `ModelFactory`는 승인된 공급자 구현을 요청별 지침·스키마와 조합한다. OpenAI 구성에서는 고정 모델·키 공급자·추론 설정·상한으로 `provider.openai.OpenAiGateway`를 만든다. **서비스 생성만으로 외부 통신은 발생하지 않는다.** OpenAI의 입력 토큰 계수는 외부 전송이다. 다른 구현은 해당 모델의 로컬 계수를 사용할 수 있다.

저장한 응답만 필요할 때는 이 서비스에 다시 보내지 않는다. 기존 결과 반환·시도 합류는 API에서 처리한다. 원천으로 확인된 사실이나 사용자 정정은 모델로 다시 판정하지 않으며 유효 재사용 자격은 API에서 확인한다. 이 모듈에 합성 `verified=true`만 믿는 우회 경로는 없다.

루트의 `node scripts/harness/run-api.mjs check`는 API·AI Java 테스트, 주석, 기존 Python 평가/더미 검사, Boot JAR 포함/비공개 자료 제외를 검사한다. `apps/api`에서 `gradlew :ai:test`로 AI만 검사할 수도 있다. Java가 기존 Python 개발 자료 5,083건의 입력·투영·스키마·복원에 동의하는지 확인하되, 대조 정답을 모델에 전달하지 않는다. **이는 계약 호환 검사이며 실제 의미 정확도 측정이 아니다.**

## 아직 연결되지 않은 부분

- 분석 HTTP 접수/조회/재시도와 DB 작업 실행 서비스에서 이 모듈을 호출하는 배선.
- 운영 예산 예약·원천 재검증·개별 기억 암호화 저장·조회/삭제의 통합 구현.
- 실제 OpenAI/KMS 자격·요금·활성화, 실제 품질·토큰·지연 측정.
- 로컬 모델 어댑터·모델/토크나이저/템플릿·실행기·자격/통신·실측 사용량 구성. 교체 경계가 있다는 이유로 연결 완료로 취급하지 않음.
- Flutter 분석 화면 연결·외부 Android 통합·Play 배포 검증.

모듈·대역 테스트·배포 빌드 성공을 위 기능의 완료로 기록하지 않는다. 금액 계산이나 신규 금융/분석 HTTP 필드는 추가하지 않았다. 후속 작업은 [API 실행 상세](../../api/docs/llm-execution.md)와 [분석 API 작성안](../../api/docs/analysis-api.md)을 따른다.

## 공급자 교체 경계

Java 실행과 Python 평가를 유지한다. 향후 로컬 모델 실행기는 서버 내부에서 교체하는 대상이며 Flutter의 금융 계산·공개 v4 계약·DB 저장 규칙을 바꾸는 근거가 아니다. 로컬 모델/도구는 아직 선택하지 않았으며 별도 실행기를 설치하거나 자동 연결하지 않는다.

| 경계           | 공급자 구현의 책임                                                                                              | 공통 계층의 보장                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `ModelFactory` | 서버가 승인한 모델·주소·자격·옵션으로 구성. 금융 입력으로 공급자를 선택하지 않음                                | 요청별 지침·응답 스키마 전달; 생성 중 다른 모델로 전환하지 않음                                                         |
| `countInput`   | 실제 모델의 지침·스키마·템플릿까지 같은 입력을 계수. OpenAI는 전용 계수 API, 로컬은 검증된 토크나이저/상한 방식 | 기존 입력 한도를 적용. 계수 불가 시 생성 0회; 문자 수를 토큰 수로 취급하지 않음                                         |
| `generate`     | 출력/전체 context 한도와 완료·거절·잘림·사용량을 해당 공급자 형식에서 변환                                      | 생성 1회; 기존 ID·근거·완전성 검증; 자동 재시도·자동 외부 전환 없음                                                     |
| `ModelFailure` | `INPUT_COUNT`/`GENERATION`과 해당 단계의 `mayHaveBeenSent` 제공. 알려진 코드만 사용                             | 업무 서비스가 HTTP 예외에 의존하지 않음. 앞선 전송·미정산 비용을 지우는 근거로 쓰지 않으며 이력 저장은 API 연결 시 구현 |
| `TokenUsage`   | 관측 사용량을 정규화. 전체 미확인은 `usage=null`, 캐시만 미확인은 `cachedTokens=null`                           | 음수·캐시>입력 거절. 미확인을 0원으로 환산하지 않음; OpenAI의 기존 캐시 누락 처리만 해당 어댑터에 유지                  |

`ModelReply`·`TokenUsage`·`ModelFailure`는 Java 내부 형식이며 공개 HTTP/금융 응답 필드를 추가하지 않는다. 예산 예약·단가·현재 원천 검증·모델/정책/프롬프트 버전을 고려한 재사용은 API 책임으로 유지한다. 로컬 전환으로 기존 외부 API 비용 이력을 초기화하지 않는다.

예를 들어 계수 HTTP 응답 후 입력 초과면 `INPUT_COUNT / true`이며 생성은 0회다. 공통 서비스가 정상 계수 뒤 자체 한도에서 막으면 `GENERATION / false`로 생성 미전송을 표현한다. 이 값으로 앞선 계수 전송까지 없었다고 판단하면 안 된다. timeout은 해당 단계의 전송 가능성을 유지하며 실제 완료/과금을 확정하지 않는다.

교체 검증은 같은 업무 입력·스키마를 OpenAI 모의 HTTP와 HTTP 없는 대역에 주어 동일한 복원 결과를 확인한다. 계수 불가·초과·응답 오류·사용량 미확인·동시 요청 격리·재시도 금지도 함께 검사한다. 이는 실제 로컬 모델의 지원 형식·품질·속도·비용 검증을 대신하지 않는다. 새 어댑터 활성화 전에 모델·토크나이저·템플릿·context/출력 한도와 동일 자료의 실행 결과를 확인한다.
