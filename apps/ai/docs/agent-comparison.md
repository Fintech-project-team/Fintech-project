# 서버 준비와 에이전트 비교

2026-11-04. 기존 `fix/api/data-refresh-consistency`에서 수행했으며 commit/push하지 않았다. 이전 평가와 비공개 비용 장부를 보존했다. 실행 중이던 서버·DB·원격 연결은 변경하지 않았다.

## 적용한 서버 구성

명시적인 `gamma-local` 프로필로 감마 평가의 실제 런타임을 JAR에서도 사용할 수 있게 했다. 일반 API의 실행 한도는 유지하며 이 프로필만 동시 6, 입력/출력 12,000/4,000, 20초 제한, 자동 재시도 0을 쓴다. 번들 프롬프트 지문은 `PAYSE-PROMPT-4:f291746aec13df7870a0e407f9b2d4ca8e738c4019654d89379f96db863e099f`다.

최초 준비, 같은 설정 재사용, 손상된 준비 파일 복구를 실제 JAR 3회 기동으로 검사했다. 준비 횟수는 **1 → 1 → 2**, 유료 호출은 **0**이었다. 모델 접근 조회도 실제 1회 성공했고 두 번째 점검은 저장한 결과를 재사용했다. 모델 조회 성공을 Responses 권한/분석 성공으로 표시하지 않는다. 실제 분석에서는 공급자 응답·검증 성공·실패 시각을 별도로 기록했고 재시작 뒤 추가 호출 없이 저장 결과를 복구했다.

새 PC 설치, 상태 확인 명령, 비용/DB 전제, 키 보관 및 제거는 [API 시작 안내](../../api/docs/ai-startup.md)를 따른다. AI 준비 테스트는 기존 release workflow가 실행하는 `test_portable_server.py`에 포함된다. 배포 묶음에는 도구와 빈 설정 예제를 넣고 비공개 키·원천·정답은 넣지 않는다. 실제 운영 서버 교체는 수행하지 않았으므로 기존 실행 서버에는 다음 수동 배포부터 적용된다.

## API 에이전트 판단

현재 PAYSE는 `Responses` 직접 호출에서 매번 고정된 지시와 구조화된 입력을 보낸다. 대시보드에 에이전트만 만들면 기존 호출이 자동으로 그 설정을 쓰는 구조가 아니다. 저장된 에이전트는 해당 ID로 세션을 만들어 사용한다. [Agents 설정 문서](https://developers.openai.com/api/docs/guides/agents-api/configuration)

내장 다중 에이전트는 확인일 문서에서 GPT-6.1 Sol 및 GPT-5.6 모델의 베타 기능으로 명시돼 있다. 현재 사용 중인 Luna는 이 지원 목록에 명시돼 있지 않다. 모델·출력 처리·비용 예약까지 다른 실행 경계이므로 이번에는 활성화하지 않았다. [Responses 다중 에이전트 문서](https://developers.openai.com/api/docs/guides/responses-multi-agent)

실제로 비교한 것은 같은 Luna의 추론 강도 `low`, 그리고 도구/재귀 호출 없이 한 번만 독립 판단하는 재검토 역할이다. 재검토는 이전 답이나 정답을 받지 않는다. **네이티브 `multi_agent` 또는 원격 Agents API를 실제 실행한 실험은 아니다.** 추가 역할 지시와 추론 설정은 별도의 버전 지문으로 저장한다.

## 사전 정답과 비교 조건

## 채택 결과

연간 실행 중 같은 표본 355개를 대조하면 직접 호출에는 미완료 30개가 있었다. 실패율의 변동을 제거한 참고 비교로 **양쪽 모두 정상 완료한 동일 325개**도 별도 집계했다. 전체 분모 점수를 대체하지 않는 보조 지표다.

- 직접 호출: 기본 100%, 의미·확인 99.38%.
- 독립 재검토: 기본 100%, 의미·확인 99.08%.
- 재검토가 의미 오류 1개를 고쳤지만 2개를 새로 만들었다. `save_installment` 조건에서 수정/퇴행이 각각 있었고 `ride_ticket`에서도 퇴행했다.
- 재검토 표본에는 근거 없는 확정 1개, 불필요한 의미 유보 2개가 남았다. 단일 실행의 장애 감소를 에이전트 고유 효과로 단정할 수 없다.

**기본은 직접 호출을 유지한다.** 모든 자료에 한 차례 더 재검토를 붙이면 그 호출 시간과 비용이 추가되고 현재 비교에서는 의미 정확도 개선도 입증되지 않았다. 별도 원격 에이전트나 Agents SDK 자동 설치를 추가하지 않았다. 일회성 준비는 선택된 `DIRECT_BUNDLED` 정의의 존재·버전·지문을 점검하고 누락/손상 시 복원한다. 미지원 에이전트 모드는 조용히 대체하지 않고 시작을 거절한다. 향후 원격 에이전트를 채택하려면 해당 공급자/출력/비용 경계를 실제 비교 검증한 뒤 이 버전 있는 프로필을 교체해야 한다.
