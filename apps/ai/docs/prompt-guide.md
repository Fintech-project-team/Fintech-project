# 거래 분석 프롬프트 자료와 재현 절차

2026-11-04. 기존 감마 평가에서 나타난 기본 분류 오류·근거 혼동을 줄이기 위해 공개 규칙과 일반화한 교육 예시를 추가했다. 실제 모델의 가중치를 학습하거나 영구 기억을 만들지 않는다. 같은 자료를 요청마다 제공하는 방식이며, 다른 공급자도 `ModelFactory`·`ModelGateway`를 통해 동일한 지침·최소 입력·응답 스키마를 받는다. 모델 간 동일한 속도·정확도를 보장하지 않는다.

## 사례 분류

[분류 목록](prompt-cases.json)은 이전 1,837개 판단 항목을 90개 사례군으로 묶은 개발 자료다. 사용자·계좌·거래 ID, 전체 원천, 실제 모델 응답은 포함하지 않는다. `example`은 기존 합성 원천의 종류·방향·상태·적요이며, `meaning`·`basicType`·`meaningReason`·`review`는 분석 전 작성된 정답의 유형이다. `baselineErrors`는 중복 가능한 오류 종류별 빈도이므로 합을 오답 거래 수로 해석하지 않는다. 이 파일은 운영 JAR·프롬프트에 들어가지 않는다.

## 실행 자료와 조립

| 파일/코드                       | 책임                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------- |
| `contracts/meaning-policy.json` | 기존 41개 의미의 단일 기준. 평가 positive/contrast는 계속 제외                         |
| `rules/instructions.txt`        | 입력 격리·원천 우선·계산/자동 승인 금지·응답 규격                                      |
| `rules/prompt-guide.json`       | 공개 교육 규칙, 5개 선택 구간, 가상 예시 10개                                          |
| `AnalysisContract`              | 반복 근거를 사전 참조로 줄이고 각 의미의 원래 근거·순서·적용 범위를 보존               |
| `PromptGuide`                   | 업무·원천 종류·방향으로 구간 선택. 적요·상호로 예시 검색하거나 추가 모델 호출하지 않음 |
| `InputMapper`                   | 요청별 ID 대체, 검증된 원천 보충, 항목별 근거 묶음. null 보충 필드만 생략              |
| `AnalysisService`               | 같은 지침·스키마로 계수 후 생성 1회, 복원·기존 검증                                    |

선택 구간은 입금, 이체, 계좌 지출, 카드, 반복 후보다. 각 구간에 예시 2개를 둔다. 거래 요청은 해당 원천 종류가 존재하는 구간만, 반복 요청은 반복 구간만 제공한다. 근거 부족·충돌·목록 밖의 구별과 기본 분류 원칙은 모든 요청에 적용한다. 전체 거래·평가 정답을 검색 DB에 저장해 찾거나 그대로 외우게 하지 않는다.

모델 입력의 각 item 안에는 판단 대상 `target`, 그 항목의 다른 근거 `transactions`, 확인된 `relations`, `existingClassifications`를 둔다. 반복 항목은 `candidate`와 그 근거를 받는다. 여러 거래를 섞어 판단하던 첫 실측 오류를 줄이기 위한 서버 내부 투영이며, 공개 앱 입력·출력·DB 원천은 바꾸지 않는다. 참조 ID와 관계를 새로 추정하지 않으며 다른 item의 거래는 근거로 사용할 수 없다. 출력은 기존 itemKey별 규격으로 복원·검증한다.

37개 의미에서 반복되는 근거는 `commonEvidence` 사전에 한 번 넣고 각 행의 같은 필드 배열에서 정수 색인으로 참조한다. 이를 펼치면 원래 41개 기준의 값·순서가 정확히 같음을 검사한다. 모든 의미에 같은 문구가 있다고 가정하거나 공통 문구를 적용하지 않던 의미에 추가하지 않는다.

예를 들어 ‘월급이 아닌 출장비 실비 반환’은 세부 의미 `reimbursement`와 기본 분류 `unknown`을 함께 가르친다. `card_refund`는 `refund` 후보여도 새 `income`이 아니다. 관계 없는 같은 금액의 두 거래는 본인 이체를 확정하지 않는다. 예시의 사유 코드는 세부 의미용이며 기본 분류는 독립 사유를 반환한다.

모델 앞부분에는 고정 기준·지침을 두고 선택 예시, 요청별 원천을 뒤에 둔다. 재사용 가능한 접두부는 공급자의 캐시에 도움이 될 수 있지만, 캐시 적중·처리 시간은 모델과 실행 상황에 따라 달라진다. [공식 프롬프트 지침](https://developers.openai.com/api/docs/guides/prompt-engineering), [캐시 기준](https://developers.openai.com/api/docs/guides/prompt-caching), [지연 최적화](https://developers.openai.com/api/docs/guides/latency-optimization)를 참고했다. 별도 벡터 DB·임베딩·모델 분류 호출은 추가하지 않았다.

## 버전과 변경 절차

`AnalysisService.promptVersion()`은 `PAYSE-PROMPT-3:`와 SHA-256 지문을 반환한다. 지문에는 공개 기준/기본 지침·교육 JSON의 내용·저장 지침·서버 원천 설명과 조립 버전이 들어간다. 교육 JSON의 들여쓰기만 바뀌어도 다른 프롬프트가 되지는 않는다. 운영 구성과 감마 시험 구성 모두 실제 서비스 지문을 캐시 자격에 사용한다. 요청별 원천은 기존 API 입력 지문, 모델은 기존 모델 버전으로 구별한다. 조립 코드/선택 규칙 변경 때도 `PROMPT_RENDERER`를 올린다. 사용자 정정·삭제·권한 검사를 이 지문으로 대신하지 않는다.

새 유형을 추가할 때는 현재 계약의 분류 코드·필요 근거를 먼저 확인하고 교육 규칙/예시를 작성한다. 개인정보나 특정 거래의 확인 결과를 공용 예시로 올리지 않는다. 평가 파일에서 정답을 자동 추출해 프롬프트에 붙이지 않는다. 긍정·모호함·부정/충돌 반례와 현재 거래의 근거를 구별하고 회귀 검사 후 버전을 기록한다.

이번 공개 교육 자료는 사용자의 ‘분류된 결과로 프롬프트를 작성하고 Git에 저장’ 요청으로 추가했다. 기존 지침의 비공개 평가 정답 제외 원칙은 유지한다. 공개 교육 예시와 `contracts`의 평가 예시·동결 정답을 혼용하지 않는다.

## 재현과 다른 모델 비교

저장소 루트에서 실행한다. 첫 명령은 기존 결정적 생성기로 같은 연간 자료를 새 로컬 디렉터리에 만든다. 기존 동결 파일을 덮어쓰지 않는다.

```text
python -B apps/api/testing/analysis/gamma_evaluation.py --prepare .harness/gamma-frozen
python -B apps/ai/testing/prompt_review.py catalog --dataset .harness/gamma-frozen --baseline <이전-live-summary.json> --out .harness/prompt-cases.json
python -B apps/ai/testing/prompt_review.py subset --dataset .harness/gamma-frozen --batches 16 --out .harness/prompt-sample
python -B apps/api/testing/analysis/gamma_local.py --live --pg-bin <PostgreSQL-bin> --work-dir .harness/prompt-live --env-file .env.local --evaluation-dir .harness/prompt-sample --reserve-krw 3000
python -B apps/ai/testing/prompt_review.py compare --dataset .harness/prompt-sample --baseline <이전-live-summary.json> --revised .harness/prompt-live/live-summary.json --out .harness/prompt-comparison.json
```

`--live`는 실제 비용이 생기는 별도 명시 실행이다. 위 명령을 기본 CI에 넣지 않는다. 기존 키·감마 전용 로컬 암호화·폐기용 DB·누적 비용 장부·자동 재시도 금지를 사용한다. `--reserve-krw`는 평가 실행 예약을 기존 25,000원 이내로 줄이는 옵션이며 일반 프로필이나 누적 45,000원 차단선을 늘리지 않는다. 이 실행기는 현재 승인된 OpenAI 모델용이다. 다른 공급자는 기존 `ModelGateway`에 해당 모델의 계수·생성·실패·사용량 어댑터를 구현하고 계약 검사 후 별도 승인된 실행 구성으로 주입해야 한다. 모델 이름만 임의로 바꿔 다른 공급자 연결이 완료됐다고 볼 수 없다.

표본은 모델 응답·오답을 보지 않고 사전 정답의 조건/난점/확인 유형을 최대한 포함하도록 탐욕 선택하며 동률은 사례 이름순이다. 16묶음은 거래 150개와 반복 후보 12개다. 같은 원천·정답을 그대로 복사하고 부모/표본 해시를 기록한다. 기존 평가 자료와 이번 프롬프트 개발 자료이므로 독립 최종 평가가 아니다.

새 모델 비교에는 모델/옵션·프롬프트 지문·원천/정답 해시·묶음 크기·입출력 제한·예산/사용량·동시성·캐시 상태를 함께 남긴다. 의미/기본 분류/둘 다 정답 비율, 오탐·불필요 유보·올바른 유보·근거/사유 오류·실패를 같은 분모로 계산한다. 응답 지연과 토큰을 분리하고 실패/미측정을 0초·무료·정답으로 바꾸지 않는다. 캐시가 차가운 실행과 따뜻한 실행, 다른 시각 실행을 구별한다. 비용 승인을 받아 반복 측정하기 전에는 한 번의 빠른 결과를 속도 보장으로 해석하지 않는다.

기존 일반 6,000/1,200토큰 프로필은 유지한다. 감마 평가는 이전 승인된 12,000/4,000을 사용한다. 입력 압축이 모든 요청을 일반 상한 안으로 만든다는 보장은 없으며 초과하면 기존 계수 단계에서 생성을 차단한다. 서버 배포·실기기 화면·새 공급자 실제 실행은 이번 검증과 별개다.

## 이번 실행 결과

2026-11-04, `gpt-6-luna`, reasoning `none`, 입력/출력 상한 12,000/4,000, 동시 실행 1개로 같은 16묶음·162개 항목을 세 차례 실행했다. 각 실행은 생성 16회와 외부 계수 16회이며 자동 재시도는 하지 않았다. 원천 1,825개 전체를 한 호출로 보내지 않고 각 항목의 참조 근거만 사용했다. 기존 연간 평가 중 **같은 거래 150개·반복 후보 12개**의 결과를 기준으로 비교했다.

최종 채택은 두 번째 실행이다. 공개 자료 버전은 `PAYSE-GUIDE-2`, 실제 프롬프트 지문은 `PAYSE-PROMPT-3:5637bc8a4b8a191698736688735a29674e204931b9765566911468b0a3a15523`이다. 세 번째 수정안은 분석 실패가 늘어 폐기했다. 그 실행의 집계 파일에는 세부 오류 코드가 없어 정확한 실패 규칙은 확인하지 못했다. 더 빠른 실패 응답을 개선으로 채택하지 않았다.
