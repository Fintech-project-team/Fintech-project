# 새 연간 자료와 누적 분석 검증

2026-11-04, `fix/api/data-refresh-consistency`. 기존 표본의 불필요한 기본 분류 유보 22건을 해결했다. 후속 연간 평가와 추가 분포 반복에서 각각 250.749초·274.683초, 세 정확도 90% 이상을 확인했다. 마지막 반복은 기본 99.89%·의미 99.18%·확인 경로 99.45%이며 전송/형식 실패 0건이다. 첫 연간 실패와 두 번째 연간의 시간 초과 2묶음도 보존한다. 실제 서버 배포·모바일 UI 검증은 하지 않았다.

## 실행하는 문서

`src/main/resources/com/payse/ai/rules/guidance.md`를 모델이 매 요청에서 실제로 읽는다. `PromptGuide`는 기준표·Markdown·원천 종류별 공개 예시를 조립하고 내용 지문을 API 재사용 조건에 넣는다. `ModelFactory`가 바뀌어도 이 조립·검증 경로를 유지한다. 다른 모델의 동일 정확도·동일 지연은 보장하지 않는다.

- 기본 분류와 의미를 독립 판정한다. 품목 없는 실제 카드 구매는 지출 후보이면서 의미는 유보할 수 있다.
- 확인된 관계와 원천 종류를 적요보다 우선한다. 관계 없는 일반 송금을 개인 간 송금으로도 추측하지 않는다.
- 상태·값·근거 코드가 일치하는 실제 JSON 객체 형태로 예시를 제공한다.
- 목록 밖 목적, 근거 부족, 서로 충돌하는 근거를 구분한다. 지출한 용역비를 받은 사업소득으로 뒤집지 않는다.
- 해석 이유와 보존 이유를 짧게 쓴다. 고정된 계약 오류 코드만 기록하며 원문은 로그에 남기지 않는다.

공개 금융 Schema·원천·계산·사용자 확인 정책은 유지한다. 일반 API는 대기 사용자 2/전체 20, 실행 사용자 1/전체 2다. 감마 시험 구성에서만 명시적으로 1..6개 동시 요청을 선택한다.

## 자료와 사전 정답

`apps/api/testing/scenarios/gamma_fresh.py`가 새 문장·거래처·금액·ID·관계를 만든다. 365일, 거래 1,825건, 반복 후보 10건이다. 계좌 거래 1,000건 중 주 계좌 800건, 나머지 다섯 계좌 각 40건이며 미사용 계좌는 세 개다. 카드 거래·취소·환불은 별도로 포함한다. 조회·잔액·기준 시각 검증을 통과해야 동결한다.

계좌 달력과 분류 체계는 기존 합성 자료의 골격을 공유한다. 실제 고객 모집단이나 새로운 금융 분류의 일반화 평가가 아니다. 원천의 `(거래처, 적요)` 조합과 거래 ID 중복 여부는 별도 검사한다.

실행 전 `source.json`, `inputs.json`, `expected.private.json`을 각각 해시로 고정한다. 원천/모델 입력에 정답 분류·난점·확인 경로를 넣지 않는다. 정답은 생성 후 채점에서만 읽는다. 정답·모델 응답·비용 장부는 `.harness/` 아래 Git 제외 자료다.

## 대량 요청 이후 새 표본

앞선 2,147개 판단 요청 뒤 문서를 보완하고, 새 표현 연간 자료에서 결과를 읽기 전에 조건·난점·확인 경로 기준으로 고정한 12묶음 175개를 실행했다. 거래 165건과 반복 후보 10건이며 이전 응답이나 정답을 모델에 보내지 않았다.

- 거래 기본 분류 165/165 (100%), 의미 163/165 (98.79%), 확인 경로 164/165 (99.39%).
- 반복 후보 10/10 일치. 전체 확인 필요 항목 38/38을 올바르게 유보했다. 근거 부족 항목의 의미 오탐 0/38, 불필요 의미 유보 1/133.
- 12회 생성·12회 계수, 실패 0, 175개 암호화 저장·재시작 복구. 전체 분석 29.736초.
- 새 지문: `PAYSE-PROMPT-4:f291746aec13df7870a0e407f9b2d4ca8e738c4019654d89379f96db863e099f`.

두 의미 오답은 현금 인출을 유보하거나 예금 만기로 분류한 경우다. 정답은 바꾸지 않았다. 이 결과를 보고 프롬프트를 다시 수정하지 않았다. 작은 후속 표본 통과는 동일 문서의 장시간 연속 처리나 전체 연간 5분 달성을 증명하지 않는다. 첫 연간 실패와 후속 표본의 개선을 함께 보존한다.

## 비용과 재현

초기 개발 표본·종전 회귀·첫 새 연간 실행의 알려진 사용량을 일반/캐시 입력·출력 단가로 계산하면 약 $0.1545다. 캐시 쓰기·미확정 생성까지 보수적으로 잡으면 약 $0.3874다. 실제 청구 확정액과 다르다. 계수 요금은 공식 문서에서 별도 단가를 확인하지 못했다. 무료로 기록하지 않으며 임시 보류액도 실제 지출로 표시하지 않는다.

후속 표본까지의 보수적 생성 추정은 $0.422361, 두 번째 전체 연간 실행은 $0.356945, 추가 연간 분포 반복은 $0.352722로 합계 **$1.132028**이다. 생성·계수는 각각 375회다. 사용량이 알려진 요청의 기본/캐시 읽기/출력 단가 합계는 약 $0.4306이며 캐시 쓰기·사용량 불명 요청 때문에 실제 청구와 다를 수 있다. 실제 계정 잔액과 로컬 원장 금액은 이 문서에 기록하지 않는다.

사용자가 2026-11-04에 승인한 대로 계수 요금의 과도한 건별 임시 예약을 공통 $2 예비비로 정리했다. 기존 두 원장을 별도 백업하고, 이전 예약액·실행 이력·시간 초과의 최대 생성 비용은 보존했다. 원장 정책은 `approved-shared-count-2usd-20261104`이며 $20 하한과 기존 45,000원 차단선을 함께 검사한다. 계수 무료 확인이나 실제 청구 정산으로 표현하지 않는다.

사용자 확인 잔액과 하한은 비공개 장부에서 읽는다. 실제 잔액·API 키·마스터 키는 Git에 넣지 않는다. 사용량 불명 실행은 최대 생성 비용을 남기고 기존 KRW 장부와 USD 제한을 함께 적용한다. 잔액 화면이 그대로여도 비용을 0으로 판정하지 않는다.

원천·정답 준비와 채점은 공급자를 호출하지 않는다. 출력 폴더는 새 이름이어야 한다.

## API 에이전트 구성 검토

2026-11-04 공식 OpenAI 문서와 현재 `OpenAiGateway.payload/generate`를 대조했다. 현재 구현은 Responses API 요청마다 모델·MD로 조립한 instructions·추론 `none`·엄격 JSON Schema를 직접 보낸다. 도구 목록은 비어 있고 저장 에이전트 ID를 참조하지 않는다. 따라서 플랫폼에서 저장 에이전트를 편집해도 현재 PAYSE 호출에 자동 반영되지 않는다. 저장 설정을 쓰려면 호출 경로를 연결해야 한다. [저장 에이전트 설정](https://developers.openai.com/api/docs/guides/agents-api/configuration)

Responses API에는 `multi_agent.enabled`와 beta 헤더로 켜는 내장 서브 에이전트가 있다. 현재 해당 안내가 명시한 지원 대상은 GPT-6.1 Sol 및 GPT-5.6 계열이다. Luna 지원 여부와 이 계정의 접근 가능 여부는 확인되지 않았다. Agents API의 세션별 `agent.multi_agent`는 별도 경로다. 두 API의 필드·기본 동시성·출력 수집 방식을 섞으면 안 된다. [Responses Multi-agent](https://developers.openai.com/api/docs/guides/responses-multi-agent), [Agents API Multi-agent](https://developers.openai.com/api/docs/guides/agents-api/multi-agent)

| 현재 단일 분류 요청을 제한 병렬 처리 | 작은 거래 묶음을 독립적으로 처리             | 이미 6개 동시 요청으로 연간 4분 10.7초. 기본 경로 유지                        |

권고안은 일반 거래를 현재 경로로 처리하고, **근거는 충분하지만 해석이 충돌하는 항목만 최대 1회의 전문 검토**에 보내는 구조다. 근거 자체가 없거나 상대 계좌 확인이 불가능한 항목은 사용자 확인으로 남긴다. 다수결도 존재하지 않는 원천 사실을 만들 수 없다. 검토 후에도 근거 ID·관계·소유권·버전·JSON 검증과 사용자 확인을 거쳐야 한다.

이는 아직 실측하지 않은 설계 판단이다.
