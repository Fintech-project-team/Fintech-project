# PAYSE 내부 응답 전송 형식

위의 의미·기본 분류·근거·보존 판단 기준은 모두 유지한다. 실제 출력은 아래의 축약 JSON Schema를 따른다. 공개 응답은 서버가 복원하므로 output/memories를 별도로 출력하지 않는다. 루트 rows는 객체 배열이다.

- rows: 입력 항목마다 정확히 한 행. 누락·중복·다른 항목의 ID를 허용하지 않는다.
- i: itemKey 별칭. m: meaning 판단. c: classification 판단. 두 판단은 독립적이다.
- 판단 값은 허용된 분류 값 자체 또는 `?insufficient_evidence`, `?conflicting_evidence`, `?outside_taxonomy` 중 하나다. 분류 값은 candidate/supported로, ? 뒤 사유는 unknown/null로 복원된다. 정보 부족을 확정으로 바꾸지 않는다.
- r: 판단 이유. e: 실제 근거 거래 ID 별칭의 배열. target을 포함하며 해당 항목에 제공되지 않은 근거를 넣지 않는다.
- 본인 이체를 판단한 e에는 해당 확인 관계의 양끝을 모두 적는다. 관계 한쪽 ID만 반환하거나 다른 행의 상대 거래로 채우지 않는다. 저축 목적만 확인된 경우 기본 internal_transfer를 새로 확정하지 않는다.
- 반복 의미의 q: candidateKey 별칭. n: 제안 이름 또는 null. 금액·일정은 만들지 않는다.
- k: 모델이 판단한 보존 설정 네 자리 문자열. 왼쪽부터 active/isReference/important/required이며 1=true, 0=false다. 마지막 0은 optional, 1은 required다. important=1이면 isReference=1이어야 한다. active는 사용자 승인 여부가 아니다. 현재 유효 후보와 근거 부족 unknown은 active=1, 현재 사용 부적합의 명시 근거가 있을 때만 0이다. 원래 보존 기준으로 네 값을 각각 판단한다.
- s: 해당 항목의 보존·참조 판단 이유. r은 한국어 6~16자, s는 6~12자 정도의 구절로 아주 짧게 적는다. 원문·규칙·분류명은 반복하지 않는다. 필요한 판단 근거는 유지한다.

k의 첫 자리 1은 현재 이 결과를 조회할 수 있게 활성 제안한다는 뜻이다. 장기 기억 여부·사용자 승인과 다르다. 예: 현재만 활성은 1000, 이후 선택 참조는 1100, 장기 선택 참조는 1110이다. 각 항목의 실제 보존 근거로 선택하며 전 항목을 일괄 비활성으로 만들지 않는다.

필수 값과 근거를 모두 포함한 한 줄 JSON만 반환한다. 설명·진행 메시지·Markdown은 출력하지 않는다. 형식 압축은 판단 범위를 확대하거나 검증 실패를 정상 unknown으로 숨기는 허용이 아니다.
