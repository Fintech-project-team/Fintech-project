# AI 서버 준비와 상태

2026-11-04 기준. `gamma-local`은 폐기 가능한 감마 전용 배포 프로필이다. 일반 로그인·금융 조회 계약은 유지한다. 분석 controller에는 인증된 감마 사용자와 서버 설정의 현재 합성 `sourceVersion`이 모두 일치해야 접근할 수 있다. Google KMS 대신 로컬 키를 쓰는 범위는 이 프로필로 한정한다.

## 준비의 의미

서버는 이미 JAR에 들어 있는 `guidance.md`, 프롬프트와 `performance.json`을 사용한다. 학습·대화 기억·정답 업로드·전체 평가를 시작 시 실행하지 않는다. 현재 검증 프로필은 Luna, reasoning `none`, 입력/출력 12,000/4,000, 요청 제한 20초, 자동 재시도 0, 실행 동시 6이다. 배치 15는 호출 측 권장값이며 서버가 앱 요청을 자동으로 연간 배치로 바꾸지는 않는다. 이전 평가의 5분 이내 결과는 동일한 배치·원천·환경의 근거이고 모든 PC의 시간 보장이 아니다.

최초 시작 시 `ai-profile.json`과 `ai-status.json`을 비공개 폴더에 원자적으로 기록한다. 프롬프트·성능 프로필·LLM 자격 지문·암호화 키 지문·가격 정책 버전·원천 버전이 같고 설치 프로필이 온전하면 `preparedAt`과 `preparationCount`를 보존하고 `preparationReused=true`로 표시한다. 손상·누락·변경은 다시 준비하며 분석 성공 기록을 초기화한다. 프로필이 검증된 프롬프트와 다르면 시작을 거절한다. 시작 때 검증을 생략한다는 뜻은 아니며 유료/전체 동작을 반복하지 않는다는 뜻이다.

현재 에이전트 모드는 `DIRECT_BUNDLED`다. 별도 원격 에이전트나 Python Agents SDK 설치가 필요하지 않다. 준비 파일이 없으면 번들 정의를 복원한다. 검증되지 않은 원격 에이전트 생성·유료 도구·다른 모델을 자동 설치/활성화하지 않는다. 에이전트 비교 결과에 따라 검증 프로필을 교체하는 방식이며, 미지원 모드는 시작을 거절한다.

## 새 PC

검증된 CI 배포 묶음과 Java 21, Python 및 묶음의 `requirements.txt`, PostgreSQL을 준비한다. `portable_server.py doctor`로 도구·메모리·주소 후보를 확인하고 `configure`에서 비공개 폴더를 지정한다. 감마 AI 준비 질문에 `YES`를 입력하면 기존 API 키 파일을 명시 선택하고 전용 32바이트 로컬 키와 상태 폴더를 만든다. 기존 키를 대체하지 않는다. DB 비용 프로젝트·가격 버전·감마 원천 버전은 운영자가 준비한 값을 입력한다.

DB에는 기본 테이블 외에 기존 분석/비용 스키마가 필요하다. 설치 도구는 catalog와 명시 비용 정책의 모델·토큰 한도·로컬 키 단가를 읽어 확인하며 스키마/원천/가격/비용 장부를 자동 이행하거나 초기화하지 않는다. 비용 프로젝트의 모델과 12,000/4,000 한도가 번들 프로필과 같고 로컬 키 단가는 0이어야 한다. 기존 USD 하한과 KRW 차단선을 반영한 승인 한도를 DB에 설정해야 한다. 준비 성공은 잔여 크레딧을 읽었다는 뜻이 아니다.

`install`의 기본 호환성 검사 후 `--apply`로 새 폴더에 설치하고 `start`로 켠다. 방화벽/관리자 권한/HTTPS 공개는 기존 설치 정책대로 별도 승인하며 자동으로 열지 않는다. 설정 파일과 키는 Git 밖에 보관하고 공유 템플릿의 현지 값은 빈 값으로 유지한다. Git 안의 무시된 `.env.local`은 명시적 API 키 입력원으로만 읽을 수 있다.

기존 Windows `launch.json` 어댑터는 AI 준비/상태를 지원하지 않으므로 이 프로필을 거절한다. AI 배포는 portable 설치 도구를 사용한다. 새로운 배포 도구 버전으로 업그레이드할 때에는 새 배포 묶음의 `portable_server.py`로 배포를 시작한다. JAR와 관리 도구를 함께 백업/교체/복구한다. 실행 중인 서버의 설정을 몰래 바꾸거나 자동 재시작하지 않는다.

## 운영 확인

```text
python portable_server.py status --home <전용 설치 폴더>
python ai_setup.py status --properties <비공개 server.properties>
python ai_setup.py check --properties <비공개 server.properties>
```

`status`는 추가 API 요청을 하지 않는다. `preparation`은 설치 준비, `runtimeReady`는 현재 관리 대상 프로세스의 준비, `modelAccess`와 `modelAccessCheckedAt`는 마지막 모델 접근 조회 결과다. 접근 조회만으로 Responses 호출 권한이나 실제 분석 성공을 확인했다고 표시하지 않는다. `providerSuccessAt`는 실제 분석 과정에서 받은 공급자 응답, `analysisValidatedAt`는 서버 출력 검증을 통과한 시각이며 DB 저장 성공과는 구분한다. 타임아웃·거부·실패는 `lastEvent`와 관측 시각으로 구분한다. 과거 시각을 현재 연결 보장으로 해석하지 않는다.

`start`는 키/모델 조합의 최초 모델 접근 점검만 수행하고 성공한 점검은 재사용한다. `check`는 접근 확인을 명시적으로 다시 실행한다. 두 동작 모두 생성·계수·학습 요청을 보내지 않는다. 접근 실패가 있어도 금융 API 서버는 시작할 수 있고 AI 상태는 실패로 표시한다. 실제 생성 실패는 기존 분석 오류 계약으로 반환한다.

## 제거와 보관

테스트 종료 시 `analysis,gamma-local` 프로필과 `payse.gamma-local.*` 설정을 제거한다. 감마 배포 구성과 로컬 키 구현, 준비 클래스, 준비 도구/프로필 리소스는 분리되어 있다. 보관된 감마 암호화 결과를 폐기하기 전에는 기존 로컬 키를 삭제하거나 새 키로 덮지 않는다. 일반 Google KMS 구성과 테스트의 비용 장부는 자동으로 수정하지 않는다.
