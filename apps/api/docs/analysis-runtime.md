# 분석 실행 설정

2026-11-03 기준. 기존 분석 API와 공유 AI 라이브러리를 실제 공급자·비용 장부·KMS에 연결하는 서버 구성이다. 기본값은 비활성이다. 현재 운영 서버에 이 프로필을 배포하거나 실제 OpenAI/KMS를 호출한 상태는 아니다.

## 활성화 조건

1. 연결한 OpenAI API 조직 안에 PAYSE 전용 프로젝트를 만들고 그 프로젝트의 API 키를 발급한다. ChatGPT/Codex 로그인 자격은 사용하지 않는다.
2. 기존 모든 API 사용액과 미확정 청구를 확인하고 비용 정책을 준비한다. 구독 크레딧은 결제 수단이며 PAYSE 총예산을 초기화하지 않는다.
3. Google Cloud KMS 키와 해당 키의 암호화·복호화 권한을 준비한다. OpenAI 구독 혜택에 KMS 비용이 포함된 것으로 간주하지 않는다.
4. 기존 DB에 `003_auth_access.sql`이 적용된 것을 확인하고 `012_analysis_costs.sql`을 psql 파일 실행으로 한 번 적용한다. 이행은 단일 트랜잭션이다. JAR 시작 시 자동 실행하지 않는다.
5. 저장소 밖에 `analysis.properties`, 기존 형식의 `llm.properties`, KMS 액세스 토큰 파일을 두고 서비스 계정만 읽도록 제한한다. Git에는 빈 예시만 둔다.
6. `database,auth,finance,analysis` 프로필과 `payse.analysis.settings-file`의 절대 경로를 명시한다. 환경 변수 `PAYSE_ANALYSIS_SETTINGS_FILE`로 경로를 전달할 수도 있다.
7. CI 검증 후 수동 배포한다. 기존 설정·인증서·DB를 JAR로 덮어쓰지 않는다.

`deploy/analysis.properties.example`의 값을 실제 비공개 파일에서 채운다. Windows 경로도 `C:/.../analysis.properties`처럼 슬래시를 쓰면 properties 이스케이프 혼동을 피할 수 있다. 새 PC에서는 그 PC의 비공개 경로·DB·KMS·프로젝트 자격을 지정한다. 컴퓨터 IP를 API 키나 조직 식별자로 사용하지 않는다.

`enabled=false`는 명시 비활성이다. 빈 예시는 복사만으로 활성화되지 않으며, 활성 설정의 누락·중복 키·미등록 키·모델/단가 불일치는 시작 오류로 처리한다. 별도 모의 응답으로 바꾸지 않는다.

KMS 토큰 파일은 호출마다 다시 읽는다. 이 구현은 Google 로그인이나 토큰 자동 갱신기를 설치하지 않는다. 운영 인증 공급자가 파일을 원자적으로 갱신해야 하며, 만료·권한 오류는 분석 실패로 처리한다. 키 파일을 채팅·Git·명령줄 인자에 넣지 않는다.

## 비용 정책

`payse.analysis_cost_projects`는 운영자가 설정한다. 앱 역할은 직접 조회·수정할 수 없다. `project_id`는 비용 집계 식별이며 연결한 API 프로젝트와 대응시킨다. `pricing_version` 변경은 모델/정책 캐시 버전에도 반영한다.

| 열                   | 의미                                                    |
| -------------------- | ------------------------------------------------------- |
| project_id           | PAYSE 호출이 함께 쓰는 비용 집계 식별                   |
| pricing_version      | 단가·환율·세금·수수료를 확인한 정책 버전                |
| pricing              | 아래 고정 JSON 키의 승인 값                             |
| opening_micros       | 이 장부 도입 전 사용액·외부 사용액의 확인된 원화 환산액 |
| limit_micros         | 신규 호출 차단선. 45,000,000,000 이하                   |
| baseline_verified_at | 기존 사용액을 확인한 시각                               |
| enabled              | 운영자의 명시적인 신규 호출 허용                        |

단위는 **1원 = 1,000,000 micros**다. 기존 총예산 50,000원·신규 차단선 45,000원·여유 5,000원을 유지한다. 서버가 발급 크레딧·달력·프로세스 재시작을 보고 비용을 자동 초기화하지 않는다.

`pricing`의 필수 키:

- `model`: 비공개 LLM 설정과 동일한 고정 모델 이름
- `inputMicrosPerMillion`, `cachedMicrosPerMillion`, `outputMicrosPerMillion`: 100만 토큰의 원화 micros 단가
- `inputLimit`, `outputLimit`: 요청별 입력·출력 토큰 상한. 출력에는 비공개 추론 토큰도 포함
- `countingMicros`: 계수 호출 1회의 확인한 비용 상한. 공식 무료 조건을 확인한 경우에만 명시적으로 0 설정
- `kmsMicros`: 키 감싸기 또는 풀기 1회의 원화 비용 상한. 0 기본값 없음

가격·환율·부가 비용은 코드에 임의 기본값을 넣지 않는다. 입력/출력 단가는 양수, 캐시 단가는 입력 이하, KMS 단가는 양수여야 한다. 캐시 토큰 미확인은 일반 입력 단가로 계산한다. 토큰별 소수 비용을 합산한 후 micros 단위로 올림한다.

모델 최대 비용과 계수 비용은 작업 시도와 **같은 접수 트랜잭션**에 예약한다. 커밋 후 외부 전송 직전에 현재 정책·총액을 재검사하고 한 번의 전송권을 별도 커밋한다. 같은 호출 ID의 중복 예약은 중복 청구 허가가 아니다.

현재 보수 정책은 기존 사용액 + 미확정 예약 + 새 예약이 차단선 **미만**일 때만 허용한다. 정확히 45,000원에 닿는 예약도 거절한다. 경계 허용을 넓히는 운영 변경은 별도 확인 대상으로 남긴다. 같은 프로젝트 행 잠금으로 동시 예약을 직렬화한다.

관측한 토큰 비용은 응답 의미 검증·암호화·결과 저장보다 먼저 정산한다. 세션 만료·금융 트랜잭션 롤백이 이를 지우지 않는다. 사용량 누락·전송 불명은 최대 예약액을 유지한다. TTL·재시작으로 반납하지 않으며, 공급자 청구 확인 후 운영자가 대조한다. 전송권 미취득 또는 어댑터가 확정한 미전송만 반납한다. 실제 비용이 예약보다 커도 실제 값을 보존하고 후속 호출을 차단한다.

KMS는 생성 결과의 항목별 암호화와 조회 복호화마다 같은 장부에 예약한다. 모델 성공 뒤 KMS 한도/권한/저장 실패가 나면 결과 저장은 실패할 수 있으며, 이미 발생한 모델 비용은 보존된다. 금융 조회·Dart 계산에는 이 장부를 적용하지 않는다.

이 장부를 거치지 않는 별도 키·다른 프로그램 사용액은 자동 수집하지 않는다. 기존 사용액 대조와 별도 호출의 통제가 끝나기 전 프로젝트 전체 예산을 보장한다고 보고하지 않는다. 운영 정책의 가격·기존 비용을 수정할 때는 먼저 비활성화하고 미정산 예약을 대조한다. 구독 혜택을 연결했다는 이유로 가격이나 기존 사용액을 0으로 만들지 않는다.

## 원천 입력과 앱 호환성

공개 앱 요청/응답 schema는 유지한다. 서버가 인증·소유권·기관 연결·현재 sourceVersion을 확인한 DB 원천에서 **이번 요청의 거래만** 보충한다.

- 거래 금액과 이용·기장·출금·환불·취소 날짜, 확인 시각과 그 근거
- 계좌·카드 ID는 요청별 대체 ID로 변환
- 미연결 계좌 ID는 모델에 전달하지 않음
- Snapshot asOf를 원천 기준 시각으로 전달
- 날짜 null은 그대로 유지하며 임의 시각을 만들지 않음
- 계좌번호·잔액·사용자 인증·비공개 평가 정답은 전송하지 않음

이 보충 객체는 서버 내부 전달값이다. 앱이 요청에 임의 필드를 추가하면 기존 입력 검증에서 거절한다. 모델 입력에도 추가 정답·미등록 필드·다른 거래가 섞이면 전송 전에 거절한다. 입력에 포함된 계좌/기간이 전체라는 가정은 하지 않는다.

감마의 정답 분류·자기이체 정답 관계는 별도 평가 자료에 유지한다. 다른 계정의 기존 확인 분류는 기존 계약대로 대조하며 근거 없이 사용자 확인 사실을 만들지 않는다. 같은 금액·가까운 날짜만으로 본인 계좌 간 이체를 확정하지 않는다.

초기 검증은 월급, 본인 이체, 반복 지출 후보에 집중한다. 기존 일반 의미 코드를 삭제하거나 새 `findings/unresolved` 응답으로 바꾸지는 않았다. 반복 수치·금액·미래 일정은 Dart 책임이며 앱의 입력 생성·사용자 확인 UI는 프론트 담당 범위다. 금액·날짜가 전달되어도 LLM이 최종 계산을 담당하지 않는다.

## 검사와 아직 필요한 확인

- `test_analysis_costs.py`: 실제 폐기 PostgreSQL의 10개 비용·권한·경합·롤백 검사
- `test_analysis_service.py`: 기존 인증·금융·분석 HTTP/JPA 회귀와 비용 SQL 검사
- Java: 설정 오류/비밀 비노출, 가격 산정, 비용 차단, KMS 키 파기, 원천 투영·별칭·정답 유입 차단
- 기존 감마 연간 1,825건/97묶음은 모의 공급자 경로 검사이며 실제 정확도 검사가 아님

연결한 OpenAI 조직의 실제 지급액·만료일·API 프로젝트/키, KMS 권한·토큰 갱신, 승인 가격 및 기존 비용, 운영 DB 적용, 실제 소량 LLM 호출은 별도로 확인해야 한다. 현재 실서버 JAR·프로필은 변경하지 않았다.
