# 분석 저장 구조 작성안

상태: **논리·물리 설계 제안, DDL/마이그레이션 미작성**. 현재 운영 테이블 수는 바꾸지 않는다. 구현 때 확정한 실제 컬럼은 [공통 DB 사전](../../../docs/database-schema.md)에 편입하며 이 문서와 이중 권위를 만들지 않는다. [분석 API](analysis-api.md), [실행 상세](llm-execution.md), [서비스 경계](service-boundaries.md)를 함께 읽는다.

## 1. 분리 이유

금융 원천과 사용자 설정은 기존 users·user_attributes·금융 테이블에 유지한다. 분석은 그 자료를 읽는 별도 저장소다. 금융 `users.data_version`, `write_receipts`, 현재 버전만 있는 `source_contexts`를 작업 큐·결과 캐시로 전용하지 않는다. UI 미구현을 이유로 원천이나 fixture에 분석 완료 필드를 넣지 않는다.

아래 7개 저장 단위가 책임 분리 제안이다. 기억별 관리·삭제는 확정 정책이며, 결과 묶음과 개별 기억을 나누는 물리 구조는 구현 전 검토안이다. 본문 없는 삭제 차단도 별도로 둔다. 같은 수명의 컬럼은 같은 행에 두되 결과·3개월 복구 식별·7일 상세·미정산 비용의 수명을 섞지 않는다. 테이블 수 자체를 제품 요구로 확정하지 않는다.

## 2. 필드·타입·제약

표의 `?`만 nullable이다. timestamp는 `timestamptz`, ID는 `uuid`, 카운터는 `bigint`다. enum은 허용값 CHECK 또는 동등한 제약을 사용하며 임의 문자열 상태를 받지 않는다. 사용자 소유 테이블의 user_id는 users FK이며 삭제 정책은 RESTRICT와 명시적 폐기 순서다.

### analysis_jobs — 작업·최소 복구 식별

| 컬럼                                   | 타입         | 필요한 이유·제약                                                                    |
| -------------------------------------- | ------------ | ----------------------------------------------------------------------------------- |
| id, user_id                            | uuid         | PK와 소유자. UNIQUE(user_id,id)로 복합 소유권 참조 가능                             |
| semantic_kind, trigger_kind            | text         | 분석 목적과 시작 동작 분리. 처음 접수한 trigger는 지문을 바꾸지 않음                |
| descriptor_hash, input_hash?           | text         | 접수 descriptor와 본문 검증 뒤 의미 지문 구분. 힌트를 검증된 지문으로 저장하지 않음 |
| accepted_at, guard_expires_at          | timestamptz  | 최초 접수와 고정 3개월 식별 기한. 재시도로 변경 금지                                |
| state, attempt_count                   | text, bigint | 허용 상태·누적 시도. count>=0, 최대 횟수 미지정                                     |
| selected_result_id?, canonical_job_id? | uuid         | 채택 결과 또는 합류한 대표 작업. 동일 사용자만 참조, 순환/자기 참조 금지            |
| execution_session_id?                  | uuid         | 대기 취소/진행 권한 확인용 기존 세션 식별. 결과 재조회 시 같은 세션 강제 금지       |
| finished_at?, permit_expires_at?       | timestamptz  | 상세 7일 삭제와 실행 허용 만료의 타입 있는 기준. 허용은 본문 제출 때 재검증         |
| detail?                                | jsonb        | 본문 없는 항목 ID·진행 수·운영 오류. 전체 요청/응답 금지, 종료+7일 뒤 제거          |

현재 세션 ID는 기존 demo_sessions의 소유권과 대조한다. 같은 사용자·의미 지문의 활성 대표 작업은 최대 1개이며 만료/종료 작업까지 영구 UNIQUE로 묶지 않는다. descriptor 상태와 검증된 input_hash의 잠금 기준을 구분해 제출 경합을 처리한다. 대표 작업 접수 시각을 기준으로 합류 기록을 정리하고 합류 때문에 보존 기한이 연장되지 않게 한다.

### analysis_attempts — 전송 시도와 멱등성

| 컬럼                     | 타입        | 필요한 이유·제약                                                       |
| ------------------------ | ----------- | ---------------------------------------------------------------------- |
| id, user_id, job_id      | uuid        | 시도 PK, 같은 소유자의 작업 FK                                         |
| attempt_no               | bigint      | job 내 UNIQUE, 1 이상. 기록값이며 최대 횟수 정책 아님                  |
| dispatch_state           | text        | notSent/sent/outcomeUnknown/settled. timeout을 notSent로 되돌리지 않음 |
| created_at, finished_at? | timestamptz | 시도 생성·종료. finished_at>=created_at                                |
| detail?                  | jsonb       | 공급자 요청 ID·본문 없는 오류·시작/종료 근거. 종료+7일에 상세 제거     |

시도 최소 식별은 해당 작업의 고정 3개월까지 유지한다. 미정산 비용은 별도 장부에 시도 ID를 독립 보존하므로 이 행 삭제로 비용이 사라지지 않는다. 접수·입력 제출·재시도·삭제의 모든 멱등 키는 `analysis_commands` 하나에 둔다. attempts에 같은 키/본문 지문을 중복 저장하지 않는다. 시도 키를 금융 write_receipts로 옮기지 않는다. 종료되지 않은 전송을 7일 경과만으로 정산 완료 처리하지 않으며 완료 불명 상태를 명시적으로 전환한 뒤 필요한 최소 복구·비용 사실을 남긴다.

### analysis_commands — 모든 분석 명령의 중복 방지

| 컬럼                           | 타입        | 필요한 이유·제약                                                                  |
| ------------------------------ | ----------- | --------------------------------------------------------------------------------- |
| user_id, request_key           | uuid, text  | 복합 PK. 서로 다른 작업에 같은 키 재사용 시 충돌                                  |
| operation, request_hash        | text        | 경로/명령 종류와 정규 본문. token·epoch만 바뀌어도 새 금융 효과를 만들지 않음     |
| job_id?, attempt_id?, item_id? | uuid        | 접수/제출/재시도/삭제별 대상. 같은 사용자만, 명령 CHECK로 필요한 대상 지정        |
| created_at, expires_at         | timestamptz | 접수/제출은 원 작업의 고정 식별 기한. 삭제 기록은 삭제 효력 보존 정책에 맞게 분리 |

result 본문을 영수증으로 복사하지 않는다. job 삭제 후 명령이 깨진 FK를 남기지 않도록 같은 보존 단위로 제거한다. 사용자 삭제를 막는 CASCADE 역방향 의존성을 만들지 않는다. 삭제 후 재보존 차단은 아래 suppressions에 두며 3개월 재시도 식별과 혼동하지 않는다. 삭제 명령 영수증의 보관기간과 폐기 후 DELETE 재전송 응답은 공개 삭제 API 확정 전 정할 항목이다. 따라서 해당 경로는 작성안으로만 유지한다.

### analysis_results — 본문 없는 결과 묶음

| 컬럼                      | 타입        | 필요한 이유·제약                                                                                 |
| ------------------------- | ----------- | ------------------------------------------------------------------------------------------------ |
| id, user_id               | uuid        | PK·소유권. 작업 식별이 삭제되어도 남은 기억에 필요한 헤더는 유지                                 |
| semantic_kind, input_hash | text        | 최초 채택/같은 유효 입력의 결과 재사용 검색. 기억 자체의 삭제 식별과 분리                        |
| provenance                | jsonb       | 당시 원천/설정/규칙/모델/프롬프트/응답 버전·asOf. 스키마 검증된 메타만, 원천/전체 응답 복사 금지 |
| accepted_manifest         | jsonb       | 접수된 itemKey와 처리 범위의 본문 없는 기록. 현재 사용 가능 여부나 기억 내용을 복사하지 않음     |
| committed_at              | timestamptz | 최초 채택 커밋 시각. 현재 조회 시각이나 모든 기억의 보관 만료를 뜻하지 않음                      |

이 헤더에는 전체 LLM 응답의 평문·암호문·표시 요약을 두지 않는다. 검증한 응답을 아래 기억 단위로 분리해 암호화한다. 헤더의 최초 처리 범위와 현재 사용 가능 기억은 다르다. 기억이 삭제/만료되면 남은 범위만 반환하며 완전한 정상 결과로 꾸미지 않는다. 모든 기억이 없어졌어도 필요한 최소 중복 방지 식별만 해당 기한까지 유지한다. 헤더/최소 tombstone의 실제 정리 순서와 기한은 FK·명령 영수증 보존 설계에서 구체화하며 본문 보관 연장 근거로 사용하지 않는다.

### analysis_items — 개별 기억·암호화·보존 상태

| 컬럼                                     | 타입         | 필요한 이유·제약                                                                             |
| ---------------------------------------- | ------------ | -------------------------------------------------------------------------------------------- |
| id, user_id, result_id                   | uuid         | 기억 PK·소유자·동일 사용자 결과 FK. UNIQUE(user_id,id); 다른 소유자 연결 금지                |
| item_key                                 | text         | 입력/출력 항목 대응용. 같은 결과 안에서 UNIQUE. 임의 모델 문자열을 삭제 식별로 신뢰하지 않음 |
| semantic_kind, memory_key, evidence_hash | text         | 작업 종류·묶음과 무관한 기억 식별·당시 관련 근거 지문. NOT NULL, 생성 시 서버 검증 후 불변   |
| stored_at, normal_expires_at             | timestamptz  | 해당 기억의 최초 저장·일반 3개월 기한. 조회/재시도/같은 근거의 묶음 변경으로 재기산 금지     |
| ciphertext, crypto_meta                  | bytea, jsonb | 본문·표시 요약·보존 이유 암호화, 독립 데이터 키 참조·nonce/tag 등 검증 메타. 평문 키 없음    |
| active, is_reference, important          | boolean      | 활성·AI 참고자료·중요보존 분리. important=true이면 is_reference=true 필요                    |
| reference_policy                         | text         | optional/required. required도 현재 유효성·사용자 정정·삭제를 우회하지 못함                   |
| metadata_version                         | bigint       | 1 이상. 개별 기억 삭제/메타 변경 경합 제어. 금융 dataVersion과 별도                          |
| policy_version, policy_actor             | text         | 검증한 보존 정책 버전·주체(ai/server/user). 구체적인 보존 이유는 암호문에만 저장             |
| deleted_at?, purge_requested_at?         | timestamptz  | 삭제·만료의 즉시 참조 차단과 실제 파쇄 진행을 구분                                           |

`memory_key`는 허용된 의미 목적과 안정된 원천/후보 식별로 같은 기억을 구분한다. `evidence_hash`는 그 기억에 실제 관련된 원천 값·사용자 정정 근거의 지문이다. 전체 분석 묶음, 모델이 만든 요약 문장, 임의 itemKey만으로 동일 기억을 판정하지 않는다. 모델/프롬프트 버전·조회 시각·전체 dataVersion·묶음 구성은 차단 식별에서 제외한다. 항목별 정규화 필드와 직렬화·해시 규격은 의미 작업 JSON Schema와 함께 확정하며 미확정 상태에서 임의 구현하지 않는다.

같은 기억·근거가 다른 결과 묶음/모델 버전의 행에도 존재하면 삭제 차단과 폐기 요청을 모두 적용한다. 같은 기억·근거를 재저장해 최초 저장/만료를 늘리지 않는다. 반대로 서로 다른 기억 또는 실제 근거가 달라진 기억은 함께 삭제하지 않는다. 재사용·중복 행 제약의 실제 SQL은 이 조건을 만족하도록 검증한다.

현재 입력의 유효성은 조회/채택 때 확인한다. stale을 고정 boolean 하나로 영원히 신뢰하지 않는다. 비활성·원천 정정은 현재 적용을 막지만 중요보존 예외 자체를 해제하지 않는다. 결과/기억 FK를 7일 상세 작업 행에 종속시키거나 sourceVersion을 현재 source_contexts 값에 FK로 묶지 않는다. 기억은 결과 헤더를 참조하지만 헤더 삭제가 살아 있는 중요보존 기억을 CASCADE 삭제하지 않게 한다.

### analysis_suppressions — 같은 기억의 자동 재보존 차단

| 컬럼                                              | 타입                   | 필요한 이유·제약                                                                       |
| ------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------- |
| user_id, semantic_kind, memory_key, evidence_hash | uuid, text, text, text | 복합 PK. 같은 사용자·같은 기억·같은 근거만 차단. 다른 기억이나 새 근거로 확대하지 않음 |
| blocked_at                                        | timestamptz            | 삭제 시점. 결과 내용·판단 이유·금액을 복제하지 않음                                    |

삭제 대상에 저장된 불변 memory_key/evidence_hash를 사용한다. 현재 원천에서 과거 지문을 재구성하지 않는다. 모델/프롬프트 교체·새 resultId·묶음 변경으로 차단을 우회할 수 없다. 근거가 바뀌면 새 판단을 허용하되 기존 차단을 지우지는 않는다. 3개월 결과 청소에 함께 삭제하지 않으며 계정 탈퇴의 최종 파쇄에는 포함한다. 복원 시 옛 백업이 최신 삭제 차단을 되돌리지 않도록 검증한다.

사용자 삭제는 같은 기억·근거의 모든 행에서 metadata_version 증가·deleted_at/폐기 요청과 차단 기록을 함께 커밋한다. 이미 반환한 기기 캐시는 B가 삭제 응답/재조회에 맞춰 무효화한다. AI 메타 변경과 늦은 응답 채택은 같은 기억 식별의 잠금·차단 조회 아래 처리한다. 삭제 전 조회 결과로 후속 작업을 진행할 때도 채택 시 재검증한다. 금융 원천/설정과 다른 기억은 바꾸지 않는다.

### analysis_costs — 프로젝트 공통 비용

| 컬럼                        | 타입             | 필요한 이유·제약                                                                    |
| --------------------------- | ---------------- | ----------------------------------------------------------------------------------- |
| id, project_key, attempt_id | uuid, text, uuid | PK, 공통 예산, 시도별 UNIQUE. 시도 상세 삭제 후에도 비용 대조 가능                  |
| reserved_krw, actual_krw?   | numeric          | 소수 비용/환산 정밀도 보존. >=0. 사용자 금융 Money 한도를 비용 모델에 전용하지 않음 |
| state, pricing_basis        | text, jsonb      | reserved/unsettled/settled/released 및 단가·통화·환산·세금·수수료 근거              |
| created_at, settled_at?     | timestamptz      | 예약·정산 시각. timeout이나 기록 TTL만으로 해제하지 않음                            |

프로젝트 잠금 아래 기존 실제 비용·미정산 예약·새 예약을 검사한다. settled는 actual_krw·settled_at이 필요하고 released는 미과금/예약 해제 확인 근거가 있어야 한다. timeout·TTL을 해제 근거로 삼지 않는다. 실제 구현의 통화 정밀도·반올림·정확히 차단선에 도달한 자기 예약 처리·정산 후 보관기간은 아직 미정이며 유료 경로 활성화 전 확정한다. 비용 장부는 클라이언트 조회 권한이나 사용자 결과 FK CASCADE에 종속시키지 않는다.

## 3. 인덱스·권한·성능

- 사용자 작업/결과 조회: (user_id,id); 재사용 후보 검색: (user_id,semantic_kind,input_hash,committed_at DESC). 조건에 맞는 결과마다 유효성을 검증하며 무조건 최신 1행만 정답으로 고르지 않는다.
- 기억 조회/삭제 차단: (user_id,id), (user_id,semantic_kind,memory_key,evidence_hash), (user_id,result_id). 결과 묶음만 검색해 다른 묶음의 삭제 대상 사본을 놓치지 않는다.
- 대기 작업: (state,accepted_at), 폐기 대상: (normal_expires_at) 및 중요보존/삭제 조건. 원천·거래 전체를 매번 스캔하지 않는다.
- 같은 의미 작업의 실행과 결과 채택은 동일 잠금 기준+조건부 UPDATE/UNIQUE로 직렬화한다. 최초 결과 커밋 성공만 채택하고 다른 응답이 덮지 못하게 한다.
- 모든 사용자 행은 RLS·복합 소유자 관계를 적용한다. runtime에 새 테이블 전체 권한을 일괄 GRANT하지 않는다. 결과 읽기/명령 함수와 비용 작업자 권한을 필요한 범위로 나눈다.
- 상세 JSONB는 확장용 무제한 EAV가 아니다. 상태·검색·만료·권한에 쓰는 필드는 타입 있는 컬럼, 버전별 부가 메타는 검증 스키마를 가진 JSONB로 구분한다.
- 결과 body는 필요할 때만 복호화하고 조회 페이지에 원천/키/토큰을 포함하지 않는다. 민감 본문을 큐·로그·에러로 복제하지 않는다.

## 4. 날짜·폐기·원자성

달력 3개월은 최초 시각을 Asia/Seoul로 해석해 같은 시각을 유지하고 대응 일이 없으면 말일로 보정한다. 예: 1/31 15시 → 4/30 15시. 저장은 timestamptz다. 금융 급여 날짜 계산과 달리 서버의 운영 보관 기한 계산이며 Flutter 계산 책임을 옮기지 않는다.

중요보존 예외·사용자 삭제·탈퇴 후 1년은 공통 정책대로 적용한다. 읽기 경로는 만료 즉시 차단하며 정리 작업 주기 때문에 읽기 기한을 늦추지 않는다. KMS·백업/WAL/복제본·모든 감싼 키 사본까지 검증해야 파쇄 완료다. 현재 DB 키 행만 지우는 구현으로 완료 처리하지 않는다.

원자 경계는 접수/시도·비용 예약, 결과 헤더+허용 기억+항목별 제외 사유+채택, 사용자 삭제+동일 기억 사본 차단으로 분리한다. 모델 응답은 전체 입력 항목의 형식을 검증하되, 커밋 시 사용자 삭제 차단에 해당하는 항목은 저장하지 않고 본문 없는 제외 사유만 기록한다. 이런 의도적 제외를 모델 미완료나 전체 결과 사용 가능으로 표시하지 않는다. 외부 LLM 호출 동안 DB 연결·사용자 행 잠금을 유지하지 않는다. 실패/중도 취소는 미커밋 업무를 롤백하고 외부 실행·미정산 비용은 보존한다. 응답 유실은 먼저 같은 키의 커밋 여부를 확인한다.

## 5. 구현에서 검증할 반례

동일 요청 연타, 다른 본문 같은 키, 타 사용자 결과/명령 연결, 조회 중 세션 종료, 원천 변경 뒤 응답, 먼저 끝난 이전 시도, 같은 결과 저장 경합, 성공 커밋 뒤 응답 유실, SQL 중도 취소, 7일 상세 제거 후 재조회, 말일 3개월, 중요보존 해제/사용자 삭제, 탈퇴, 미정산 비용 잔류를 검사한다. 지금은 설계 대조이며 실제 PostgreSQL 실행 PASS가 아니다.

개별 삭제 검증에는 통신비·월세·급여 중 월세만 삭제, 다른 묶음의 같은 월세 기억 차단, 원천 근거 변경 후 새 판단, 보존 항목별 만료·키 분리, 삭제와 AI 보존 갱신/늦은 응답의 경합, 하나 삭제 후 결과 부분 반환, 전체 응답 사본/백업의 삭제 내용 잔류 여부를 포함한다.
