# 감마 연간 실제 LLM 평가

2026-11-03 사용자가 기존 `fix/api/data-refresh-consistency`에서 어려운 연간 자료·사전 정답·자동 채점·실제 호출을 승인했다. [로컬 키 시험](gamma-local.md)의 감마 격리 경계를 재사용한다. 운영 DB·모바일·일반 서버 JAR은 바꾸지 않는다.

## 자료와 사전 정답

`testing/scenarios/gamma_challenge.py`는 기존 연간 원천에서 새 합성 버전을 만든다. 365일·1,825행, 계좌 거래 1,000건의 주 계좌 800/나머지 다섯 계좌 각 40, 미사용 계좌 세 개를 유지한다. 월별 급여, 회사명만 있는 입금, 차입금·경비 정산·상여, 명시된 내부 이체 관계와 미확인 쌍, 부분 환불·취소, 취소 문의·환불 미완료, 목적 충돌·누락·적요 속 지시문을 섞는다. 계좌 asOf와 잔액도 같은 원천으로 재작성한다. 기본 더미와 다른 계정 자료는 변경하지 않는다.

`testing/analysis/gamma_labels.py`의 작성된 기준은 입력과 분리된다. 숨은 생성 의도가 아니라 모델이 볼 수 있는 원천에 근거한 답을 정한다. `unknown`도 정상 정답이며 `expectedReview=ask_user_for_missing_information`은 정보 부족을 사용자 확인 대상으로 받아야 한다는 뜻이다. 기존 단일 의미 분류표의 범위 부족은 `outside_taxonomy`와 별도 오류로 남긴다.

```text
python -B apps/api/testing/analysis/gamma_evaluation.py --prepare .harness/gamma-evaluation-frozen
```

새 폴더에만 `source.json`, `inputs.json`, `expected.private.json`, `manifest.json`을 만든다. 모델 호출 전 파일 SHA-256을 고정하며 실행 전후 변경을 거절한다. 입력은 원천만 읽어 생성하고 정답·난도·채점 기준은 포함하지 않는다. 모델 실행 프로세스에는 정답 경로를 주지 않는다. 정답을 보고 답을 고치거나 평가셋을 다시 만들어 이전 점수를 숨기지 않는다.

거래 의미는 전건을 10개씩 묶는다. 원거래·명시 관계는 근거에서 제거하지 않는다. 반복 후보 입력은 공개 원천에서 최근 3개월 동안 월별 1회·같은 일자/금액·같은 명칭/적요의 엄격한 부분집합을 추출한다. 이 테스트용 앱 입력 준비는 Flutter의 ±5일·중앙값 ±10% 일반 탐지기를 구현하거나 검증했다는 뜻이 아니다. 후보 의미와 사용자 확인 UI·최종 설정 반영은 별도다.

## 승인된 평가 프로필

사용자가 비용 예상을 확인하고 **감마 평가에만 입력 12,000/출력 4,000토큰**을 승인했다. `--evaluation-dir`과 명시 승인 환경이 함께 있을 때만 적용한다. 기존 세 표본 실행·운영의 6,000/1,200 상한은 유지한다. 통신 20초, 10건 또는 60초 대기, 사용자 동시 전송 1, 본문 65,536바이트, 근거 60개, 반복 후보 20개의 기존 경계는 유지한다.

```text
python -B apps/api/testing/analysis/gamma_local.py --live --pg-bin <PostgreSQL-bin> --work-dir <새-실행-폴더> --env-file <승인된-.env.local> --evaluation-dir .harness/gamma-evaluation-frozen
```

일반 API의 descriptor→허용→입력 제출→실제 모델→검증→암호화 저장→결과 조회를 사용한다. 실패한 요청을 재전송하지 않는다. 서로 다른 묶음에서도 연속 세 실패면 나머지를 미실행으로 남기고 중단한다. 실패·미실행은 정상 unknown으로 채점하지 않는다. 성공한 결과는 재시작 후 재조회하고 추가 공급자 호출이 없는지 확인한다.

원천 버전으로 제한한 합성 시험에 한해 공개 API가 반환한 의미 필드·사유·근거 ID를 Git 제외 실행 폴더의 `live-summary.json`에 남겨 로컬 채점한다. 운영 요청·응답 로깅 기능이 아니다. 비공개 키·토큰·DB 자격은 포함하지 않는다. `evaluation.json`은 사전 정답과 대조한 결과이며 `result.json`의 통신 성공과 구분한다.

## 비용과 결과 해석

새 평가 예약은 최대 25,000원이며 과거 비용·미확정 예약을 포함한 신규 차단선 45,000원을 유지한다. 모델은 `gpt-6-luna`, 추론은 `none`이며 자동 채점에는 모델을 쓰지 않는다. 계수 요청은 미확정이므로 기존 100원/회 예약을 유지하고 실제 청구로 표현하지 않는다. 토큰 장부의 보수 환산도 실제 환율이 아니다.

2026-11-03 [공식 모델 가격](https://developers.openai.com/api/docs/models/gpt-6-luna)은 100만 토큰당 입력 USD 0.10, 캐시 입력 0.01, 캐시 쓰기 0.125, 출력 0.50이다. 약 184회·입력 8,000/출력 2,200토큰 가정의 생성 비용은 약 USD 0.35다. 모든 요청에서 승인 상한을 썼을 때 표준 생성 비용은 약 USD 0.59이며 기존 보수 입력 단가 0.25를 사용하면 약 USD 0.92다. 계수 요청 요금·실제 청구는 별도 확인 대상이다. 이 값은 실행 전 예상이며 실제 사용량은 결과와 함께 보고한다.

채점 지표는 분자/분모를 함께 반환한다.

- `meaningAccuracy`·`basicAccuracy`·`valueAccuracy`: 각각 의미값·기본 분류값·두 값 모두의 정답 일치율. 사유 코드·필수 근거 추적의 엄격한 검사는 아래 `accuracy`에서 별도 반영한다.
- `accuracy`: 기본 분류·의미·사유 코드·필수 근거가 모두 맞고 현재 분류표 범위 부족도 없는 항목 비율.
- `decisionMatch`: 올바른 범위 부족 유보까지 포함한 정답 행동 일치율. 범위 부족을 전체 판단 목표 달성으로 바꾸지 않는다.
- `falsePositiveRate`: 의미별 FP/(FP+TN). `precision`은 TP/(TP+FP), `recall`은 TP/(TP+FN).
- `abstention`: 정상 응답의 의미 unknown/전체. 실패·미실행을 unknown으로 세지 않는다.
- `correctUnknown`·`unsupportedAssertion`: 정보가 부족한 정답에서 적절한 유보·근거 없는 단정.
- `unnecessaryAbstention`: 의미 판단이 가능한 정답에서 불필요한 유보.
- `reviewMatch`: 실제 unknown/사유 코드로 도출한 확인 처리와 사전 정답의 일치. 앱의 질문 화면 구현을 뜻하지 않는다.

거래 1,825개와 반복 후보는 별도 분모로 집계한다. 의미별 혼동 행렬과 난도별·유형별 실패를 함께 보며, 처리 실패 때문에 오탐률만 낮아진 것을 성능 개선으로 해석하지 않는다. 사유 문장의 자연어 타당성은 실패·경계 표본을 직접 검토한다.

이 자료는 같은 생성 문법을 공유하는 **합성 개발 평가셋**이다. 독립 실거래·독립 최종셋이나 PAYSE 전체 판단 99.99% 달성 근거가 아니다. 평가 방법은 [OpenAI 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)과 기존 [의미 평가 규칙](../testing/analysis/README.md)을 참고하되 프로젝트 계약을 우선한다.

실제 응답에서 확인한 예:

로컬 근거는 `.harness/gamma-evaluation-frozen-01/`의 원천·입력·정답·manifest와 `.harness/gamma-evaluation-live-01/`의 `live-summary.json`, `result.json`, `evaluation.json`, `cost-summary.json`이다. 모두 Git 제외이며 일반 CI는 유료 호출을 실행하지 않는다.
