# 감마 실제 분석 연결 검증

2026-11-05 기준. 계좌 연결부터 실제 공급자 분석, 암호화 저장, 서버 재시작 후 결과 복원까지 API·AI 경로를 확인했다. 모바일 화면·기기 검증 및 1년치 전체 정확도 재평가와는 구분한다.

## 원천 연결과 보존

- 연결 전 DB 백업을 보관하고 감마 외 사용자의 원천·설정·버전·세션을 비교했다. 다른 사용자의 행은 변경되지 않았다.
- 감마만 기존 DB의 합성 원천을 기관 연결 경로로 가져왔다. 9개 기관, 9개 계좌, 4개 카드이며 사용하는 계좌 6개를 선택하고 미사용 계좌 3개는 제외했다.
- 2025-11-06부터 2026-11-05까지 거래 1,825건을 19개 페이지로 조회했다. 중복 거래 ID 없이 모든 페이지의 사용자·원천 버전·데이터 버전·기준 시각이 일치했다.
- 연결과 계좌 선택의 동일 요청 재전송은 기존 영수증을 반환하고 버전을 추가로 올리지 않았다. 분석 전후 금융 원천·사용자 설정·데이터 버전도 같았다.
- 급여 설정, 분류 확정, 예정 지출 등록은 분석 결과로 자동 생성하지 않았다. 감마는 연결과 계좌 선택을 마친 상태이며 검증 세션은 로그아웃했다.

## 실제 서버에서 확인한 흐름

1. 현재 Snapshot과 거래 페이지를 조회한다.
2. 현재 문맥과 의미 입력의 지문으로 `POST /analysis-jobs`를 접수한다.
3. 상태의 `action=submitInput`에서 허용 식별과 입력을 `POST /analysis-jobs/{id}/input`으로 제출한다.
4. `GET /analysis-jobs/{id}`로 상태를 확인한다. 접수 202는 분석 완료가 아니다.
5. 현재 문맥과 관련 입력을 `POST /analysis-results/query`로 제출해 실제 결과를 받는다.
6. 서버 재시작 및 새 로그인 후 현재 세션 문맥으로 같은 결과를 조회한다.

사전 기대값을 별도 저장한 거래 의미 15건과 반복 의미 5건을 실제 모델로 처리했다. 두 작업 모두 `succeeded`, `resultAvailability=available`이며 완료 항목은 각각 15건·5건, 미완료 항목은 0건이었다. 전체 20개 결과에 암호문·암호화 메타데이터·보존 기록이 저장됐다.

동일 접수·입력 재전송, 반복 상태/결과 조회, 서버 재시작·새 로그인 후 조회에서 모델 호출이 추가되지 않았다. 저장 식별자·최초 저장 시각·원래 출처·해석이 유지되고 응답의 현재 세션 문맥만 갱신됐다. 로그아웃 후 비인증 조회는 401이었다. DB와 HTTPS 프로세스는 재시작하지 않았다.

| 첫 실행        | 접수 후 실행 전 대기 | 입력 제출 후 결과 확보 |
| -------------- | -------------------: | ---------------------: |
| 거래 의미 15건 |              0.125초 |               10.781초 |
| 반복 의미 5건  |             61.235초 |                5.953초 |

10건 미만의 배치 대기 규칙을 유지했다. 이 표본은 5초 목표 달성 근거가 아니며, 네트워크·저장·조회 대기도 포함한 관측 시간이다. 재시작 후 API 메모리는 약 317MiB였고 힙 상한 768MiB, 시스템 물리 메모리 여유 약 15GiB를 확인했다.

## 발견한 의미 문제와 보완

최초 정답지는 원천에 구체 목적이 없는 `월간 이용료`를 구독으로 기대한 오류가 있었다. 원본 기대값과 결과는 그대로 보존했다. 거래 해석은 이를 정상적으로 유보했지만, 같은 거래 3개를 묶은 반복 해석은 구독으로 과도하게 추정했다. 최초 기대값과 단순 대조한 19/20을 정확도 성과로 사용하지 않는다.

기존 [의미 규격](analysis-meaning.md)과 공개 의미 기준에 따라 프롬프트를 보완했다. 반복 사실은 서비스 목적의 근거가 아니며, 목적이 명시되지 않은 월간 이용료·정기 결제·자동 납부는 `unknown/insufficient_evidence`로 반환한다. 카드 구매의 기본 `expense` 후보는 의미 유보와 별개로 유지한다.

| 대조 사례                                    | 기대 처리                                          |
| -------------------------------------------- | -------------------------------------------------- |
| 월간 이용료 1건, 구체 서비스 목적 없음       | 기본 expense 후보, 의미 unknown                    |
| 같은 이용료가 3개월 반복됨                   | 반복 여부와 별개로 의미 unknown                    |
| 영상 콘텐츠 월정액 구독료                    | subscription 후보                                  |
| 소프트웨어 정기 구독료                       | subscription 후보                                  |
| 금액·시점이 비슷한 출금/입금, 소유 관계 없음 | 본인 계좌 이체로 확정하지 않고 unknown             |
| 대출 상환, 원금·이자 구분 없음               | loan_repayment 의미 후보, 기본 수입·지출 분류 유보 |

교정 기대값과 명시 목적의 긍정 대조 2건을 실행 전에 새 파일로 동결했다. 원래 20건을 포함한 22건의 집중 회귀 검증이며 독립적인 연간 정확도 평가가 아니다. 비공개 정답·실행 본문·키는 운영 프롬프트나 배포 JAR에 넣지 않는다.

실제 공급자 생성 3회와 계수 3회로 22건 모두 완료·암호화 저장·재시작 복원을 통과했다. 기본 분류·의미·확인 요청의 기대값 일치율은 각각 22/22였다. 정상 판단 유보 5/5, 명확한 17건의 불필요한 유보 0건, 근거 없는 단정 0건이었다. 작은 집중 회귀 표본의 결과이며 일반 정확도 100%를 뜻하지 않는다. 새 프롬프트 지문은 `PAYSE-PROMPT-4:ff27f8e460bd074a83024d41c8823301ea4e47145fb1dad3dc8687ef3c84bc4b`다.

## 프론트 연동 시 구분

- `succeeded`는 접수한 묶음의 처리 완료다. `unknown`도 근거 부족을 명시한 정상 완료이며 사용자에게 부족한 목적·관계를 확인한다. 후보는 사용자 확인 전 확정 설정이 아니다.
- 실패·완료 불명·취소·만료는 정상 후보 0개나 정상 unknown으로 바꾸지 않는다. `review.requiresUserInput`, `itemsAvailable`, `items`, `action`에 따라 실패 목록과 사용자 재시도를 표시한다. 자동 모델 재호출은 하지 않는다.
- 반복 후보 수치 계산에서 0개인 경우와 분석 요청 실패는 별개다. 상태 조회의 결과 식별자만으로 해석 본문을 복원하지 말고 결과 조회 API를 사용한다.
- 완료 결과는 앱 재접속 후 현재 입력을 재검증해 복원할 수 있다. 다만 입력 제출 전에는 앱의 제출이 필요하므로 “앱을 나가도 언제나 계속 진행된다”는 보장은 하지 않는다. 실행 중 세션 변경·삭제·원천 변경의 채택 제한도 유지한다.
- 원천/설정 변경, 사용자 삭제, 보존 만료, 모델/프롬프트 버전 변경으로 재사용 자격이 없으면 `stale`·`missing` 등 현재 상태를 처리한다. 과거 성공을 현재 결과 사용 가능과 동일시하지 않는다.

정확한 필드·오류·수명은 [실행 API](analysis-api.md), [실패 복구](analysis-recovery.md), [Java·Dart 공통 규약](../../../docs/analysis-protocol.md)을 따른다. 이번 변경은 공개 입출력 필드를 바꾸지 않는다. 이번 달 쓸 수 있는 돈은 사용자 확인·설정 저장 후 최신 Snapshot으로 기존 Dart 계산을 실행해야 하며 서버·LLM이 금액을 확정하지 않는다.

## 비용·배포 경계

생성 호출 전에 비용을 예약하고 USD 잔여 20 하한, 기존 계수 요금 공통 예비비, 서버용 별도 예산을 유지했다. 비용 보고는 관측 토큰에 보수적인 단가를 적용한 값이며 공급자의 최종 청구 조회가 아니다. 결과 조회와 동일 구성의 준비 재사용은 생성·계수 요청을 실행하지 않는다.

첫 서버 흐름의 생성 비용 상한 추정은 $0.00549, 집중 회귀 22건은 $0.007307이었다. 회귀 정산 후 기존 평가·서버 예약·계수 공통 예비비까지 제외한 장부상 잔여는 $26.218866이었다. 이 값은 결제 화면의 실시간 잔액이 아니다.

새 프롬프트는 검증 후 `performance.json`의 지문과 함께 배포한다. 바뀐 지문은 기존 결과의 재사용 자격에도 반영된다. 기존 암호화 결과나 로컬 키를 삭제하지 않는다. 기능 브랜치 검증과 실제 설치 버전은 구분하며, 운영 교체는 승인된 브랜치의 성공한 CI 산출물로 수행한다. [AI 준비·상태](ai-startup.md)와 [수동 배포](../deploy/continuous-delivery.md)를 따른다.

후속 반복 계획의 월별 확정·버전 변경·지급 연결 등 미구현 기능과 모바일 실기기 완료를 이번 검증 범위에 포함하지 않는다.
