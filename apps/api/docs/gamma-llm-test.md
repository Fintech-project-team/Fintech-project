# 감마 연간 자료와 LLM 테스트

이 자료는 합성 개발 테스트용이다. 실제 금융기관 수집이나 LLM 정확도 검증 결과가 아니다. 일반 서버 코드에 감마 이름·ID 조건을 추가하지 않고 기존 소유권·금융 조회를 사용한다.

## 저장 구조와 준비 자료

계정은 `payse.users`, 급여·카드 설정은 `user_attributes`, 계좌는 `financial_accounts`, 카드는 `financial_cards`, 거래는 `financial_transactions`, 원천 시각·버전·조회 범위는 `source_contexts`에 저장한다. `institution_links`는 금융기관 연결 상태다. 계좌 테이블의 필수 `user_id`는 소유권이며 기관 연결 여부와 다르다. 다른 사용자에게 자료를 노출하기 위해 소유자를 비우거나 공용 계좌로 만들지 않는다.

`testing/scenarios/gamma_year.py`가 기존 `gamma-life`의 기관·계좌 식별 골격으로 다음 자료를 생성한다. 원래 `gamma-month-end`와 `gamma-life`는 보존한다. 기본 시드의 감마는 `gamma-life`이며, 연간 자료는 운영자가 별도로 준비하는 테스트 사례다.

| 항목         | 값                                                                             |
| ------------ | ------------------------------------------------------------------------------ |
| 기준 시각    | `2026-11-05T12:00:00+09:00` — 기존 감마 사례와 맞춘 고정 테스트 시각           |
| 기간         | 2025-11-06~2026-11-05, 365일                                                   |
| 전체 거래 행 | 매일 5건, 총 1,825건                                                           |
| 계좌 거래    | 1,000건: 주계좌 800건, 나머지 5계좌 각 40건                                    |
| 카드 사용    | 825건, 별도 카드 원천 행                                                       |
| 계좌·카드    | 사용 계좌 6개 + 거래 없는 계좌 3개, 카드 4개                                   |
| 본인 이체    | 200쌍, 출금·입금 400행. 서로 다른 계좌, 같은 금액·시각                         |
| 기타         | 12회 급여, 임차료·통신·보험·구독료·대출 상환, 대출 실행금, 생활 지출·일반 송금 |
| 사용자 설정  | 계산 계좌 미선택, 월급 설정 없음, 분류·계획·보호·배정·정산 없음                |

80%는 **계좌 거래 행**의 비율이다. 카드 사용 행은 계좌 거래 분모에 섞지 않는다. 이체 한 번은 두 원천 행이며 지출 두 번을 뜻하지 않는다. 대출은 입금·상환 거래로 표현하며 별도 대출 계약·원금 잔액을 지어내지 않는다. 계좌 잔액은 테스트 생성 단계의 기초잔액과 명시 원장으로 일관성을 검사한다. 서비스에 금융 계산을 추가하지 않는다.

```text
python -B apps/api/testing/scenarios/gamma_year.py --out <새_비공개_폴더> --seed 20261103
```

출력은 `source.json`, `evaluation-gold.json`, `manifest.json`이다. 정답에는 실제 생성한 이체 쌍·후보 종류와 판단 유보가 허용되는 근거 제한을 보관한다. 원천의 `payseTransactionType`은 모두 null이며 정답 관계를 `transactionRelations`에 넣지 않는다. 정답을 모델에 보내거나 기존 분류를 사용자 확인으로 가장하지 않는다. 기존 사례의 정답은 기존 파일에 그대로 보존한다.

## 감마만 수집을 대체하고 기존 계좌 가져오기 사용

감마의 외부 마이데이터 수집 단계만 사전 적재한 합성 원천으로 대체한다. 원천은 감마 소유로 일반 금융 테이블에 저장하고 `institution_links`는 비워 둔다. 알파·베타의 기존 자료·설정·기관 연결에는 이 테스트 대체를 적용하지 않는다. 현재 다른 계정의 원천도 합성 자료이며 실제 마이데이터 수집이 구현되었다는 뜻은 아니다.

```text
테스트 준비: 감마 연간 합성 원천 → 기존 DB 테이블에 사전 적재
앱: 감마 로그인 → 미연결 Snapshot → 기관 선택·동의
    → POST /institution-links → DB 원천을 기존 조회 권한으로 공개
    → 모든 거래 페이지 수신 → 계산 계좌 선택·저장
    → 분석 요청·후보 확인 (서버 활성화와 앱 분석 연동 필요)
```

로그인은 연결·계좌 선택·원천 교체를 실행하지 않는다. 기존 기관 연결 쓰기가 동의 상태와 `dataVersion`을 저장하며 원천 금액·날짜·분류는 변경하지 않는다. 재로그인에는 이미 저장한 상태를 복원한다. 첫 로그인 자동 연결 도구와 검사는 제거했다. 이를 설치했던 개발 DB에서는 `payse_test_first_login` 트리거와 `payse_test_login` 스키마의 `connect_once()`·`pending`을 제거한다. 금융 데이터나 현재 세션을 삭제할 필요는 없다.

향후 실제 수집기는 금융기관에서 받은 자료를 기존 DB 원천 계약에 맞춰 저장한다. 현재 앱 조회는 이미 DB를 사용하며 파일을 매 로그인마다 읽거나 감마 이름을 검사해 응답을 바꾸지 않는다. 외부 수집기의 구현과 동의·수집 실패 처리는 후속 범위다.

기존 DB에 초기 적재용 `export_sql.py` 결과를 그대로 재실행하지 않는다. 기존 사용자 초기화는 대상 합성 상태 대조·저장소 밖 백업·사용자 잠금·다른 사용자/인증 보존·전체 롤백 검증을 거치는 별도 운영 작업이다. 인증 키·토큰·접속 properties·실제 DB 덤프를 Git에 넣지 않는다.

## 현재 LLM 구현과 요청안의 차이

실제 계약은 [거래 의미](../../ai/contracts/transactionMeaning.output.schema.json), [반복 의미](../../ai/contracts/recurringMeaning.output.schema.json), [분석 API](analysis-api.md)다. 팀원의 `findings/unresolved` 예시는 제안 형식이며 현재 응답에 그대로 존재하지 않는다.

| 팀원 요청              | 현재 구현·추가 합의점                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 월급 후보              | `transactionMeaning`의 `meaning.value=salary`, 기본 분류 후보와 별도 표시                                          |
| 본인 계좌 간 이체 후보 | 확인된 관계 또는 기존 확인 분류가 필요. 같은 금액·시각만으로 확정하지 않음                                         |
| 반복 지출 후보         | Flutter가 만든 후보·features를 `recurringMeaning`으로 해석. 서버가 1년 거래에서 반복 금액·일정을 계산하지 않음     |
| 유형·근거·이유         | `classification`/`meaning`, `evidenceTransactionIds`, `reason`/`reasonCode`                                        |
| 판단 불가              | 정상 `status=unknown`, `value=null`; 실행 실패·형식 오류와 구분                                                    |
| 확인 필요 여부         | 현재 모든 결과가 후보이며 자동 금융 반영 금지. 별도 `requiresUserConfirmation` 필드는 없음                         |
| 계좌·날짜·금액 패턴    | 서버가 요청 거래의 금액·실제 날짜·계좌/카드 대체 ID를 모델에 보충. 상대 계좌 소유 증명은 없으며 임의 생성하지 않음 |

현재 원천에는 거래 ID, 계좌/카드 ID, 원천 버전·참조, 거래 종류, 입출금, 금액, 상태, 거래명·적요, 이용/기장/출금/취소/환불 날짜, 확인 시각·근거, 잔액 반영, 원거래 ID, 분할 정보가 있다. 계좌에는 종류·상품·마스킹 번호·잔액·기준 시각이 있다. 없는 상대 계좌 정보나 실명 소유 증거를 모델 입력용으로 만들어 넣지 않는다.

모델 입력은 거래 ID 별칭, 종류·방향·상태·반영 이유, 거래명·적요, 원거래와 실제 제공된 관계다. API 실행 경로는 현재 권한을 확인한 요청 거래의 금액·실제 날짜·계좌/카드 대체 ID와 asOf를 보충한다. 계좌번호·잔액·인증·비공개 정답을 전달하지 않는다. 반복 특징의 수치 계산은 Flutter 책임이다. 거래 본문에 포함된 지시는 데이터로 취급한다.

실제 계약 검증을 통과하는 형식 예시는 테스트 생성 결과 `gamma-year-format-examples.json`에 있다. 아래는 월급 항목의 구조 예시이며 실제 모델 응답을 주장하지 않는다.

```json
{
  "meaningPolicyVersion": "PAYSE-MEANING-1",
  "items": [
    {
      "itemKey": "요청과 같은 항목 키",
      "classification": { "status": "candidate", "value": "income", "reasonCode": "supported" },
      "meaning": { "status": "candidate", "value": "salary", "reasonCode": "supported" },
      "reason": "제공된 거래 적요에서 급여 근거가 확인됩니다.",
      "evidenceTransactionIds": ["원천의 실제 거래 UUID"]
    }
  ]
}
```

## 검증 범위

`testing/analysis/gamma_year_cases.py`는 정답 파일을 읽지 않고 연간 거래를 20건씩 92묶음, 반복 후보 예시 5묶음으로 나눈다. 반복 features는 명시한 테스트 준비값이며 운영 반복 탐지기가 아니다. 현재 최대 60거래/요청을 지키지만 실제 토큰 수를 0 또는 6,000으로 추정하지 않는다. 1년치를 한 번에 공급자에게 보내지 않는다.

Java `AnalysisServiceTest`는 97묶음을 **실제 의미 실행 서비스 + 모의 공급자**로 검사한다. 원천 1,825건의 포함, 분류 정답 누출 없음, ID 복원, 정상 unknown과 응답 구조를 확인한다. 이 검사에서 외부 모델 호출은 0회다. 실제 후보 탐지 정확도·실제 토큰·외부 KMS/공급자 연결·앱 확인 UI 완료를 뜻하지 않는다. 현재 반복 features 생성·후보 화면의 프론트 연동은 별도 확인 대상이다.

`database/test_financial_service.py`와 `FinancialHttpTest.gammaImport`는 새 폐기 PostgreSQL의 실제 HTTP로 감마 로그인 후 미연결, 명시적 기관 연결, 9계좌·4카드·1,825거래 전체 페이지, 같은 데이터 버전, 재로그인 상태 복원, 다른 사용자 상태·원천 불변을 검사한다. `database/test_analysis_service.py`의 기존 격리 CI에도 같은 준비·Java 검사가 포함된다.

## 테스트 종료 후 제거

이 연간 대체는 영구 서비스 기능이 아니다. 테스트 종료 시 다음 테스트 파일·참조를 함께 제거한다. 날짜나 로그인 횟수로 자동 삭제하지 않으며 실제 데이터 정리는 대상 감마 자료를 확인하는 별도 작업으로 처리한다.

- `testing/scenarios/gamma_year.py`, `testing/analysis/gamma_year_cases.py`와 `tests/test_fixtures.py`의 연간 사례 검사.
- `database/test_financial_service.py`의 연간 준비·환경값과 `FinancialHttpTest`의 `gammaImport`·`otherState`. 기존 금융 회귀 검사는 보존한다.
- `apps/ai/testing/export_contracts.py`의 감마 입력·예시 내보내기, `AnalysisServiceTest`의 감마 사례와 `AiTestConstants`의 파일 참조, `build.gradle`의 감마 생성 입력 경로.
- 저장소 밖 생성 자료·평가 정답·DB 백업의 보관 또는 폐기 여부를 확인한다. 실행 중 DB의 감마 합성 원천은 백업·소유권 대조 후 승인한 다음 원천으로 교체하고 연결·설정의 정리 범위를 명시한다. 다른 계정은 건드리지 않는다.

일반 로그인·금융 API·영구 마이그레이션·런타임 JAR에는 감마 테스트 분기를 남기지 않는다. 새 PC 설치나 일반 서버 시작에서 연간 자료를 자동 생성·적재하지 않는다.

운영 연결 구성과 비용 장부 구현은 [분석 실행 설정](analysis-runtime.md)에 정리했다. 실제 조직 크레딧·프로젝트 자격·KMS·가격 확인 및 운영 활성화는 별도이며, 모의 검사 통과를 실제 LLM 평가 완료로 보고하지 않는다.
