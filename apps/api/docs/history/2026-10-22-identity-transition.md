## 작업 범위

단일 name 계약이 확정됐지만 초기 DDL·시드·SQL exporter·모바일 데모 계정이 구 이름을 사용하고 있었다. #22 세션·조회 API 구현의 선행 작업으로 이 저장·소비 경로를 함께 전환했다. 실제 HTTP 세션·스냅샷·설정 저장 API 구현은 포함하지 않는다. 원본 저장소·GitHub·Notion·기존 사용자 DB에는 쓰지 않았다.

- 확정 세 UUID·전화번호는 유지하고 데모알파·데모베타·데모감마의 name 하나를 사용한다.
- 금융 스냅샷 15개와 catalog의 의미값은 그대로다. 사용자 설정·금융 행·세션·dataVersion을 이름 전환 때문에 초기화하지 않는다.
- 구 컬럼 값은 기존 DB의 읽기 전용 전환 계획 파일에 보존한다. 자동 DB 변경은 적용 배치파일에 포함하지 않는다.
- seed 검증은 파일 해시뿐 아니라 필드 집합·확정 사용자 매핑·소유권·초기 시나리오를 확인한다. 코드를 실제 인증 가능하게 바꾸지는 않는다.
- 문서 대조 중 공통 데이터 모델의 구 저장 상태 설명을 발견하여 해당 경로를 수정 전에 작업 명세에 추가했다. 정책이나 필드 정의는 바꾸지 않았다.

## DB 검증에서 발견·수정한 사항

- 기존 삭제 차단 테스트는 FK 오류 코드 하나만 예상했다. 실제 PostgreSQL15.13에서는 다른 FK가 먼저 거절할 수 있어, FK 계열 오류와 사용자·세션·계좌 보존을 함께 확인하도록 수정했다.
- 이행 초안의 단일 활성 세션 인덱스 검사, 구 컬럼의 사용자 정의 의존성 검사, 외부 계획 입력 타입 검사, 사용자·세션 RLS 정책 검사를 교차검토에서 보완했다. 단순 플래그나 문자열 부분 일치만으로 정상 전환 상태라고 판정하지 않는다.
- 최종 이행 회귀25개·SQL4종은 독립 PostgreSQL15.13에서 통과했다. 실제 스키마23표180컬럼을 확인했다. 목표 PostgreSQL18에서 실행한 결과가 아니며 실제 사용자 DB에는 적용하지 않았다.
- Python 회귀 중 생성된 __pycache__5개가 범위 검사에 잡혀 제거했고, 후속 실행은 bytecode 자동 생성을 끈 상태로 수행했다. 최초 발견을 최종 diff가 깨끗하다는 이유로 없던 일로 기록하지 않는다.
