# 2026-10-23 공통 저장 구조·표시명 전달 기록

관련 이슈: #18, #19, #22. 이 문서는 전달 기록이며 현재 계약은 루트 docs의 필드/DB/API 사전을 따른다. 이전 미적용 상품명 패키지는 공통 저장 구조 패키지로 대체한다.

| 변경      | API 쪽 반영                                               | 모바일 담당자 확인                                                                                    |
| --------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 사용자    | users / user_attributes / phone, 금융 소유자 ID 유지      | HTTP의 userId/name/phone/settings 형태는 유지. private server-seeds의 syntheticPhone만 phone으로 변경 |
| 세션      | demo_sessions와 /demo-sessions 유지                       | 주소·기존 세션 우선 정책 변경 없음                                                                    |
| 원천 표시 | 상품명·거래명·기관명을 자연스럽게 정리, PAYSE-FIXTURE-2   | API 원본에서 쓰는 자산 6개와 표시명/버전 기대값 동기화                                                |
| 초기 상태 | 기본 DB 적재의 급여 속성은 null, 계획·모아둘 돈·정산 없음 | 준비된 JSON 사례를 일반 신규 사용자의 자동 초기값으로 간주하지 않음                                   |
| 사례      | 기존 15개 사례의 ID·금액·날짜·기대 결과 보존              | 선택한 ready 사례는 이전 설정/부분 정산을 계속 재현                                                   |
| 은행      | 공통 목록 20개, 계좌 사례는 기존 5은행·4카드              | 목록을 연결 지원 범위로 자동 확대하지 않음                                                            |

동기화 대상 자산: alpha-ready, alpha-shock, alpha-unconnected, salary-wait, beta-ready, gamma-month-end. 기존 fixture_copy_test의 복사본 비교, policy_review_test와 connection_screens_test의 기관 표시 문구, fake_repository의 자료 버전 기대값을 확인한다. 데이터 변경에 맞춰 의미가 같은 기대값만 조정하며 계산 기대값은 유지한다. 모바일 소스·자산은 이 작업에서 수정하지 않았다.

최신 검토 기준은 5f53e69(팀원 PR #91 포함)이다. 이후 프론트 변경은 적용 전 해시 검사로 감지하며 일치하지 않으면 설치가 중단된다. API 쪽 검증 결과를 모바일 기기 검증 완료로 표시하지 않는다.
