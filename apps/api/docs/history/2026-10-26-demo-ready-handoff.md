## A/B 반영 경계

- A: 생성기·catalog·manifest·서버 준비 시드의 알파 initialCase를 demo-ready로 반영한다. 준비 도구에서 일반 테이블로 적재하며 기본 적재는 연결/설정이 비어 있고 선택 시나리오 적재만 저장된 설정을 포함한다. HTTP 조회 제공 완료나 기존 DB의 자동 전환을 뜻하지 않는다.
- B: `apps/mobile/assets/fixtures/demo-ready.json` 복사, `pubspec.yaml` 자산 등록, `lib/data/fixture_scenario.dart` 목록과 `defaultScenario`, `lib/app/dev/dev_user_fixtures.dart`의 알파 원본 매핑을 반영한다. `lib/app/payse_app.dart`가 이 매핑을 원본 로더로 주입하므로 FakeFinancialServer 본문 변경을 전제하지 않는다. Fake 로그인/연결/시나리오 선택의 기본값과 대응 테스트를 새 사례로 맞춘다. 기존 alpha-ready 및 파생 사례는 삭제하지 않는다.

- 확인할 항목: 원본 사본 동일성, 연결0 공개 키, 부분 연결 소유권·급여 접근 제한, 파싱→어댑터→계산, 완료 카드값 제외, 통신비의 다음 기간 분류, 수리비 원천 재가산 금지. A가 모바일·계산 코드를 수정하거나 화면 시연 완료로 표시하지 않는다.

통신비 날짜 차이의 원래 의도는 자료로 확인되지 않았다. 자동 정산·미지급 확정·사용자 일정 수정 이력을 만들지 않는 것으로 이번 시연 범위를 한정한다. #59 반복 회차 생성, 새 카드 청구 생성, 공과금·보험료 추가는 포함하지 않는다.
