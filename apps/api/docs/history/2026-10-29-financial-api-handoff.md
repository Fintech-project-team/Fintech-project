# 2026-10-29 금융 조회·설정 API 인계

이 기록의 검증 수치는 최초 구현 기준이다. 같은 브랜치에서 적용한 JPA 전환과 후속 검증은 [JPA 인계](2026-10-29-jpa-handoff.md)를 따른다.

관련 이슈: [#22](https://github.com/Fintech-project-team/Fintech-project/issues/22), [#23](https://github.com/Fintech-project-team/Fintech-project/issues/23). 기준 커밋 `37d0b8f4196c686d325704e1ba2fe76091699ac3`, 작업 브랜치 `feat/api/financial-read-write-22-23`.

## 구현

- `FinancialController → FinancialService → FinancialRepository/FinancialWrites`가 기존 인증 트랜잭션·사용자 잠금·RLS를 재사용한다. 실제 DB를 읽으며 런타임에 fixture 파일을 반환하지 않는다.
- [HTTP 계약](../../../../docs/api-contract.md) §3·§4의 16개 메서드/경로를 구현한다. 스냅샷·거래 페이지·기관 연결, 계좌 선택·별칭, 급여/카드 설정, 의무·보호 설정 생성/변경/DELETE/cancel이다. 기존 세 인증 경로도 유지한다.
- 거래는 최대 100건의 UUID 순서다. 기간 밖 참조만 보조 배열에 조립하며 미연결 자원은 기존 생략·제한 표식을 사용한다. 다음 페이지의 공개 참조는 유지한다.
- cursor는 별도 서버 키의 AES-GCM으로 사용자·세션·버전·시점·연결·조회 범위·위치를 검증한다. 자격·토큰·금융 원문은 넣지 않는다.
- 설정·배정·영수증·dataVersion을 원자 저장한다. 같은 키는 버전 검사보다 먼저 확인하고 같은 요청은 기존 영수증과 현재 권한의 최신 Snapshot을 반환한다. 실패·취소·지연 제약 위반은 미커밋 변경을 모두 롤백한다.
- cancel의 명시 목록은 현재 미해제 배정의 정확한 ID·금액과 일치해야 한다. 지급·해제 이력, 실제 잔액, 원천 급여 근거를 변경하지 않는다.
- `007_financial_access.sql`은 설정 컬럼·테이블에만 필요한 쓰기 권한을 추가한다. 원천 거래·잔액·급여 근거는 조회 전용이다. 기존 DB에는 실행하지 않았다.

## 확정한 호환 조건

- 실제 응답은 `PAYSE-API-0.6-3`, 원천은 `PAYSE-DRAFT-3`을 유지한다. v4 준비 자료는 보존하며 공개 전환은 Flutter 공동 검증 후 진행한다.
- 지출·모아둘 돈 이름은 trim 후 1~80 grapheme, 계좌 별칭은 기존 1~12 grapheme다. 경계 공백 제거는 Flutter의 Unicode 공백 기준과 맞춘다. 금융 쓰기 본문은 65,536바이트까지다.
- 기관 연결 해제 시 해당 계좌 선택도 해제하고 재연결 시 자동 선택하지 않는다. 계좌 원천·급여 근거·예정 지출·모아둘 돈은 보존한다.
- 월급/카드 계획 설정만 저장한다. 지급 완료·반복 일정·급여 구간·가용 금액·AI 판단은 서버가 만들지 않는다.

## 검증

- 격리 PostgreSQL 15.13과 실제 HTTP 금융 검사 17개 통과: 조회·페이지·부분 연결·설정·재로그인·소유권·동시 멱등/버전 충돌·SQL 취소·지연 제약 롤백·최소 권한·원천 보존.
- 같은 실행의 전체 Java 검사 167개 통과, 실패·오류·건너뜀 0개. 기존 인증 회귀 DB의 금융/사용자 기준 자료도 전후 동일하다.
- 투영 검사는 준비 원천, 511개 기관 연결 조합, UUID 페이지 경계, 순환 참조, 숨긴 ID·허용 필드 밖 자료 차단을 포함한다.
- 실제 HTTP의 연결 전·전체·은행만·은행/카드 부분 연결·설정 저장 후 Snapshot 5종을 변경하지 않은 Flutter `FinancialSnapshot.fromJson`으로 읽어 통과했다. 앱의 실제 HTTP Repository 연결·기기 시연 완료를 뜻하지 않는다.
- Java 컴파일·필수 주석 검사 통과. 최초 실행의 테스트 DB 이름 제한 오류·저장소 프록시 구성 오류·필수 키 누락 예외 유형 오류는 수정 후 재검증했다.

재실행은 [DB 검사 안내](../database-tests.md)의 금융 실행기를 사용한다. 기존 DB를 대상으로 실행하지 않는다.

## 제한·미실행

- 미확보 원참조의 기관 권한 근거가 DB에 없으면 503이다. `transaction_references`에는 기관 출처가 없으므로 권한을 추정해 `referenceResolutions`를 공개하지 않는다. 기존 `refund-unavailable-original`은 이 제한을 검증한다.
- 조회 기간 소속을 확인할 날짜/시각이 전혀 없는 거래는 503이다. 날짜를 만들거나 해당 거래를 조용히 누락하지 않는다. 현재 준비 거래에는 이 사례가 없다.
- v4 공개, 실제 금융기관 연결, 탈퇴/파쇄, LLM API, 외부 HTTPS 배포, 운영 DB 이행, Android/iOS 기기 검사는 별도다. 기존 DB·모바일·계산 패키지·더미 원천은 수정하지 않았다.
