# Android 시연 서버 준비·v4 전환 기록

2026-10-30 · 관련 이슈 #22·#23, KMS 준비 연계 #32. 작업 `PAYSE-ANDROID-SERVER-20261030`, 기준 커밋 `e51745627b94bdbb1bf2362988b53dd6014fc23d`, 브랜치 `feat/api/android-demo-server`. 이 기록은 당시 실행 결과이며 Android 연동 완료나 이슈 종료를 대신하지 않는다.

## 구현·환경

- 신규 서버는 `generated-v4`의 원천·Statement.items를 `PAYSE-API-0.6-4`로 제공한다. 기존 v3 DB는 자동 이행하거나 이름만 바꾸지 않는다. 청구 항목은 상세이며 홈 계산 금액을 추가하지 않는다.
- 청구·항목은 각각 한 번 조회한다. 소유자·카드·버전·참조 검증, null·음수 조정액/청구액·부분 연결·다음 페이지·접근 제한 표식을 적용한다.
- 신규 준비 도구는 급여 안내 스키마 009와 `salary-notices`를 포함한다. 구환경에 기능 표식이 없으면 기존 프로필을 유지한다.
- `--demo-state`는 initialCase의 명시 사용자 설정 포함 여부다. 시연 전용 사용자·금융 테이블 또는 컬럼을 만들지 않는다. 알파 demo-life, 베타 beta-ready, 감마 gamma-month-end의 기존 ID·금액·날짜·원천을 사용한다.
- 같은 PC의 Caddy → loopback API 구성을 추가했다. `direct`는 전달 헤더를 무시하고 `loopback-proxy`는 loopback 바인딩·실제 원격지·단일 숫자 IP를 확인한다. Caddy가 외부 전달 헤더를 제거/재작성한다. Cloudflare는 사용하지 않는다.
- Docker 엔진 28.0.4를 확인했다. Java 21 이미지 digest를 고정한 비관리자 실행 이미지와 비밀 없는 이동 묶음을 준비했다.
- Google Cloud CLI 591.0.0 설치·버전 확인을 완료했다. 프로젝트·키·실행 주체가 없으므로 KMS/유료 LLM은 활성화하지 않았다. 기존 GoogleKms 어댑터의 실행 인증 공급자·저장 경로 연결은 별도 구현/검증 범위다.

## 분리한 실제 환경

모두 `%LOCALAPPDATA%/PAYSE/development/` 아래 새 디렉터리이며 기존 Windows PostgreSQL 서비스·api-v3 DB를 대상으로 하지 않았다.

| 환경         | 디렉터리                   | PostgreSQL / API | 용도                                                 |
| ------------ | -------------------------- | ---------------- | ---------------------------------------------------- |
| v3 초기 검증 | android-verify-20261030    | 15433 / 18081    | v4 결정 전 검증 기록 보존                            |
| v4 쓰기 검증 | android-v4-verify-20261030 | 15434 / 18082    | direct, 쓰기·안내 닫기·재로그인·재시작 검사          |
| v4 시연      | android-v4-demo-20261030   | 15435 / 18083    | loopback-proxy, 금융·안내 쓰기 없는 로그인/조회 확인 |

시연 서버 주소 `http://127.0.0.1:18083`은 PC 내부용 upstream이다. 폰에 전달할 외부 Base URL이 아니다. 시연 DB에는 쓰기 검증의 취소 이력·닫힌 안내·증가한 버전을 복사하지 않았다. 조회 smoke의 세션 발급/종료 기록은 남는다. DB 비밀번호·서명 키는 저장소 밖 사용자 ACL·DPAPI로 보호한다.

추가 PostgreSQL 통합 회귀는 `test_salary_notice_service.py`로 실행하여 Java 230개·SQL 9개 PASS, 실패·skip 0을 확인했다. 기존 v3 금융·인증·권한·동시성·취소/롤백·급여 안내·원천/기준행 보존을 포함한다. Python 전체 190개 PASS 후 검사 종료·묶음 파일 보완에 영향받은 10개/6개도 PASS였다(새 총 검사 수 191개).

실제 환경의 `verification.json`, `smoke.json`, `tls-verification.json`은 소유 환경 폴더에 보존한다. 일회성 TLS 연결 검사는 금융·안내 데이터를 쓰지 않았고 임시 프록시·키는 종료/정리했다. 공개 주소·실제 폰은 사용하지 않았다.

추가 회귀 검사에서 과거 `unsupportedSourceVersion`의 v4 거절 가정을 발견했다. v4 지원 결정에 따라 비지원 버전으로 검사 입력을 바꿨으며 503 기대값은 유지했다. 기존 금융 전용 실행기는 새 급여 suite의 자격을 준비하지 않아 그 suite가 skip된다. 최종 통합 검증에는 금융·급여 자격을 함께 준비하는 `test_salary_notice_service.py`를 사용한다.

## B 담당 연결 사항

| 위치·기능                                          | 전달 내용                                                                                                                                                                                                      |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/mobile/lib/app/payse_app.dart`의 저장소 주입 | Fake/Unavailable 경로를 실제 HTTP 구현과 교체 가능하게 연결. Base URL을 설정으로 주입하고 세션을 전달한다. 현재 코드에 서버 주소만 입력해도 연결되는 상태는 아니다.                                            |
| 금융 모델·조회                                     | v4 items·제한 표식·다음 페이지를 함께 처리. 청구 `dueDate=null`은 계약상 유효하므로 파서와 미확보 표시를 보완한다. 현재 기본 시연의 청구일은 모두 있어 기본 시연 오류를 뜻하지 않는다.                         |
| 급여 안내                                          | Bearer로 `GET /salary-notices/{payMonth}`, `PUT /salary-notices/{payMonth}/dismissal` 사용. PUT 본문·금융 버전·작업 키 없음. 계약 `PAYSE-SALARY-NOTICE-1`; 사용자+명목 회차별 상태, 금융 상태는 변경하지 않음. |
| Android TLS                                        | 기기 Keystore 비반출 키·CSR 생성, 인증서 체인을 사용하는 TLS adapter 구현. 서버 이름·체인 검증을 해제하지 않는다. TLS/프록시 오류와 API 업무 JSON 오류를 구분한다.                                             |
| 공동 검증                                          | 등록 폰 허용·미등록 거절, 로그인·전체 페이지·설정 저장·재로그인·급여 안내·청구일 미확보를 실제 외부 HTTPS에서 확인한다.                                                                                        |

모바일·계산 패키지는 수정하지 않았다. 팀원이 보고한 v3 완료를 실제 HTTP·mTLS 통합 완료로 기록하지 않는다.

## 남은 준비

도메인/최종 서버 이름, 신뢰할 서버 인증서, 이 PC에 도달하는 공인 경로, 폰 CSR과 인증서 발급/등록이 필요하다. 방화벽·공유기·공개 연결·Windows 자동 시작은 설정하지 않았다. 설치·기기 등록 절차는 [Android HTTPS](../../deploy/android-https.md), 제어 방법은 [로컬 서버 안내](../local-server-guide.md)를 따른다. 기존 DB/키를 이동하는 백업·복원과 실제 KMS/LLM 활성화도 별도다.
