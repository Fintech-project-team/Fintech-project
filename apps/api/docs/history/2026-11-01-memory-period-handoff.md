# 기간 조회·AI 기억 관리 인계 — 2026-11-01

관련 이슈: #32, #22. 현행 계약은 [분석 API](../analysis-api.md), [저장 구조](../analysis-storage.md), [금융 API](../../../../docs/api-contract.md)를 따른다. 이 파일은 작업별 구현·검증 기록이다.

## 변경

- 금융 `GET /transactions`에 선택적 `startDate`·`endDate`를 추가했다. 기존 Snapshot·cursor 단독 경로와 금융 v4 응답은 유지한다. 원천 확보 범위와 요청 기간을 구분한다.
- `GET /analysis-memories`는 최초 저장일의 한국 날짜 범위로 개별 기억을 조회한다. 20건씩 제공하며 실제 재사용 자격은 항상 `unchecked`다. 적용하려면 기존 결과 조회에 최신 입력을 전달해야 한다.
- 비활성 기억은 관리 목적으로 열람할 수 있다. 만료·삭제·현재 근거 접근 제한은 본문을 숨기며, 조회로 기한을 연장하지 않는다. 금융 조회에는 AI 보존 플래그를 적용하지 않는다.
- 011 이행은 원천 접근 검증용 `source_refs`·`source_hash`와 기간 인덱스를 추가한다. 모델의 일부 근거가 아닌 서버가 검증한 입력의 전체 관련 거래 집합을 보존한다. 기존 행은 NULL로 남기고 목록에서 `unverified`로 처리한다. 기존 결과 조회의 최신 입력 검증은 유지한다.
- 사용자·세션·기간·자료 문맥을 페이지 토큰에 묶고, DB 밖 복호화 후 인증·삭제·만료·공개 권한을 재검증한다. 조회 중 변경은 본문 없이409, 로그아웃은401이다.
- AI 개발 지침은 `apps/ai/AGENTS.md`로 통합했다. 다른 담당 영역의 소스·금융 fixture·운영 DB·인증 키는 변경하지 않는다.

## 검증 기록

실제 PostgreSQL 15.13·loopback HTTP 전체 회귀: API Java335개 PASS(분석 HTTP35개·금융 HTTP21개 포함), AI Java56개·Python96개 PASS. Java/Python 계약 대조 정상5,083건·오류11건 PASS이며 실제 모델 의미 정확도 검사는 아니다. memory-period-api-check-02 기록에서 금융 원천·인증/급여 기준 행 보존, 기존 DB 접속0회·서비스 변경0회·임시 DB 종료를 확인했다.

첫 HTTP 전체 검사는 기존 테스트의 대량 seed 재적재가 `SET CONSTRAINTS ALL IMMEDIATE`에서 시간 초과되어 중단했다. 원래 실패 기록을 유지하고 준비 경로 보완 후 전체 회귀를 다시 실행해 통과했다. 제약조건·RLS를 끄거나 검사를 생략하지 않는다.

독립 실험에서는 원본 JDBC 적재18.332초, 최종 제약 검사 직전 `ANALYZE`만 삽입한 적재4.024초를 확인했다. 최초120초 시간 초과 자체는 독립 재현되지 않았으므로 통계만이 확정 원인이라고 단정하지 않는다. `AnalysisHttpTest.prepareSeed`의 폐기 DB 준비에서만 이 방법을 사용하고 실제 API·금융 SQL의 제약은 유지한다.

허용하는 최소 날짜0001-01-01을 한국 자정에서 UTC로 바꾸면 연도0이 된다. PostgreSQL은 해당 ISO 문자열 CAST를 거절했지만 `OffsetDateTime` 타입 바인딩은 같은 시각으로 왕복했다. 기간 Repository는 타입 바인딩으로 보완했고 실제 HTTP의0001~9999년 범위 검사에 포함했다.

추가 011 SQL 검사18개 PASS: 형식·RLS·열별 권한·불변·기간·이행 실패 롤백·기존 암호문/시각 보존을 확인했다(memory-period-sql-check-01). 실제 LLM/KMS·유료 호출·운영 DB 이행·모바일 변경은0건이다. 공통 하네스 최종 runId는 커밋 메시지에 기록한다.

## 남은 범위

- 신규 011 이행의 운영 적용은 별도 배포 작업이다. 서버 시작 때 자동 실행하지 않는다.
- 금융 조회는 기존처럼 사용자 전체 원천을 읽어 투영·검사·정렬한다. 기간 선택이 SQL 기간 검색 최적화까지 완료했다는 뜻은 아니다. 대규모 2년치 자료의 속도는 미측정이다.
- AI 목록 문맥 해시는 요청 기간의 메타 행 수에 비례한다. 암호문 복호화는 페이지의 열람 가능한 최대20건으로 제한한다.
- Flutter 연결·실기기 검증, 실제 공급자/KMS 활성화, 비용 장부, 자동 정리·백업/키 파쇄는 별도다. #32 전체 완료로 처리하지 않는다.

## 팀원 전달 초안

확인한 호출부는 `apps/mobile/lib/data/connection/financial_api.dart`의 `loadTransactionPage(cursor)`와 `transaction_history.dart`의 `TransactionHistoryCollector`다. 기존 수집기는 Snapshot 첫 페이지부터 시작하므로 새 기간 조회에서는 별도의 빈 목록에서 날짜 쌍의 첫 응답부터 모아야 한다. 기본 연간 목록과 기간 선택 결과를 섞거나 기간 cursor만 기존 메서드로 넘기면 안 된다. 새 요청 파라미터·관리 목록 모델·오류 표시·삭제 후 캐시 무효화는 B가 구현한다. 기존 `TransactionPage` JSON 필드는 유지되지만 새 흐름의 공동 실행 검증은 별도다.

> 금융 거래는 기존 v4를 유지하면서 startDate/endDate 기간 조회를 추가했습니다. 다음 페이지에도 같은 날짜 쌍과 cursor를 보내고, 409면 첫 페이지부터 다시 조회해 주세요. coverage는 실제 원천 확보 범위이므로 요청한 2년을 모두 확보했다고 표시하면 안 됩니다. AI 기억 목록은 GET /analysis-memories로 20건씩 확인·삭제용으로 제공합니다. active=false도 열람 가능하지만 만료·삭제·권한 제한 본문은 생략하며, 실제 적용 여부는 최신 입력으로 기존 결과 조회 API에서 확인해야 합니다. 모바일 파일은 수정하지 않았으며 연결·실기기 검증은 별도로 필요합니다.
