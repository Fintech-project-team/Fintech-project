금융 필드 사전은 [데이터 모델](../data-model-draft.md), 물리 저장은 [DB 설계](../database-design.md)가 기준이다. 기존 MD·SQL·fixture·Flutter·Java 파일은 변경하지 않는다. 이번 신규 파일은 이 폴더의 MD 4개와 `docs/tasks/PAYSE-API-20-20261021.json` 1개다.

인증 내부 설계는 [#21](https://github.com/Fintech-project-team/Fintech-project/issues/21), 세션·조회 구현은 [#22](https://github.com/Fintech-project-team/Fintech-project/issues/22), 설정 저장 구현은 [#23](https://github.com/Fintech-project-team/Fintech-project/issues/23)의 후속 범위다. DB migration·파쇄 운영 작업의 구체 이슈 배정은 이 문서에서 확정하지 않는다. 앞서 작성한 내부 구조·DB 보완·실험 기록은 별도 후속 자료로 보존하며 이번 적용 대상에 포함하지 않는다.

## 기준과 확정 정책

최신 사용자 결정 → [제품 기준](../../../../docs/product-baseline.md)·[공통 계약](../../../../docs/data-contracts.md)·[화면 규칙](../../../../docs/v0.6-screen-rules.md) 순으로 대조한다. [프론트 보완](../../../mobile/docs/screen-rules-update.md)의 `A 확인`은 이미 합의한 API로 간주하지 않는다. 경로·페이지 크기·DTO·요청 본문 크기 한도는 API 설계안이며 실제 연결 전 담당자끼리 형식을 확인한다; 제품 정책을 다시 선택하는 절차는 아니다.

| 항목           | 적용 기준                                                                              |
| -------------- | -------------------------------------------------------------------------------------- |
| 탈퇴           | 비활성화·즉시 로그아웃·1년 보관 후 파쇄; 기존 ‘세션 정리’ 문구보다 최신 직접 결정 우선 |
| 인증 제한      | 자격 조합 실패 5회/5분 후 5분 대기, IP 인증 요청 60회/분; 기기 PIN 제한과 별개         |
| 배정 항목 취소 | 사용자가 확인한 미지급 연결 해제와 취소를 원자 처리; 실제 잔액·지급 근거 보존          |
| 계산           | U·소비 합계·미래 회차·시뮬레이션은 Flutter; 서버는 저장 제약 검증                      |
| 원천           | PAYSE 합성 자료; CODEF 직접 호출·동일 형식 복제 의무 없음                              |

1년 보관은 사용자 제품 결정이며 법정 보관기간이라는 주장이 아니다. 탈퇴 후 같은 자격의 재가입·자동 복구 경로는 정의하지 않는다. 프론트의 ‘탈퇴 후 재가입 시 첫 계산 표시’를 구현하면 비활성 계정 접근 금지와 충돌하므로 인계 때 명시한다.

배정 amountKRW는 지급 해제 누계를 포함한 현재 유효 총 배정액이다. 기존 문서의 ‘초기·원래 배정액’을 수정 불가 최초값으로 읽지 않는다. 최초·이전 값은 변경 이력으로 보존하고 연결 해제만으로 releasedKRW나 지급 근거를 바꾸지 않는다.

## 버전 경계와 프론트 영향

v0.6은 데모 세션·재확인·종료·탈퇴, 최초 기관 연결, 계좌 선택·별칭, 연간 원천 페이지, 급여·카드 계획, 예정 지출·모아둘 돈·명시 배정의 계약을 포함한다. 기존 월간 계획·정산 근거 읽기도 유지한다.

반복 후보 승인·분류 정정·거래에서 계획 등록은 v0.7, 미래 시뮬레이션은 v0.8, 정산 정정·돌발 사건·보호 조정은 v0.9의 후속 쓰기다. 기관 추가/해제 화면의 P1 우선순위도 유지한다. #20 명세 완료로 서버 구현·재접속 유지 완료를 선언하지 않는다.

API에 화면 번호·문구·탭 순서를 저장하지 않는다. Flutter는 Repository/mapper에서 API 표현을 화면·계산 모델로 변환한다. 이번 작업으로 현재 프론트 파일이 바뀌지는 않으며 연결 전 표현·부분 연결·페이지·멱등·탈퇴를 fake repository에 반영할 내용은 [인계 표](review-checklist.md)에 정리한다.
