## 검증과 완료 경계

문서의 경로·타입·권한·멱등·오류 규칙, 18개 메서드·경로, 상대 링크와 허용 변경 범위를 검사한다. 검사 계획·자동 포맷은 PASS 근거로 사용하지 않는다. 실행 결과와 보고서 runId는 해당 작업의 검증 기록에 남긴다.

이 API 문서의 완료 기준만으로 API 실행·DB migration·공유 인증 저장소·파쇄 작업·성능 부하·Flutter 기기 검증을 통과했다고 표시하지 않는다. 데이터 감사에서 실행한 원본·SQL 검사는 별도 감사 보고서의 실제 실행 근거를 따른다. DB 제약 검사 결과만으로 API 구현 통과를 주장하지 않는다. 담당자 간 계약 확인과 실제 연결 검증은 별도 상태이며 문서 검증 통과로 완료 표시하지 않는다.

이름 통합으로 세 합성 사용자의 로그인/호칭 이름은 데모알파·데모베타·데모감마다. DB 공백 금지는 인증 식별값에만 적용한다. 호칭의 실제 화면 위치는 B가 정한다. 연결 전 상태와 부분 연결 변환은 아래 공통 계약 검증 기준을 따른다. 현재 구 필드가 있는 서버 seed를 새 로그인 응답 구현으로 간주하지 않으며 후속 전환 상태는 [인증 인계](auth-verification.md)를 따른다.

## 연결 표현의 후속 구현 검증

아래는 실행된 API/Flutter 테스트가 아닌 명세의 완료 기준이다. 서버와 FakeRepository가 같은 입력·상태·기준 버전에서 같은 공개 결과를 제공하는지 검사한다.

| C01 | alpha·beta·gamma 각각 최초 연결 전                                                                | 각자의 userId/sourceVersion/asOf/기관 목록 유지, API schemaVersion 사용, institutionLinks/coverage=[], 금융 키 생략. alpha ID/데이터를 beta/gamma에 재사용하지 않음 |
| C02 | 해당 사용자의 일부 은행만 확정 연결                                                               | 허용 계좌·은행 거래 및 종속 설정만, 숨긴 부모·ID·고아 참조 없음. 원본은 불변                                                                                        |
