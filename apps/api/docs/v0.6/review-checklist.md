## 이번 검증과 완료 경계

문서의 경로·타입·권한·멱등·오류 규칙, 18개 메서드·경로, 상대 링크와 허용 변경 범위를 검사한다. 최초 #20 설치는 추가 전용이었고, 이름을 반영한 #21 통합본은 검토된 기존 문서 제한 수정과 백업을 포함한다. 검사 계획·자동 포맷은 PASS 근거로 사용하지 않는다. 실행 결과와 보고서 runId는 배포 묶음의 검증 기록에 남긴다.

API 실행·DB migration·공유 인증 저장소·파쇄 작업·성능 부하·Flutter 기기 검증은 이번 범위에서 실행하지 않는다. 이전 DB 실험 결과를 이번 API 구현 통과 증거로 재사용하지 않는다. 담당자 간 계약 확인과 실제 연결 검증은 별도 상태이며 문서 검증 통과로 완료 표시하지 않는다.

이름 통합으로 세 합성 사용자의 로그인/호칭 이름은 데모알파·데모베타·데모감마다. DB 공백 금지는 인증 식별값에만 적용한다. 호칭의 실제 화면 위치는 B가 정한다. 연결 전 상태와 부분 연결 변환은 아래 사용자 채택 6·7의 기준을 따른다. 현재 구 필드가 있는 서버 seed를 새 로그인 응답 구현으로 간주하지 않으며 후속 전환 상태는 [인증 인계](auth-verification.md)를 따른다.

## 연결 표현의 후속 구현 검증

아래는 실행된 API/Flutter 테스트가 아닌 명세의 완료 기준이다. 서버와 FakeRepository가 같은 입력·상태·기준 버전에서 같은 공개 결과를 제공하는지 검사한다.

| ID  | 입력/상태                                                                                         | 기대 결과                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C01 | alpha·beta·gamma 각각 최초 연결 전                                                                | 각자의 userId/sourceVersion/asOf/기관 목록 유지, API schemaVersion 사용, institutionLinks/coverage=[], 금융 키 생략. alpha ID/데이터를 beta/gamma에 재사용하지 않음 |
| C02 | 해당 사용자의 일부 은행만 확정 연결                                                               | 허용 계좌·은행 거래 및 종속 설정만, 숨긴 부모·ID·고아 참조 없음. 원본은 불변                                                                                        |
| C03 | 허용 은행 1곳+카드사 연결, 그 카드의 출금 은행은 미연결                                           | 카드 유지, withdrawalAccountId 생략+제한 표시. null/0원 대체 없음, 출금 계좌에 의존한 계산만 보류                                                                   |
| C04 | alpha→beta 계정 전환 중 alpha 지연 응답                                                           | beta 컨텍스트에 alpha 이름/금융 객체/연결/페이지/캐시를 적용하지 않음                                                                                               |
| C05 | 연결된 계좌 included=false                                                                        | 계좌·연간 거래를 계속 조회, 해당 선택 때문에 not_connected 제한을 만들지 않음                                                                                       |
| C06 | 이미 연결·설정 저장한 같은 사용자의 재로그인                                                      | 저장한 연결·선택·설정 복원, 최초 상태로 재투영하거나 시드를 다시 적재하지 않음                                                                                      |
| C07 | 알려진 미연결 참조 / 실제 미상 null / 허용 범위 결과 없음 / 확인된 0원 / 다음 페이지              | 각각 제한된 생략 / null / [] / 0 / ID 유지·미수신으로 구분                                                                                                          |
| C08 | 부모 숨김에 따라 보호·의무·배정·정산·계획/버전/회차/결정·급여 근거를 처리                         | 공개되지 않은 부모 ID·근거·고아 참조 없음, 숨김을 지급 완료/미지급·전체 합계 완전성으로 해석하지 않음                                                               |
| C09 | 연결 저장 실패·중복/역전 응답·dataVersion 변경                                                    | 실패 때 성공 상태 확정 없음, 기존 멱등·버전 계약 준수, 성공한 새 범위에서 cursor/누적 페이지 폐기                                                                   |
| C10 | 원천 검증은 통과하지만 권한/참조 판정이 불가능 / 조립 실패·타임아웃                               | 정상 빈 값으로 위장하지 않고 오류 전달. 조립 한도·타임아웃은 기존 API 503, 구체 Fake 오류 클래스는 B가 정함                                                         |
| C11 | 대상 은행만 연결 / 다른 은행 1곳+대상 카드사 연결(대상 거래 출금 은행은 미연결)에서 각 recordKind | account_entry는 원천 은행, 카드 구매·환불·취소는 원천 카드사 연결로만 공개. 반대쪽 비공개 ID는 생략+등록된 제한 표식                                                |
| C12 | 미지원 schemaVersion·잘못된 ownerType/field/targetKind·숨김 ID·배열 인덱스·중복 표식              | 정상 계산으로 진행하지 않음. 서버 생성 전 검증 실패는 503, 클라이언트 수신 계약 오류는 오류 상태. 정상 중복은 튜플로 제거                                           |
| C13 | 원본 초기 dataVersion=1, 연결 저장 후 현재 dataVersion=2                                          | sourceVersion/asOf 유지, 응답 dataVersion=2. 원본 버전과 다르다는 이유로 실패하거나 1로 되돌리지 않음                                                               |
| C14 | 실제 미확보 원거래 ID는 있으나 소유자·기관 공개 근거가 없는 원본                                  | 공개 권한을 추정하지 않으며 503. 검증된 관계 근거가 있으면 기존 미확보 표현을 유지; 전체 기관 강제 연결로 해결하지 않음                                             |

원본 전용 validate.py와 API 표현 검증을 분리한다. 원본 시나리오의 다중 계정·부분 연결·지연 응답 시험을 명시적으로 수행하기 전에는 실제 연결 완료로 표시하지 않는다.
