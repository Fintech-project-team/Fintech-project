## B에게 전달할 내용

| 인계 항목 | 구현 시 유지할 동작                                                              |
| --------- | -------------------------------------------------------------------------------- |
| 금융 입력 | 기존 데이터 모델을 재사용하고 U·소비 합계·미래 회차 계산은 Flutter에 유지        |
| 연결 상태 | 연결 전 whitelist, 숨김 키와 원천 미상 null 구분, 제한 자원에 의존한 계산만 보류 |
| 페이지    | Snapshot 첫 페이지 후 cursor로 누적; 버전 변경 시 폐기·재조회; 중복 ID는 병합    |
| 연간 자료 | nextCursor=null과 원천 coverage 완전성을 별도로 판정; 미수신을 0원 처리하지 않음 |
| 저장      | 금융 쓰기 W/S 적용; 인증·탈퇴의 전용 형식과 구분; 늦은 낮은 버전 응답 폐기       |
| 삭제      | POST cancel에 사용자가 확인한 미해제 배정 ID·금액 전체 전달; 지급 이력 유지      |
| 인증      | 이름·전화번호만으로 접근 금지; PIN은 로컬; 재확인 성공도 새 토큰 발급 아님       |
| 탈퇴      | 비활성화 성공 후 접근 정보 정리·인증 화면; 재가입 자동 복구를 구현하지 않음      |

현재 Flutter 호출부는 [payse_app.dart](../../../mobile/lib/app/payse_app.dart)를 대조했으며 실제 금융 API 호출 구현 완료로 간주하지 않는다. [화면 보완 문서](../../../mobile/docs/screen-rules-update.md)의 재가입 표현은 최신 탈퇴 정책과의 차이를 인계한다. 기존 프론트 코드는 이번에 수정하지 않는다.

## 이번 검증과 완료 경계

문서의 경로·타입·권한·멱등·오류 규칙, 18개 메서드·경로, 상대 링크, 기존 파일 보존, 허용 신규 경로, 설치기의 추가 전용 동작을 검사한다. 검사 계획·자동 포맷은 PASS 근거로 사용하지 않는다. 실행 결과와 보고서 runId는 배포 묶음의 검증 기록에 남긴다.

API 실행·DB migration·공유 인증 저장소·파쇄 작업·성능 부하·Flutter 기기 검증은 이번 범위에서 실행하지 않는다. 이전 DB 실험 결과를 이번 API 구현 통과 증거로 재사용하지 않는다. 담당자 간 계약 확인과 실제 연결 검증은 별도 상태이며 문서 검증 통과로 완료 표시하지 않는다.
