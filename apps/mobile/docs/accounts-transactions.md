## 1. 바꾸는 이유

기존 구조는 02-3 계좌 목록에서 계좌 하나를 골라야 02-4 거래 내역으로 갔다. 여러 계좌·카드의 거래를 보려면 하나씩 열어야 한다. 계좌별 조회는 유지하고, 연결된 계좌와 카드의 거래를 날짜별로 함께 보는 통합 거래 내역을 더한다.

2026-10-28 범위 정정: 앞선 설계의 '계좌 입출금만, 카드 승인 제외'는 철회한다. 그 제한은 소비 중복 집계를 피하려던 것인데, **거래를 한 목록에 보이는 것과 금액을 합산하는 것은 별개**다. 카드 거래도 목록에 넣고, 합계·통계만 보류한다.

## 2. 화면 구조와 이동 흐름

2026-10-30 29-2 구현: 하단 탭 이름을 `계좌·카드`로 바꾸고(D10 확정), 안쪽을 두 탭으로 나눴다.

```text
29-2(구현)
하단 탭 '계좌·카드' ─┬─ [거래 내역] (앱 시작 시 기본) = 02-4 공통 거래 화면, 계좌·카드 통합 조회
                    └─ [계좌 관리]                  = 02-3
                          ├─ 계좌 행 누름  → 02-4 공통 거래 화면(그 계좌로 고정, 새 화면으로 열림)
                          │                   ← 뒤로: 계좌 관리, 이전 스크롤 위치 그대로
                          ├─ 연필 버튼     → 02-6 계좌 이름 바꾸기(시트)
                          └─ 계산에 포함할 계좌 바꾸기 → 01-1 재사용 → 저장 후 계좌 관리로 복귀
02-4 거래 행 누름 → 02-5 거래 상세(읽기 전용 아래 시트). 모든 행을 누를 수 있다(D7 변경)
```

- 기억(D1): 앱을 쓰는 동안 다른 하단 탭에 다녀와도 마지막 안쪽 탭·조회 조건·스크롤을 그대로 둔다. 앱을 새로 시작하면 `거래 내역`(기본 조건)으로 시작한다.
- 계좌 관리에서 연 계좌별 거래 화면은 안쪽 탭 위에 쌓인 화면이다. 조건은 `거래 내역` 탭 조건과 따로 관리한다. 뒤로 갔다가 같은 계좌를 다시 열면 이번 달로 새로 시작한다.
- 카드별 진입 화면은 이번 범위에 없다. 특정 카드의 거래는 거래 내역의 거래 수단 선택으로 본다.
- 조회 조건은 거래 내역 화면 안에서만 쓰며 홈 계산 포함 계좌(Account.included)를 바꾸지 않는다.

| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 조회 대상                    | 연결된 금융사의 모든 계좌와 카드. 계산에서 제외한 계좌도 포함                                                                                                     | 응답 모델 §2.3 "연결된 미선택 계좌·카드의 연간 거래는 계속 제공" |
| 계산 선택 변경               | 거래 조회 범위를 바꾸지 않는다. 단, 계좌 선택 저장은 자료 버전을 올리므로 받아 둔 거래 페이지를 버리고 새 Snapshot부터 다시 받는다                                | 응답 모델 §2.3·표 '연결/계좌 선택 저장 후 새 버전'               |
| 계좌 종류                    | 입출금·예금·적금 모두 같은 경로로 거래가 온다(더미 확인: 신한 자유 적금 13건, 국민 정기예금 12건). 종류별 조회 제한은 계약에 없다                                 | data-model Coverage, demo-ready                                  |
| 조회 지원하지 않는 계좌·카드 | 계약상 대상별 상태는 coverage `complete/partial/failed/unconnected`뿐이며 '거래 조회 미지원' 상태는 없다. 상품 종류만 보고 미지원으로 판단하지 않는다(T5, A 답변) | data-model Coverage.status                                       |

거래 수단 필터에는 '계산에서 제외' 표시를 붙이지 않는다. 조회 가능 여부와 혼동되기 때문이다. 계산 포함 여부는 계좌 관리에서만 보인다.

## 4. 02-4 공통 거래 화면

통합 조회(`거래 내역` 탭)와 계좌별 조회(계좌 관리에서 진입)가 같은 화면을 쓴다.

| 구분        | 통합 조회                                          | 계좌별 조회                                                     |
| ----------- | -------------------------------------------------- | --------------------------------------------------------------- |
| 머리        | 안쪽 탭 `거래 내역`                                | 뒤로 가기 + 계좌 표시명(제목) + '은행명 ····끝 4자리'           |
| 보이는 기록 | 연결된 계좌의 계좌 내역 + 연결된 카드의 카드 기록  | 그 계좌의 계좌 내역만                                           |
| 조건 칩     | '전체 거래 수단' · '거래 종류 전체'                | '입출금 전체'(전체 / 입금 / 출금)만. 거래 수단은 그 계좌로 고정 |
| 행 둘째 줄  | 거래 종류 · 거래 수단(§4-3)                        | 거래 종류만(거래 수단은 머리에 있으므로, D5)                    |
| 기준 줄     | '기준 시각 · 연결된 계좌와 카드의 거래 내역이에요' | '기준 시각'만                                                   |

### 4-1. 보여 줄 거래

- 계좌 내역: recordKind `account_entry`. 날짜는 bookingDate.
- 카드 기록: recordKind `card_purchase`(카드 사용)·`card_refund`(환불)·`card_cancellation`(승인 취소). 날짜는 각각 purchaseDate·refundDate·cancellationDate(승인 취소일, 2026-10-29 #132 계약 확정. 날짜만 확인되면 occurredAt은 null).
- 기간: 응답의 최근 달력 1년(coverage requestedStart~requestedEnd). 그 밖 거래(relatedTransactions)는 목록에 넣지 않는다.
- 같은 소비가 두 번 보일 수 있다: 카드 사용과 나중의 카드대금 납부, 체크카드 사용과 연결 계좌 출금(더미: 10/12 국민 체크카드 40,000원 사용과 하나은행 '국민카드 체크결제' 40,000원 출금). **둘 다 보이고, 연결 근거 없이 하나로 묶지 않으며, 합치지 않는다.** 자동으로 묶으려면 transactionRelations 같은 연결 근거가 필요하다(후속).
- 카드 사용을 계좌 출금으로 부르지 않는다. 거래 종류 라벨로 구분한다(§4-3).
- 거래명은 원천 merchantName 그대로다. 앱이 금액·날짜로 추정해 이름이나 종류를 붙이지 않는다. A가 거래처명(merchantName)과 적요(description)를 나눈 더미로 다시 구성한다(T8).
- 원천 사실은 바꾸지 않는다: 금액·날짜·거래명 수정 없음.

### 4-2. 조건 줄과 기본 조회

```text
        [‹]  2026년 10월 ▾  [›]          ← 가운데 정렬. 화살표는 이전·다음 달을 바로 적용, 가운데를 누르면 '기간 선택' 시트
[전체 거래 수단 ▾]  [거래 종류 전체 ▾]    ← 각각 '거래 수단 선택'·'거래 종류 선택' 시트
10월 19일 12:00 기준 · 연결된 계좌와 카드의 거래 내역이에요
```

| 항목        | 규칙                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본 조회   | 이번 달 · 전체 거래 수단 · 거래 종류 전체. '이번 달'은 스냅샷 기준 시각(asOf)이 속한 달의 1일~기준일(기기 시계가 아님)                         |
| 달 이동     | '›'는 기준 시각이 속한 달에서 비활성. '‹'는 조회 범위 첫 달까지. 제목에 '(19일까지)' 같은 범위를 붙이지 않는다                                 |
| 최근 기간   | 최근 3개월·최근 1년은 제목(선택지 이름) 아래에 실제 범위('2026년 7월 20일 ~ 10월 19일')를 보이고 화살표를 숨긴다                               |
| 기준 시각   | '10월 19일 12:00 기준'을 유지한다. asOf는 합성 자료의 계산 기준이며 수집·갱신 시각이 아니므로(data-model) '마지막 업데이트'라고 쓰지 않는다    |
| 계좌별 진입 | 처음 열면 이번 달(D2). 거래가 없을 때만 '최근 1년 보기'를 둔다                                                                                 |
| 정렬        | 거래 날짜 최신순. 날짜별로 묶어 머리에 'M월 D일 요일'(아래 진한 선). 머리에 합계를 두지 않는다                                                 |
| 같은 날     | 같은 날짜 기준의 occurredAt이 있으면 늦은 시각 먼저. 없으면 transactionId로 고정 정렬(D3). 이 순서에 '실제 발생 순서'라는 의미를 붙이지 않는다 |

### 4-3. 행

```text
임*섭                                   +90,000원
입금 · 국민은행 입출금 통장 ····0001
정기구독                                 −10,000원
카드 사용 · 현대 신용카드 ····0001 · 할부 2/6
```

| 요소      | 규칙                                                                                                                                                           |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 첫 줄     | 거래명 15/600(한 줄, 말줄임)·상태 라벨 … 금액 15/700(줄바꿈 없음). 부호는 direction(in '+', out '−' U+2212, D9)                                                |
| 둘째 줄   | 13 textSecondary '거래 종류 · 거래 수단'. 거래 수단은 '은행명 계좌 표시명 ····끝 4자리' 또는 '카드 상품명 ····끝 4자리'. 할부가 있으면 뒤에 '· 할부 n/m'(T10)  |
| 크기·선   | 위아래 16dp, 최소 76dp, 아래 연한 선(dividerRow)                                                                                                               |
| 예외 상태 | 정상(posted·반영됨)은 아무것도 붙이지 않는다. 예외만 상태 라벨(D4·D6, §4-7). 거래명 자리가 56dp보다 좁아지면(좁은 화면·큰 글씨) 라벨을 거래명 아래 줄로 내린다 |
| 누르기    | 모든 행이 버튼이며 02-5 상세 시트를 연다. 펼침 아이콘은 두지 않는다(D7 변경)                                                                                   |

거래 종류 라벨(D8 정정):

| 기록                                       | 라벨          | 금액 부호 |
| ------------------------------------------ | ------------- | --------- |
| 계좌 내역, 분류 `internal_transfer`        | 내 계좌 이체  | 방향대로  |
| 계좌 내역, 분류 `card_payment`             | 카드대금 납부 | −         |
| 계좌 내역, 그 밖(분류 income·expense·null) | 입금 / 출금   | + / −     |
| card_purchase                              | 카드 사용     | −         |
| card_refund                                | 카드 환불     | +         |
| card_cancellation                          | 승인 취소(D9) | D9        |

- '내 계좌 이체'·'카드대금 납부'는 데이터가 준 분류(`payseTransactionType`)일 때만 붙인다. 앱이 이름·금액으로 추정하지 않는다.
- '수입'·'지출'은 라벨로 쓰지 않는다. 소비·수입으로 단정하는 표현이라 합계 규칙이 정해진 뒤 다룬다.
- 거래 종류 선택의 다섯 값(계좌 입금·계좌 출금·카드 사용·카드 환불·승인 취소)은 recordKind와 direction만으로 나눈다. 카드 사용을 계좌 출금으로 세지 않는다.

### 4-4. 선택 시트(기간·거래 수단·거래 종류)

조건마다 따로 시트를 연다. 모든 시트는 흰 바탕·위 모서리 16·바깥 50% 덮개, 화면 높이의 85%까지. 제목·닫기와 하단 '적용'은 고정하고 내용만 스크롤한다. 초기화 버튼은 없다.

| 거래 수단 선택(통합만)   | 체크 다중 선택. 전체 · 계좌 전체 · (금융사별 계좌) · 카드 전체 · (카드). 묶음 항목은 일부 선택 상태를 보인다. 0개면 '적용'을 끄고 '거래 수단을 1개 이상 골라 주세요'                           | 전체    |

- 거래 수단 시트 구분(2026-10-30 실기기 확인 뒤 혜연 결정): '전체' / 계좌 묶음 / 카드 묶음 세 덩어리. '계좌 전체'·'카드 전체' 위에만 진한 선, 묶음 안 행 사이 선 없음, 은행 이름과 각 계좌·카드는 체크 상자 폭만큼 들여 쓰고 같은 은행 계좌는 한 묶음(금융사 순서).
- 거래 수단 칩 문구: '전체 거래 수단' / 하나면 그 이름 / '계좌 전체'·'카드 전체' / '계좌 2개' / '계좌 1개 · 카드 1개'.
- 거래 수단을 바꿔 기존 거래 종류가 맞지 않게 되면 거래 종류를 '전체'로 되돌린다. 기간은 어떤 조건을 바꿔도 유지한다.
- 닫기·바깥 누르기·뒤로 가기는 이전 조건을 유지한다. '적용'은 조건을 반영하고 목록 맨 위로 간다. 달 이동 화살표는 바로 적용한다.
- 앱이 받은 1년 거래를 앱에서 거른다(GET /transactions에는 필터가 없다).

### 4-6b. 아래로 당겨 새로고침 (2026-10-30 혜연 승인, 시안 R-1~R-6)

거래 내역·계좌 관리·계좌별 거래 화면에 둔다.

| 단계      | 표시                                                                                                                                                                                         |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 당기는 중 | 문구 없이 원형 선이 당긴 만큼 차오른다(textSecondary). 기준 거리(96dp)에 닿으면 다 찬 진한 원으로 조금 커지고 가벼운 진동. 손을 뗄 때만 요청하고, 놓기 전에 기준 아래로 되돌리면 취소        |
| 진행 중   | 기존 목록·잔액을 그대로 두고 맨 위 84dp 자리(목록 위쪽 바깥)에서 같은 원이 회전. 요청이 1초 넘게 걸릴 때만 '새로고침 중…' 페이드인(끝난 요청의 문구는 나타나지 않음). 로딩 틀·최소 대기 없음 |
| 성공      | 응답으로 즉시 다시 그리고 같은 자리에서 체크와 '최신 정보를 확인했어요.'로 180ms 전환, 1.5초 뒤 250ms에 접힘. 표시 중에도 화면을 쓸 수 있다. 하단 알림 없음. 기준 시각은 응답 asOf           |
| 실패      | 아무것도 반영하지 않고 표시를 접은 뒤 이전 정보·기준 시각 유지. 위에 띠 '새로고침하지 못했어요' / '이전 정보를 보여드려요.' + '다시 시도'. 성공 표시 없음                                    |

아이콘 자리(24dp)와 한 줄 문구 자리를 늘 확보해 문구 유무로 아이콘·목록 위치가 바뀌지 않는다. 스크린리더에는 시작 '새로고침 중', 완료 '최신 정보를 확인했어요', 실패 '새로고침하지 못했어요. 이전 정보를 보여드려요.'를 알린다.

반영 기준(버전 일관성):

- 새로고침 한 번은 기존 계약의 Snapshot 조회와 그 dataVersion의 거래 페이지 전체 수집이다. 둘 다 같은 dataVersion으로 끝났을 때만 성공이며 응답 Snapshot과 거래 목록을 홈·계좌 관리·거래 내역(열려 있는 계좌별 화면 포함)에 한 번에 반영한다. 거래 내역은 받아 둔 거래를 그대로 쓰고 다시 받지 않는다.
- Snapshot 조회 실패·형식 오류·거래 페이지 실패·409 재시작 초과는 실패다. 새 잔액과 이전 거래가 섞이지 않도록 Snapshot도 반영하지 않는다.
- coverage partial·failed는 응답 성공이라 반영하고 일부 조회 띠로 안내한다. 세션 무효·연결 상태 변경은 기존 앱 진입 처리를 따른다.
- 진행 중 다시 당기거나 '다시 시도'를 눌러도 새 요청을 보내지 않는다. 진행 중 계좌 이름·계산 포함 계좌 저장이 성공하면 저장 응답을 쓰고 늦게 온 새로고침 응답은 버린다. 진행 중이던 홈 새로고침 응답도 버린다.
- 기간·거래 수단·거래 종류·입출금 조건, 안쪽 탭, 계좌별 화면의 계좌, 스크롤은 유지한다.
- 홈의 다시 불러오기 버튼(로딩 틀·최소 3초, 2026-10-28 결정)은 바꾸지 않는다.
