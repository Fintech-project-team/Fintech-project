## 1. 바꾸는 이유

기존 구조는 02-3 계좌 목록에서 계좌 하나를 골라야 02-4 거래 내역으로 갔다. 여러 계좌·카드의 거래를 보려면 하나씩 열어야 한다. 계좌별 조회는 유지하고, 연결된 계좌와 카드의 거래를 날짜별로 함께 보는 통합 거래 내역을 더한다.

2026-10-28 범위 정정: 앞선 설계의 '계좌 입출금만, 카드 승인 제외'는 철회한다. 그 제한은 소비 중복 집계를 피하려던 것인데, **거래를 한 목록에 보이는 것과 금액을 합산하는 것은 별개**다. 카드 거래도 목록에 넣고, 합계·통계만 보류한다.

## 2. 화면 구조와 이동 흐름

하단 탭의 `계좌`는 그대로 두고, 안쪽을 두 탭으로 나눈다.

```text
29-2 이후(최종)
하단 탭 '계좌' ─┬─ [거래 내역] (앱 시작 시 기본) = 02-4 공통 거래 화면, 계좌·카드 통합 조회
               └─ [계좌 관리]                  = 02-3
                     ├─ 계좌 행 누름  → 02-4 공통 거래 화면(그 계좌로 고정, 새 화면으로 열림)
                     │                   ← 뒤로: 계좌 관리, 이전 스크롤 위치 그대로
                     ├─ 연필 버튼     → 02-6 계좌 이름 바꾸기(시트)
                     └─ 계산에 포함할 계좌 바꾸기 → 01-1 재사용 → 저장 후 계좌 관리로 복귀
02-4 거래 행 누름 → 추가 정보가 있는 행만 그 자리에서 02-5 상세 펼침(화면 이동 없음)

29-1 단독 배포
하단 탭 '계좌' → 02-3 계좌 관리(안쪽 탭 없음, 거래 내역 탭 노출 안 함)
                 계좌 행은 누를 수 없음(이동할 화면이 아직 없음). 연필·계산에 포함할 계좌 바꾸기만 동작
```

- 기억(D1): 앱을 쓰는 동안 다른 하단 탭에 다녀와도 마지막 안쪽 탭·필터·스크롤을 그대로 둔다. 앱을 새로 시작하면 `거래 내역`(기본 필터)으로 시작한다.
- 계좌 관리에서 연 계좌별 거래 화면은 안쪽 탭 위에 쌓인 화면이다. 필터는 `거래 내역` 탭 필터와 따로 관리한다. 뒤로 갔다가 같은 계좌를 다시 열면 이번 달로 새로 시작한다.
- 카드별 진입 화면은 이번 범위에 없다. 특정 카드의 거래는 거래 내역의 거래 수단 필터로 본다.
- 하단 탭 이름 `계좌`가 카드 거래까지 담게 된다. 이름을 바꿀지는 **결정 필요 D10**.

## 3. 조회 범위와 계산 범위

`쓸 수 있는 돈 계산에 포함한 계좌`(계좌 선택, included)와 `거래를 조회하는 계좌·카드`는 별개다.

| 규칙                         | 내용                                                                                                                                                              | 근거                                                             |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 조회 대상                    | 연결된 금융사의 모든 계좌와 카드. 계산에서 제외한 계좌도 포함                                                                                                     | 응답 모델 §2.3 "연결된 미선택 계좌·카드의 연간 거래는 계속 제공" |
| 계산 선택 변경               | 거래 조회 범위를 바꾸지 않는다. 단, 계좌 선택 저장은 자료 버전을 올리므로 받아 둔 거래 페이지를 버리고 새 Snapshot부터 다시 받는다                                | 응답 모델 §2.3·표 '연결/계좌 선택 저장 후 새 버전'               |
| 계좌 종류                    | 입출금·예금·적금 모두 같은 경로로 거래가 온다(더미 확인: 신한 자유 적금 13건, 국민 정기예금 12건). 종류별 조회 제한은 계약에 없다                                 | data-model Coverage, demo-ready                                  |
| 조회 지원하지 않는 계좌·카드 | 계약상 대상별 상태는 coverage `complete/partial/failed/unconnected`뿐이며 '거래 조회 미지원' 상태는 없다. 상품 종류만 보고 미지원으로 판단하지 않는다(T5, A 답변) | data-model Coverage.status                                       |
| 합계·통계                    | 목록에는 계좌 내역과 카드 기록을 모두 보이되, 일별·월별 입출금 합계와 소비 합계는 두지 않는다(중복 집계 규칙 확정 전)                                             | 2026-10-28 범위 정정                                             |

거래 수단 필터에는 '계산에서 제외' 표시를 붙이지 않는다. 조회 가능 여부와 혼동되기 때문이다. 계산 포함 여부는 계좌 관리에서만 보인다.

## 4. 02-4 공통 거래 화면

통합 조회(`거래 내역` 탭)와 계좌별 조회(계좌 관리에서 진입)가 같은 화면을 쓴다.

| 구분        | 통합 조회                                            | 계좌별 조회                                                       |
| ----------- | ---------------------------------------------------- | ----------------------------------------------------------------- |
| 머리        | 안쪽 탭 `거래 내역`                                  | 뒤로 가기 + 계좌 표시명(제목) + '은행명 원래 상품명 ····끝 4자리' |
| 보이는 기록 | 연결된 계좌의 계좌 내역 + 연결된 카드의 카드 기록    | 그 계좌의 계좌 내역만                                             |
| 거래 수단   | 전체 / 계좌 전체 / 카드 전체 / 계좌 하나 / 카드 하나 | **그 계좌로 고정**. 조건 줄·필터 시트에 거래 수단 선택이 없다     |
| 입금·출금   | 거래 수단이 계좌 전체 또는 계좌 하나일 때만(D11)     | 있음                                                              |
| 행 둘째 줄  | 거래 종류 · 거래 수단(§4-3)                          | 거래 종류만(거래 수단은 머리에 있으므로, D5)                      |
| 초기화      | 이번 달 · 전체 거래 수단                             | 이번 달 · 그 계좌 · 입출금 전체                                   |

### 4-1. 보여 줄 거래

- 계좌 내역: recordKind `account_entry`. 날짜는 bookingDate.
- 카드 기록: recordKind `card_purchase`(카드 사용)·`card_refund`(환불)·`card_cancellation`(승인 취소). 날짜는 각각 purchaseDate·refundDate·cancellationDate(승인 취소일, 2026-10-29 #132 계약 확정. 날짜만 확인되면 occurredAt은 null).
- 기간: 응답의 최근 달력 1년(coverage requestedStart~requestedEnd). 그 밖 거래(relatedTransactions)는 목록에 넣지 않는다.
- 같은 소비가 두 번 보일 수 있다: 카드 사용과 나중의 카드대금 납부, 체크카드 사용과 연결 계좌 출금(더미: 10/12 국민 체크카드 40,000원 사용과 하나은행 '국민카드 체크결제' 40,000원 출금). **둘 다 보이고, 연결 근거 없이 하나로 묶지 않으며, 합치지 않는다.** 자동으로 묶으려면 transactionRelations 같은 연결 근거가 필요하다(후속).
- 카드 사용을 계좌 출금으로 부르지 않는다. 거래 종류 라벨로 구분한다(§4-3).
- 거래명은 원천 merchantName 그대로다. 앱이 금액·날짜로 추정해 이름이나 종류를 붙이지 않는다. A가 거래처명(merchantName)과 적요(description)를 나눈 더미로 다시 구성한다(T8).
- 원천 사실은 바꾸지 않는다: 금액·날짜·거래명 수정 없음.

### 4-2. 조건 줄과 기본 조회

```text
[‹]  2026년 10월 (19일까지) ▾  [›]   ← 기간: 좌우 화살표로 이전·다음 달, 가운데를 누르면 필터 시트(기간 부분)
[전체 거래 수단 ▾]  [입출금 전체 ▾]   ← 누른 조건 부분을 펼친 상태로 같은 필터 시트를 연다
                                        입출금 칩은 거래 수단이 계좌일 때만 보인다(D11)
10월 19일 12:00 기준 · 연결된 계좌와 카드의 거래 내역이에요
```

| 항목        | 규칙                                                                                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 기본 조회   | 이번 달 · 전체 거래 수단. '이번 달'은 스냅샷 기준 시각(asOf)이 속한 달의 1일~기준일(기기 시계가 아님)                                                                          |
| 달 이동     | '›'는 기준 시각이 속한 달에서 비활성. '‹'는 조회 범위 첫 달까지. 첫 달과 이번 달은 실제 범위를 함께 보인다(예: '2025년 10월 (20일부터)', '2026년 10월 (19일까지)')             |
| 기준 시각   | '10월 19일 12:00 기준'을 유지한다. asOf는 합성 자료의 계산 기준이며 수집·갱신 시각이 아니므로(data-model) '마지막 업데이트'라고 쓰지 않는다                                    |
| 계좌별 진입 | 처음 열면 이번 달(D2). 거래가 없을 때만 '최근 1년 보기'를 둔다                                                                                                                 |
| 정렬        | 거래 날짜 최신순. 날짜별로 묶어 머리에 'M월 D일 요일'. 머리에 합계를 두지 않는다                                                                                               |
| 같은 날     | occurredAt이 있으면 늦은 시각 먼저. 없으면 transactionId로 고정 정렬(D3). 이 순서에 '실제 발생 순서'라는 의미를 붙이지 않는다. 더미는 계좌 내역·카드 기록 모두 시각이 null이다 |

### 4-3. 행

```text
임*섭                                   +90,000원
입금 · 국민은행 입출금 통장 ····0001
정기구독                                 −10,000원
카드 사용 · 현대 신용카드 ····0001 · 할부 2/6
```

| 요소      | 규칙                                                                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 첫 줄     | 거래처명 15/600 … 금액 15/700. 늘어난 돈 '+', 나간 돈·사용 '−'(U+2212). 금액이 우선이며 잘리지 않음                                                           |
| 둘째 줄   | 13 textSecondary '거래 종류 · 거래 수단'. 거래 수단은 '은행명 계좌 표시명 ····끝 4자리' 또는 '카드 상품명 ····끝 4자리'. 할부가 있으면 뒤에 '· 할부 n/m'(T10) |
| 예외 상태 | 정상(posted·반영됨)은 아무것도 붙이지 않는다. 예외만 상태 라벨(D4·D6)                                                                                         |
| 펼침 표시 | 상세에 보일 추가 정보가 있는 행만 오른쪽 끝에 펼침 아이콘(▾ 16, 열리면 ▴)을 두고 행 전체(최소 64dp)를 버튼으로 한다. 정보가 없는 행은 누를 수 없다(D7)        |
| 펼침 개수 | 한 번에 하나                                                                                                                                                  |

거래 종류 라벨(D8 정정):

| 기록                                       | 라벨          | 금액 부호 |
| ------------------------------------------ | ------------- | --------- |
| 계좌 내역, 분류 `internal_transfer`        | 내 계좌 이체  | 방향대로  |
| 계좌 내역, 분류 `card_payment`             | 카드대금 납부 | −         |
| 계좌 내역, 그 밖(분류 income·expense·null) | 입금 / 출금   | + / −     |
| card_purchase                              | 카드 사용     | −         |
| card_refund                                | 카드 환불     | +         |
| card_cancellation                          | 승인 취소(D9) | D9        |

- '내 계좌 이체'·'카드대금 납부'는 데이터가 준 분류(`payseTransactionType`)일 때만 붙인다. 앱이 이름·금액으로 추정하지 않는다.
- '수입'·'지출'은 라벨로 쓰지 않는다. 소비·수입으로 단정하는 표현이라 합계 규칙이 정해진 뒤 다룬다.
- 같은 목록에 펼침 아이콘이 하나라도 있으면 모든 행의 금액 오른쪽에 아이콘 칸을 비워 금액 끝선을 맞춘다.

### 4-4. 필터 시트 '거래 내역 필터'

| 필터      | 선택지                                                                                                                                | 기본    |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| 기간      | 이번 달 · 최근 3개월 · 최근 1년 · 월 선택(조회 범위 안의 달)                                                                          | 이번 달 |
| 거래 수단 | 통합 조회만. 전체 / 계좌 전체 / 카드 전체 + 계좌 목록(금융사별 '표시명 ····끝 4자리') + 카드 목록('상품명 ····끝 4자리'). 하나만 고름 | 전체    |
| 입출금    | 거래 수단이 계좌 전체 또는 계좌 하나일 때만 보인다. 전체 · 입금 · 출금. 거래 수단을 카드 쪽으로 바꾸면 '전체'로 돌아간다              | 전체    |

- 시트는 화면 높이의 85%까지. 제목·하단 버튼(초기화 / 적용)은 고정하고 내용만 스크롤한다.
- 닫기·바깥 누르기·뒤로 가기는 변경을 취소한다. '적용'은 조건을 반영하고 목록 맨 위로 간다. '초기화'는 시트 안 선택만 기본값으로 되돌리며 '적용'을 눌러야 반영된다.
- 앱이 받은 1년 거래를 앱에서 거른다(GET /transactions에는 필터가 없다).

### 4-5. 02-5 상세 펼침

목록에 이미 있는 정보(거래 수단·날짜·거래 종류)는 반복하지 않는다. 응답에 실제로 있는 추가 정보만 보인다.

| 줄            | 보이는 조건                                                                                                                                                                                                                                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 거래 시각     | occurredAt이 있을 때 'HH:mm'                                                                                                                                                                                                                                                                                                               |
| 적요          | description이 거래처명과 다를 때(A의 새 더미에서 거래 종류 표기, T8)                                                                                                                                                                                                                                                                       |
| 할부          | 카드 기록에 installmentCurrent/Total이 있을 때 'n/m회차'. n은 이번 청구서에 청구되는 회차다. 할부 결제는 구매 기록 1건이므로 받은 자료의 값을 그대로 보이며, 자료가 갱신되면 같은 기록의 n이 바뀐다(T10)                                                                                                                                   |
| 원거래        | 환불·취소의 originalTransactionId가 가리키는 원거래를 실제로 확보했을 때만 원래 사용일·금액. null이거나 미확보면 이 줄을 생략한다(T9)                                                                                                                                                                                                      |
| 처리 상태     | status가 posted가 아닐 때(D4)                                                                                                                                                                                                                                                                                                              |
| 잔액 반영     | 계좌 내역의 reflectionReason이 reflected가 아닐 때(D6)                                                                                                                                                                                                                                                                                     |
| 포함된 청구   | 카드 사용이 청구서(Statement.includedTransactionRefs)에 포함돼 있을 때 청구서마다 'M/D 결제 예정 청구' 한 줄(결제 예정일 순) + 03-3으로 이동(29-3 이후). 할부는 같은 결제를 여러 청구서가 참조하므로 여러 줄이 될 수 있다(T10). 청구서별 배분 금액·회차 번호는 계약에 없어 보이지 않는다. 청구 금액·포함 건수·결제 계좌는 여기 두지 않는다 |
| 카드대금 연결 | 출금 거래 → 정산 → 예정 지출 → 청구서 → 카드 관계가 확인될 때만 결제한 카드. 여러 카드 청구에 연결되면 모두 보이고 하나를 고르지 않는다(T6)                                                                                                                                                                                                |

- 거래 후 잔액은 계약의 Transaction 필드에 없다. 만들지 않는다.
- 청구 전체 정보(결제 예정일·결제 계좌·이번 청구 금액·포함 건수)는 03-3 카드 결제 상세에 둔다(C2).
- v0.7의 '분류 바꾸기'·'예정 지출로 등록' 버튼은 이번 범위에 넣지 않는다.

### 4-6. 페이지 수집

GET /transactions는 transactionId 오름차순 100건 페이지라, 일부 페이지만 받으면 최근 거래가 다 왔는지도, 어느 계좌·카드가 빠졌는지도 알 수 없다.

| 상황                                  | 동작                                                                                                                                                            |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 최초 조회                             | 모든 페이지를 같은 dataVersion으로 다 받고 병합·정렬이 끝난 뒤 목록을 보인다. 그동안 로딩 틀                                                                    |
| 중간 페이지 실패(이전 결과 없음)      | 받은 페이지를 목록으로 보이지 않는다. '거래 내역을 불러오지 못했어요' + '다시 시도'                                                                             |
| 중간 페이지 실패(이전 완료 결과 있음) | 이전에 끝까지 받은 목록을 유지하고 그 목록의 기준 시각을 보인다. 띠 '새 거래 내역을 불러오지 못했어요' / '10월 19일 12:00 기준 내역을 보여드려요' + '다시 시도' |
| 수집 중 자료 버전 변경(409)           | 받은 페이지를 버리고 새 Snapshot부터 다시 수집한다. 사용자에게는 로딩만 이어서 보인다                                                                           |
| 계좌·카드별 조회 실패(coverage)       | 페이지 수집은 끝났지만 coverage가 partial·failed인 계좌·카드가 있으면, 현재 조건에 그 대상이 포함될 때만 누락 안내(§4-7)                                        |

### 4-7. 상태와 문구

| 상태               | 표시                                                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 불러오는 중        | 조건 줄은 그대로, 기준 줄 자리에 '거래 내역을 불러오는 중이에요', 목록 자리에 실제 행 크기의 로딩 틀                                                 |
| 이번 달 거래 없음  | 조건이 기본값이고 0건: '이번 달 거래 내역이 없어요' + '최근 1년 보기'                                                                                |
| 조건 결과 없음     | 조건을 바꿨고 0건: '선택한 조건의 거래 내역이 없어요' / '기간이나 필터를 바꿔보세요.' + '필터 초기화'                                                |
| 조회 실패          | §4-6. '거래 내역을 불러오지 못했어요' + '다시 시도'. 거래 없음으로 표시하지 않는다                                                                   |
| 일부 누락(partial) | 받은 거래는 보이고 위에 안내 띠 '일부 거래 내역을 불러오지 못했어요' / '국민은행 입출금 통장 · 0001의 내역이 일부 누락됐을 수 있어요.' + '다시 시도' |
| 전체 누락(failed)  | 같은 띠, 설명 '현대 신용카드 · 0001의 거래 내역을 표시하지 못했어요.' 그 계좌만 고정한 계좌별 조회는 목록 대신 이 안내와 '다시 시도'                 |

실패·누락 안내는 모두 홈 새로고침 실패 띠 규격(회색 전폭·빨간 안내 아이콘·제목+설명·밑줄 '다시 시도')을 쓴다. 누락 띠는 현재 조건에 영향을 주는 계좌·카드만 이름으로 보인다. 여러 곳이면 '국민은행 입출금 통장 · 0001 외 1곳'으로 줄인다. `unconnected`는 연결 해제된 대상이라 목록·필터에 나오지 않는다.
