# 가입·로그인·잠금

- 상위 기준: [v0.6 화면 규칙](../../../docs/v0.6-screen-rules.md), [화면 규칙 보완](screen-rules-update.md), [앱 구조](../../../docs/app-architecture.md) §3·§4, [v0.6 API 계약](../../api/docs/v0.6/api-contract.md) §2, [디자인 값](../../../docs/design.md) §5

## 1. 완료 범위와 한계

| 구분      | 내용                                                                                                                                |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 구현      | 00-1, 10-1~10-5, 11-1, 09-11 문구, 09-12(키패드 숨김·점 아래 문구), 10분 무입력·백그라운드 복귀 잠금, 5회 오류 복구 흐름, 진입 판단 |
| 서버      | **실제 서버 연동 아님.** `FakeAuthRepository`(메모리)가 계약의 발급·재확인·종료·거절·시도 제한을 흉내 낸다                          |
| 기기 저장 | **메모리 가짜 구현.** 앱을 다시 시작하면 세션·PIN·약관 동의가 사라진다. 재시작 후 유지는 완료 범위가 아니다                         |
| 복구      | 화면 흐름과 재확인 호출(새 세션 없음)까지. 실제 본인인증을 통한 복구 완료는 범위 밖이다                                             |
| 범위 밖   | 로그아웃·탈퇴(03-6), 금융사 연결(#26, 지금은 `ConnectionPlaceholderScreen` 자리), 실제 보안 저장소, 금액 계산                       |

## 2. 구조

```text
lib/app/payse_app.dart        진입 판단(세션·PIN 유무) + 잠금 덮개 + 수명 감시
lib/app/local_lock_controller.dart   10분 무입력 판정(주입 시계, 백그라운드 복귀 재계산)
lib/app/main_entry.dart       PIN 뒤 스냅샷 재조회 → 미연결이면 연결 자리, 연결됨이면 하단 탭
lib/data/auth/                공통 입력 규칙(auth_input_rules) · AuthRepository 계약 · FakeAuthRepository · 저장 인터페이스(Session/LocalPin/Consent) · 메모리 구현
lib/features/auth/            화면(auth_screens) · 흐름 Navigator(auth_flows) · ViewModel · 공통 입력 규칙 export와 PIN 규칙(auth_validation)
lib/shared/design/            PayseTextField · SelectionCheck(Row/ListRow) · PayseChip · PayseToggle · PinPad · CodeTimerField
```

진입: 세션 없음 → 00-1 / 세션 있음·PIN 없음 → 10-4 / 둘 다 있음 → 11-1 → 스냅샷 재조회. 첫 가입 직후에는 연결 자리부터 보인다.

PIN 실패: 횟수는 `LocalPinStore`가 PIN과 함께 보관한다. 지금은 저장소 인스턴스가 살아 있는 동안 유지된다(화면을 다시 만들거나 잠금이 다시 걸려도 이어짐). 앱 프로세스를 다시 시작한 뒤에도 유지하는 것은 실제 기기 저장소 구현 때 제공한다. 5회면 맞는 PIN도 비교하지 않고 거절하며(09-12) 본인 확인 복구 후 새 PIN을 설정할 때만 0이 된다. 시간으로 풀리지 않으며 서버 인증 시도 제한(이름+전화번호 5회/5분)과 별개다.

잠금: 마지막 터치 후 10분이면 열린 화면 위에 11-1을 덮는다. 아래 화면은 `Offstage`로 그리지 않고 접근성 트리에서도 빠지며, 상태(ViewModel·입력)는 폐기하지 않아 해제 후 그대로 돌아간다.

## 2-1. 실패·경합 처리

| 상황                                            | 처리                                                                                                                                  |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 자격 불일치·사용 중 계정 (401 AUTH_REJECTED)    | 09-11 "인증번호가 맞지 않아요", 입력 유지                                                                                             |
| 토큰 무효 (401 SESSION_INVALID, 운영 종료·소실) | 복구 중이면 기기 세션·PIN 삭제 → 10-2 신규 로그인(09-13). 10-4 뒤로 가기에서는 종료 성공과 같게 본다                                  |
| 형식 오류 (422)                                 | 입력 유지, 시도 제한에 세지 않음                                                                                                      |
| 시도 제한 (429)                                 | 5번째 실패부터. Retry-After가 지나기 전에는 입력을 고쳐도 다시 보내지 않고 남은 시간을 표시                                           |
| 발급 요청 중 이탈                               | 10-3 뒤로 가기(버튼·시스템)를 막음. 그래도 화면이 사라진 뒤 성공하면 저장하지 않고 세션을 종료                                        |
| 화면을 떠난 뒤 받은 세션의 종료 실패            | 정리 담당(`PendingSessionCleanup`)이 토큰을 보관하고 다음 발급 요청 전에 다시 종료한다. 성공·이미 무효가 확인돼야 버린다(메모리 보관) |
| 무효 세션 전환 시 열려 있던 화면                | 루트 화면 위에 쌓인 화면(개발용 더미 화면 등)을 모두 닫고 10-2로 간다                                                                 |
| 10-4 처음부터 다시 하기 중 PIN 입력             | 세션 종료가 끝날 때까지 PIN 입력·완료를 받지 않음. 정리는 화면이 사라져도 끝까지 수행                                                 |

## 3. 실제 구현으로 바꿀 지점

| 지금                                    | 바꿀 때                                                                          |
| --------------------------------------- | -------------------------------------------------------------------------------- |
| `FakeAuthRepository`                    | `AuthRepository`를 구현한 HTTP 클라이언트. 화면·ViewModel 변경 없음              |
| `MemorySessionStore`                    | 기기 보안 저장소 구현. 토큰 원문은 여기에만 둔다                                 |
| `MemoryLocalPinStore`                   | 보관 방식(해시·기기 보안 저장소)을 정해 구현. 인터페이스는 PIN을 돌려주지 않는다 |
| `MemoryConsentStore`                    | 기기 저장 구현                                                                   |
| `lib/app/dev/dev_demo_accounts.dart`    | 서버 코드 확정 후 개발용 임시 코드 교체 또는 삭제                                |
| 릴리스 기본 `UnavailableAuthRepository` | 실제 서버 구현으로 교체                                                          |

작성·답변 당시 기록은 [이름 이행 이력](../../api/docs/history/2026-10-22-identity-transition.md)에 보존한다.

## 4. 이름 계약과 구현 경계

인증 입력은 [공통 HTTP 계약](../../../docs/api-contract.md#인증-입력과-단일-이름)을 따른다. 화면과 FakeAuthRepository는 `lib/data/auth/auth_input_rules.dart`의 순수 함수를 공유한다. `auth_validation.dart`의 공개 함수 경로와 PIN 규칙은 유지한다. 이름은 앞뒤 U+0020만 제거한 한글 완성형·영문 2~20자이며 내부 공백은 허용하지 않는다. 전화번호는 U+0020·U+002D만 제거하고 코드는 정규화하지 않는 ASCII 6자리다.

- 개발 계정 이름은 서버 시드의 `name`인 데모알파·데모베타·데모감마다. UUID·전화번호도 같은 시드와 대조한다. 금융 권한과 소유권에는 이름 대신 userId를 사용한다.
- 개발용 코드 `000001`~`000003`은 릴리스에서 제외되는 Fake 전용 값이다. 서버 `codeVerifier`는 비활성 상태이며 실제 코드 검증·HTTP 인증 구현 완료가 아니다.
- 로그인 201의 `name`은 API 계약에 정의돼 있다. 현재 `DemoSession` 모델의 name 수신·호칭 저장은 아직 미구현이며 별도 연결 작업이다. 이름을 표시할 구체 화면 위치는 B가 정한다.
- 인증 입력의 메모리 수명은 [제품 기준](../../../docs/product-baseline.md)을 따른다. 형식 오류 422와 자격 불일치 401을 구분하며, 실제 서버·보안 저장소는 위 구현 경계에 따라 교체한다.
- 기관 일부 제외 연결은 원본 더미를 보존하고 FakeRepository가 계정 원본을 부분 연결 상태로 변환한다. [응답 계약](../../../docs/api-response-models.md)을 따른다.

## 5. 정해지지 않아 임시로 둔 문구

약관 항목 이름·본문, 00-1 소개 문장, 429 대기 안내, 연결 오류 안내, PIN 화면 제목, 11-1 오류 횟수 안내는 확정 문구가 아니다. 앱 화면에 테스트용 앱·합성 정보라는 안내는 넣지 않는다(로드맵 v8).
