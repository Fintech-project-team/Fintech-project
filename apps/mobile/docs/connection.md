- 상위 기준: [API 계약](../../../docs/api-contract.md) §3·§5·§6, [응답 모델](../../../docs/api-response-models.md) §1.1·§2, [v0.6 화면 규칙](../../../docs/v0.6-screen-rules.md), [화면 규칙 보완](screen-rules-update.md), [앱 구조](../../../docs/app-architecture.md) §3·§7
- 화면(12-1~12-3, 01-1, 01-2)은 디자인 승인 뒤 2단계(UI 명세)에서 만든다. 지금 연결 자리의 '홈으로 가기'는 임시 화면 이동이며 연결·계좌 선택·버전을 바꾸지 않는다.

## 1. 완료 범위와 한계

| 구분      | 내용                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------- |
| 구현      | 조회·연결·계좌 선택 계약, 사용자별 가짜 서버(장부), 연결 전·부분 연결 투영, 세션 단위 저장소, 첫 화면 연결    |
| 서버      | **실제 서버 연동·서버 영속화 아님.** `FakeFinancialServer`(메모리)가 계약의 검증·replay·버전·투영을 흉내 낸다 |
| 유지 범위 | 사용자별 장부는 앱 프로세스 동안 유지(재로그인 복원). 앱 재시작 후 유지는 범위 밖                             |
| 범위 밖   | 연결·계좌 선택 화면, 실패 연출, 01-2 확인 화면, 거래 페이지 조회(`GET /transactions`), 금액 계산              |

## 2. 구조

```text
lib/data/connection/financial_api.dart          UserFinancialRepository 계약 · W(쓰기 공통 필드) · S(영수증·replayed·snapshot) · 결과 타입
lib/data/connection/snapshot_projector.dart     원본(PAYSE-DRAFT-2) + 사용자 상태 → HTTP Snapshot(PAYSE-API-0.6-2) 순수 변환
lib/data/connection/fake_financial_server.dart  FakeFinancialServer(앱 수명 장부) · FakeUserFinancialRepository(세션 단위)
lib/data/connection/user_snapshot_repository.dart  Snapshot JSON → FinancialSnapshot 어댑터(첫 화면용)
lib/app/dev/dev_user_fixtures.dart              개발 데모 계정 userId → 불변 원본(alpha-ready·beta-ready·gamma-month-end)
```

| 수명    | 대상                                                                                                                                                                                                                                               | 처리                                                          |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 앱 수명 | `FakeFinancialServer`의 사용자별 장부(연결·선택·버전·영수증)                                                                                                                                                                                       | 재로그인해도 유지. 사용자마다 분리                            |
| 세션    | 토큰으로 사용자를 정함(요청 본문 userId 없음). 원본 대기 뒤 확정 전에 세션을 다시 확인해 도중 종료된 요청은 401·저장 없음. 앱의 세션 저장소는 닫히면 진행 중 응답도 버림. 무효 토큰=401 → 첫 화면이 기기 세션·PIN을 지우고 10-2 신규 로그인(09-13) |
| 불변    | 원본 fixture                                                                                                                                                                                                                                       | 깊이 복사 후 투영. 원본을 바꾸거나 로그인마다 초기화하지 않음 |

## 3. 계약 대응

| 규칙           | 구현                                                                                                                                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 연결 전 응답   | 세 계정 모두 같은 변환으로 10개 키만. 계정별 연결 전 파일 없음(alpha-unconnected는 첫 화면 개발용 선택에만)                                                                                                                            |
| 부분 연결      | 투영 전에 원본 검증(모든 자원 행의 userId 일치, 필수 부모·참조 존재). 등록 표(§2.1, `access_restriction.dart` 공유)로 검사한 제한 표식, 거래 공개 기준(§2.2), 종속 참조(§2.3). 공개 행의 sourceRef·evidenceRef에 숨긴 ID가 있으면 오류 |
| 미확보 참조    | 원거래·referenceResolutions가 원본(transactions·relatedTransactions)에 없으면 사용자·기관 근거가 없으므로 연결 범위와 상관없이 서비스 불가(503). 전체 연결을 근거로 쓰지 않음                                                          |
| 연결 쓰기      | 빈 목록·중복·은행 0곳(카드사만)=422, 제공되지 않은 기관=403                                                                                                                                                                            |
| 계좌 선택      | 빈 목록·중복=422, 연결 권한 밖·다른 사용자·없는 계좌=403. 전체 집합 교체                                                                                                                                                               |
| 최초 계좌 선택 | 연결만으로 included를 확정하지 않음(전부 false). 선택 저장 성공으로만 확정. 미선택 연결 계좌의 거래도 공개                                                                                                                             |
| 재시도         | 같은 키·같은 요청(메서드·경로·W 버전·본문, 배열 순서 포함)은 버전 검사 전 replay(기존 영수증 식별 + 최신 스냅샷), 다른 요청은 409. 응답 영수증의 changedRefs는 현재 조회 권한으로 거름(내부 영수증은 보존)                             |
| 409            | 자료 버전(STALE_DATA)과 규칙 버전(RULE_VERSION_MISMATCH)을 다른 타입으로 구분                                                                                                                                                          |
| 원본 형식 오류 | 머리(dataVersion·ruleVersion·institutions) 형식 확인, 그 밖의 형식 오류도 예외 대신 서비스 불가. 첫 화면은 예외로 끝난 조회도 다시 시도 화면                                                                                           |
| 원자성         | 상태·영수증·버전을 성공 때 한 번에 바꿈. 실패한 키에는 영수증이 남지 않음. 같은 버전 동시 저장은 하나만 성공                                                                                                                           |
| 세션           | 토큰으로 사용자를 정함(요청 본문 userId 없음). 무효 토큰=401 → 첫 화면이 기기 세션·PIN을 지우고 10-2 신규 로그인(09-13)                                                                                                                |

## 4. 실제 구현으로 바꿀 지점

| 지금                          | 바꿀 때                                                                              |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| `FakeUserFinancialRepository` | `UserFinancialRepository`를 구현한 HTTP 클라이언트(Bearer). 화면·ViewModel 변경 없음 |
| `FakeFinancialServer`         | 실제 서버로 대체(앱에서 제거). 투영 규칙 테스트는 서버·Fake 공통 검증 벡터로 유지    |
| `dev_user_fixtures.dart`      | 서버가 userId로 원본을 정하므로 앱에서는 제거                                        |

## 5. 미확정·후속

- beta·gamma 금융사 구성 변경은 A와 논의 중이다. 원본이 바뀌면 원본 일치 테스트가 알려 주며 사람이 에셋을 동기화한다. 기관 개수를 코드에 고정하지 않는다.
- 화면 모델(`FinancialSnapshot`)은 제한 표식(`accessRestrictions`)을 보존하고 지원 형식(PAYSE-DRAFT-2·PAYSE-API-0.6-2)·등록 조합을 검사한다. 카드 출금 계좌·거래 계좌/카드는 '연결 제한으로 생략'과 '원래 미확인 null'을 구분한다(표식 없는 생략은 형식 오류). 연결 정보가 필요하다는 화면 문구는 UI 단계에서 정한다.
- `GET /transactions` 페이지 조회와 cursor 폐기는 화면이 페이지를 쓰기 시작할 때 구현한다(지금 Snapshot은 page.nextCursor=null).
- 개발용 스냅샷 덮어쓰기는 세션·계정이 바뀌면(신규 로그인·세션 무효) 지운다.
