| 외부 | 정상 공통 더미의 직전 급여 회차 근거          | #96(A) 대기. 반영 전 홈은 '입금 정보 부족' |

## 2. 구조

```text
MainEntry(진입 조회 성공 Snapshot) → AppShell → computeHomeCalculation(한 번)
                                                  ├ calculationInputsFromSnapshot (lib/data)
                                                  └ payse_calculation.calculateCurrentAmount
                                       → HomeScreen (같은 HomeCalculation을 이후 02-2·01-3도 사용)
```

- 계산은 앱 셸이 스냅샷이 바뀔 때만 한 번 수행한다. 화면은 금액을 계산하지 않고 결과만 표시한다. 홈 입력이 없어 inputRevision은 0이다.
- 다시 불러오기는 진입 조회를 다시 실행한다. 조회 중에는 기존 로딩 화면을 보이고 이전 금액을 최신처럼 보이지 않는다.

## 3. 어댑터 규칙

| 상황                                                                                               | 처리                                                                                      |
| -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 급여 근거 키 생략(접근 제한)                                                                       | 근거 null → `receiptEvidenceUnavailable`                                                  |
| partial·confirmed 근거 거래가 posted 계좌 입금·reflected가 아님                                    | 계약 위반(데이터 오류)                                                                    |
| 근거·정산 거래 또는 그 계좌의 sourceVersion·asOf가 스냅샷과 다름(키 없음 포함)                     | 계약 위반. 같은 JSON에 있다는 것만으로 같은 원천으로 보지 않음                            |
| 근거·정산 거래가 응답에 없음: 다음 페이지(`page.nextCursor`) 또는 referenceResolutions unavailable | 미수신·미확보 → 근거 null / 정산 null(정보 부족). resolved인데 없거나 그 밖이면 계약 위반 |
| 미수신·숨김과 확정 위반이 함께 있음                                                                | 받은 근거를 끝까지 검사해 순서와 관계없이 계약 위반                                       |
| 정산: 거래별 유효 배분 합계 > 출금액, 계좌 불일치, 출금 아님, 근거 없음                            | 계약 위반. 무효화된 연결은 합계·정산에서 제외                                             |
| 의무·보호액·배정의 미연결 계좌 숨김(targetKind account·reserve·obligation)                         | 공개 목록 그대로(포함 계좌에 영향 없음)                                                   |
| 의무 숨김 targetKind plan·planRevision                                                             | 의무 null → 예정 지출 정보 부족                                                           |
| 정산 숨김 targetKind transaction, 포함 계좌 활성 의무의 정산 제한                                  | 정산 null → 예정 지출 정보 부족                                                           |
| 공개 배정·정산이 응답에 없는 보호액·의무를 가리킴                                                  | 형식 오류(부모 숨김이면 자식도 숨기는 계약)                                               |

계약 위반과 계산 패키지의 `CalculationInputException`은 데이터 오류, 그 밖의 예외는 Flutter 오류로 보고하고 '예상하지 못한 오류'로 보인다. 정보 부족으로 바꾸지 않는다.

## 4. 02-1 홈 표시

- 시안 `home-c-final.html`(C Minimal Spacious)과 기존 위젯(MoonGlyph·AmountHero·LedgerRow·StatusNotice)을 쓴다. PAYSE 텍스트, 주기 줄(월급까지 N일 + 구간 날짜), 금액 라벨, U, 기준 시각, 장부(계좌 잔액 B / 모아둘 돈 R−O / 예정 지출 E).
- 장부 금액은 같은 결과의 B·(R−O)·E이며 합이 U=B−E−(R−O)다. O가 있으면 모아둘 돈 아래에 '설정 R 중 예정 지출에 들어 있는 O는 모아둘 돈에서 다시 빼지 않아요'를 적는다.
- 주기 줄: 정상 '월급까지 N일', 09-14 '오늘은 월급일 · 입금 확인 전', 09-15 '월급 입금 확인 전', 정보 부족 '월급 정보 확인 필요'. 입금 대기면 반영 대기 의무 건수·금액을 경고로 알린다.
- 음수는 −·오류 색과 부족 문장, 정보 부족은 '계산할 수 없어요'와 사유 문장. 값이 없는 장부 행은 그리지 않는다.
- 1단계에서 넣지 않은 것: '계산 내역 보기' 버튼과 장부 화살표(2단계 02-2), 모아둘 돈 건수(계산 결과에 보호액 건수가 없음), 금액 구성 막대·달 연동(디자인 미정). 상태 문구는 확정 문구가 아니며 화면 확인 때 조정한다.

## 5. 검증

- 공통 더미 연결: alpha-ready·beta-ready·gamma-month-end는 근거 부재로 정보 부족(B만 계산), salary-wait는 입금 대기, salary-confirmed는 정상 계산. 실제 진입 흐름(가짜 서버 → 홈)에서도 alpha가 정보 부족으로 보인다. **정상 공통 더미의 금액 표시는 #96 반영 뒤 다시 검증해야 하며 지금은 미검증이다.**
- 테스트 전용 입력(테스트 안에서 공통 더미 사본에 근거를 넣음): 정상 U 1,300,000, 음수, 급여 근거·정산 계약 위반, 숨김·빈 목록·고아 참조, 부분 연결 투영.
- 화면: 정상·음수·정보 부족·09-14·09-15·데이터 오류·예상하지 못한 오류, 320dp·글자 2배.
- 미확인: 에뮬레이터·실기기 화면 확인.
