## 2. 구조

```text
MainEntry(진입 조회 성공 Snapshot) → AppShell → computeHomeCalculation(한 번)
                                                  ├ calculationInputsFromSnapshot (lib/data)
                                                  └ payse_calculation.calculateCurrentAmount
                                       → HomeScreen (같은 HomeCalculation을 이후 02-2·01-3도 사용)
```

- 계산은 앱 셸이 스냅샷이 바뀔 때만 한 번 수행한다. 화면은 금액을 계산하지 않고 결과만 표시한다. 홈 입력이 없어 inputRevision은 0이다.
- 다시 불러오기는 진입 조회를 다시 실행한다. 조회 중에는 기존 로딩 화면을 보이고 이전 금액을 최신처럼 보이지 않는다.

## 4. 02-1 홈 표시

- 확정 시안(v78)과 [디자인](../../../docs/design.md) §6 '홈 전용 장부'를 따른다. 구조: PAYSE·다시 불러오기 아이콘 → 주기 줄(달 39dp) → 금액 라벨 '다음 월급일까지 / 쓸 수 있는 돈' → U 또는 '계산할 수 없어요' → 기준 시각 → 상태별 안내 → 장부 → 화면 아래에 고정한 '계산 내역 보기' 띠 버튼.
- 장부는 홈 전용 행(금액 앞 −, '원' 끝선, 24dp 화살표 칸)으로 같은 결과의 B·(R−O)·E를 보이며 합이 U=B−E−(R−O)다. 보조 줄은 보호액 건수('N건')와 '월급일 전 N건'(계산 결과의 건수). 모아둘 돈·예정 지출 행을 누르면 02-2가 열린다. 값을 모르면 '계산 불가'이고 화살표가 없다.
- 상태: 정상(구성 바, 범례 없음) / 음수(바 없음, 경고 띠) / 입금 대기(바 → 경고 띠 → 장부, 예정 지출 '입금 확인 대기') / 정보 부족(사유 문장, 지난 회차 근거 부재면 '월급 입금 확인하기'). 색 칩은 구성 바가 보일 때만 붙는다.
- 기기 기록 상태(`HomeSalaryRecord`)는 앱 셸이 01-3 기록으로 판단해 넘긴다(§6). '미입금 · 내가 확인한 상태'는 4단계에서 만들지 않는다.
  - `reportedNotDeposited`: 지난 회차 근거 부재일 때만 상태 라벨 'M/D 예정 월급 미입금 · 내가 확인한 상태'와 안내를 보인다. 계산이 가능해지면 표시하지 않는다.
  - `resolvedAfterFirstCalc`: U가 계산됐을 때만 장부 아래 '처음 계산 과정을 단계별로 보기'를 보인다.
- '월급 입금 확인하기'와 '처음 계산 과정을 단계별로 보기'는 3단계에서 비활성(접근성 상태 포함)이며 4단계에서 연결한다.

### 홈 달·새로고침 (2026-10-26 확정 규칙 구현)

- 큰 달: 계산 결과의 `cycleProgress`로 밝은 면 10% + 82% × 진행률(`moonLitFraction`), 입금 대기 100%, 주기 없음 점선 원(`cycle_moon.dart`). 화면은 날짜·입금 여부를 판단하지 않는다.
- 정보 부족(지난 회차 근거 부재) 문구: '월급 입금 확인 필요' / '아직 계산할 수 없어요' / 'M/D에 예정된 월급의 입금 여부를 확인할 정보가 없어요.' 사용자가 미입금을 확인한 상태는 기존 문구 유지.
- 새로고침(`HomeRefresh`): 앱 진입 화면(`main_entry.dart`)이 홈에 들어온 뒤의 새로고침을 진입 조회와 따로 관리한다. 새로고침 중에는 탭을 유지하고 홈을 로딩 틀로 보이며 중복 요청을 막는다. 성공하면 새 스냅샷, 실패하면 이전 스냅샷을 그대로 두고 안내 띠를 보인다. 표시할 계산 결과가 없던 홈(데이터 오류 뒤)의 실패는 홈 틀 + '아직 계산할 수 없어요'. 세션 무효·다른 진입 화면이면 그 결과를 따른다. 앱에 처음 들어올 때의 로딩·조회 실패는 금융사 연결 진입 화면 그대로다.

## 5. 02-2 계산 내역

- 홈 장부 아래 '계산 내역 보기'로 같은 HomeCalculationReady(스냅샷+결과)를 연다. 데이터 오류·예상하지 못한 오류 홈에는 진입점이 없다.
- 금액·건수·합계는 `calculateCurrentAmount`의 결과(B·E·R·O·R−O·U, accountLines, reserveLines, deductionKrw, placementTotals, settledTotal, 의무별 근거)만 쓴다. 화면은 부호 비교·비율·날짜 위치만 다루고 금액을 더하거나 빼지 않는다. 이름·계좌 끝자리·정산 거래 날짜는 같은 스냅샷 원천 값이다.
- 구성 바 7가지 상태와 영수증 규격은 [디자인](../../../docs/design.md) §6을 따른다.
- 출금 완료 내역은 포함 계좌 의무의 유효 정산액이다(제외 계좌 출금은 B에 없으므로 넣지 않음). 정산 거래 날짜는 출금일, 없으면 반영일을 쓴다.
- 정보 부족이면 첫 사유 문장을 안내 띠로 보이고 모르는 값은 '계산 불가'다. 지금 있는 사유 문장은 1단계 홈과 같다.
- 테스트 전용 예시: 제외 계좌 보험료(공통 더미에 없음, #100 미반영)는 테스트 안 사본에만 넣는다.

## 6. 01-3 첫 계산과 기록 (4단계, 2026-10-27)

- 01-3(`first_calc_screen.dart`)은 1/4 계좌 잔액 → 2/4 모아둘 돈 → 3/4 예정 지출 → 4/4 결과를 홈과 같은 `HomeCalculationReady`로 보인다. 2/4·3/4는 저장된 모아둘 돈·예정 지출만 하위 항목으로 보이고 배정·부분 출금 관계는 설명하지 않는다. 입금 대기는 3/4에서 보류 지출을 차감 행 밖 '입금 확인 후 반영할 지출' 묶음에 − 없이 보이고 지금 빼지 않는다고 알리며, 4/4에 입금 대기 띠를 둔다. 반영 금액이 0원이면 0원이라고 알리고, 보호액이 모두 예정 지출에 배정돼 0원이면 그 이유를 따로 보인다. 1/4~3/4의 '홈으로 가기'는 건너뜀, 시스템 뒤로 가기는 이전 단계다.
- 01-2 '쓸 수 있는 돈 계산하기' → 앱 진입 화면이 01-2의 스냅샷을 그대로 홈 셸에 넘기고, 셸이 같은 스냅샷 계산으로 01-3을 띄운다. 01-2를 건너뛰는 진입(재로그인 등)도 기록이 없고 U가 계산되면 01-3을 띄우며, U가 없으면 기록 없이 홈으로 간다. 데이터 오류·예상하지 못한 오류·로딩 중에는 띄우지도 기록하지도 않는다.
- 기록(`lib/data/first_calc_record_store.dart`, 사용자별 한 값): 설명 완료(4/4 '홈으로') / 설명 건너뜀(중간 '홈으로 가기') / 보완 미룸(01-2 '나중에 확인하고 홈으로 가기'). 완료·건너뜀이면 01-3을 다시 자동으로 띄우지 않는다. 보완 미룸이면 이후 U가 계산될 때 홈 장부 아래 '처음 계산 과정을 단계별로 보기'를 보이고, 누르면 지금 스냅샷 결과로 01-3을 보이며 기록을 바꾸지 않는다.
- 움직임(2026-10-28): 단계가 바뀌면 머리 문구만 왼쪽으로 밀려 사라지고 새 문구가 서서히 나타난다. 영수증은 유지하며 현재 행만 진하게 하위 내역을 펼치고, 지난 행은 흐리게 접는다. 단계 표시 막대는 길이·색이 움직이며 바뀐다. 4/4 구성 바는 구간이 차례로 늘어나고 범례가 차례로 나타난다. 01-2 → 01-3, 4/4 → 시작 화면, 시작 화면 → 홈은 앱 기본 화면 이동과 같은 전환(25% 오른쪽에서 들어오며 나타남)이다. 4/4 '다음' 뒤 시작 화면(달이 차오른 뒤 금융 아이콘이 달 위쪽 호를 따라 튀어나와 제자리 둘레를 천천히 도는 움직임, '이제 홈에서 확인하세요', '홈으로 가기')에서 설명 완료를 기록하고, 홈으로 넘어간다. 홈에서 다시 보기는 시작 화면 없이 4/4 '홈으로'로 끝난다. 움직임 줄이기 설정이면 최종 모습을 바로 보인다.
- 메모리 구현이다. 화면 이동 후 복귀와 앱을 종료하지 않은 로그아웃→같은 사용자 재로그인에서는 유지하고 사용자별로 나눈다. 앱 프로세스 종료·재실행 뒤 복원은 범위 밖(영구 저장은 후속).
- '월급 입금 확인하기'는 비활성이다. 4b-2(입금 내역에서 월급 거래 고르기·입금 확인 저장)는 2026-10-28 혜연·성현 결정로 적용하지 않는다. 입금 근거는 서버 스냅샷만 쓰며, 다시 적용할 때는 입금 근거 저장 계약을 먼저 정한다. 버튼은 비활성으로 두고, 나중에 입금 내역에서 고르는 별도 화면(지금 시안의 SalaryPick*·SalaryConfirm*와 다른 화면, 미정)에 연결한다.

## 6-1. 02-1a 홈 코치마크 (5단계, 2026-10-28)

- 기본 숨김(2026-10-28 혜연 결정): 앱(`PayseApp`)은 코치마크 기록 저장소를 넘기지 않으며, 저장소가 없으면 코치마크를 띄우지 않는다. 다시 켤 때는 `PayseApp`의 `coachmarkRecords`에 저장소를 넘긴다. 아래 규칙은 켰을 때의 동작이다.
- `home_coachmark.dart`가 홈 셸 위에 덮개(charcoal 50%)를 씌우고 ① 쓸 수 있는 돈(금액 라벨~구성 바, 정보 부족이면 '월급 입금 확인하기'까지) → ② '계산 내역 보기' → ③ 하단 계획 탭을 차례로 강조한다. 강조 위치는 홈이 붙인 위치 키(`HomeCoachTargets`)와 탭바 위치로 잰다. 안내 면은 '계산 내역 보기' 위 8dp에 아래 끝을 고정하고, ①에만 강조 영역과 안내 면을 잇는 노란 수직선을 긋는다.
- ① 문구는 U가 있으면 '지금 쓸 수 있는 돈이에요', 지난 회차 입금 근거가 없으면 '월급 입금을 확인하면 계산해요', 그 밖의 이유로 U가 없으면 '필요한 정보가 확인되면 계산해요'(시안 없음, 혜연 확인 사항)다.
- 보이는 때: 01-3이 끝난 뒤 홈 탭이 계산 결과(정상·음수·입금 대기·정보 부족)로 그려지고 코치마크 기록이 없을 때 한 번. 01-3이 떠 있는 동안, 새로고침 중, 데이터 오류·예상하지 못한 오류에서는 보이지 않는다.
- 기록(`lib/data/coachmark_record_store.dart`, 사용자별 한 값): 완료('시작하기') / 건너뜀('건너뛰기'·뒤로 가기). 기록이 있으면 다시 띄우지 않는다. 01-3 기록과 같은 메모리 구현이라 같은 실행 안 재로그인에서 유지하고 앱 재실행 뒤에는 사라진다(영구 저장은 후속).
- 떠 있는 동안 아래 홈은 누를 수 없고 화면 읽기 프로그램에는 안내 면만 '사용법 n / 3' 대화 상자로 읽힌다. '내 정보 › 사용법' 다시 보기는 내 정보 화면과 함께 후속으로 넣는다.
