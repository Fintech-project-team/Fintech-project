# 화면 규칙 보완 — 프로토타입 점검 반영

- 작성: 2026-10-19 · B(hyeyeonso) · 범위 v0.6~v0.9 화면
- 근거: v0.6~v0.9 클릭 프로토타입 점검 결과. 상위 기준은 [v0.6 화면 규칙](../../../docs/v0.6-screen-rules.md), [계산 규칙](../../../docs/calculation-rules.md), [데이터 계약](../../../docs/data-contracts.md), [데이터 명세 초안](../../api/docs/data-model-draft.md)이다.
- 이 문서는 기존 공통 MD를 수정하지 않고 화면 동작만 보완한다([개발 문서 기준](../../../docs/development-notes.md)). 기존 기준과 다른 항목은 "기존과 다름"에 적었다.
- 구분: **결정**은 B가 화면 범위에서 정한 사항, **A 확인**은 데이터·API·저장 계약에 영향이 있어 A 확인 전에는 구현을 확정하지 않는 사항이다.
- 계산 경계는 그대로다. 금액은 Flutter 로컬 계산, 서버는 소유권·버전·참조 검증과 저장만 한다.

## API 인계 보완 — 사용자 채택 5·6·7 (2026-10-21)

로그인 201에서 단일 `name`을 받으며 화면 호칭의 위치는 B가 정한다. name은 권한/캐시 키가 아니며 userId로 계정을 격리한다. 이름은 데모알파·데모베타·데모감마, DB 공백 금지는 인증 식별값에만 적용한다. 계좌 nickname·원천 표시값의 규칙은 유지한다.

alpha·beta·gamma 연결 전 응답은 각 계정 원본에 공통 변환을 적용한다. 계정별 연결 전 파일 복제를 요구하지 않는다. 재로그인 때 저장된 기관 연결·계좌 선택·설정을 초기화하지 않는다. FakeRepository는 실제 API와 같은 부분 연결·참조/제한 규칙을 적용하며 계좌·카드 배열만 필터링하지 않는다. [응답 모델](../../api/docs/v0.6/response-models.md)의 정확한 키·상태·예외·대표 예시와 [검증 항목](../../api/docs/v0.6/review-checklist.md)을 따른다. 기존 화면 결정의 변경이나 실제 연결 구현 완료를 뜻하지 않는다.
