## 2. 실행 방법

서버 주소와 요청 제한 시간(초)을 함께 넣는다. 제한 시간은 서버 계약에 정해진 값이 없어 빌드할 때 정한다. 주소가 있으면 빌드 모드와 무관하게 실제 서버·기기 보안 저장소를 쓰고, 가짜 서버·개발용 실패 연출·개발 설정 진입점을 쓰지 않는다. 주소 형식이 틀리면 앱이 시작하지 않는다.

```bash
flutter run --debug --dart-define=PAYSE_API_BASE_URL=<성현님이 줄 https 주소> --dart-define=PAYSE_API_TIMEOUT_SECONDS=<초>
```

주소를 빼면 기존과 같다(debug·profile은 가짜 서버, release는 서비스 불가).

### 토큰 보관과 path_provider_foundation 고정

토큰·PIN·동의는 `flutter_secure_storage` 11.2.0에 둔다(2026-11-02 혜연 결정으로 자체 네이티브 저장에서 복귀).

`pubspec.yaml`의 `dependency_overrides`로 `path_provider_foundation`을 **2.5.1**로 고정한다.

- 이유: `flutter_secure_storage_windows`→`path_provider`→`path_provider_foundation` 2.6.0은 `objective_c` 네이티브 빌드를 요구한다. 로컬 Mac은 Command Line Tools 26.6(ld-1267)인데 `xcrun --sdk macosx`가 SDK 27.0을 골라, 링커가 SDK 27.0의 `arm64e.x1` 항목을 읽지 못해 `flutter test`가 실패한다. 같은 링커·같은 오브젝트로 SDK 26.5를 지정하면 링크가 성공한다(2026-11-02 확인).
- 영향: 2.5.1은 iOS·macOS 구현이며 `objective_c`가 없다. Android 앱에는 쓰이지 않는다. 고정 상태에서 잠금 파일 의존성 해결·`flutter test` 전체·Android debug/release 빌드가 통과했다.
- 제거 조건: 로컬 개발 도구가 SDK 27.0을 읽는 링커로 맞춰지거나 SDK 선택이 26.x로 정리되어, 고정 없이 `flutter test`가 통과할 때. 또는 `path_provider_foundation`/`objective_c` 갱신으로 이 문제가 사라질 때. 제거 뒤 같은 세 검사를 다시 돌린다.

### mTLS 개발 환경 검증 (에뮬레이터, 폐기용 인증서)

로컬 `openssl s_server`(클라이언트 인증서 필수)에 에뮬레이터 앱이 Keystore 키로 접속했다. 폰 키의 공개키로만 인증서를 만들었고 개인키는 기기 밖으로 나오지 않았다.

| 경우                          | 결과                     |
| ----------------------------- | ------------------------ |
| 등록 인증서 + 맞는 서버 CA    | 200                      |
| 서버 CA가 다름                | TLS 실패(서버 검증 유지) |
| 키가 없는 별칭                | 보내기 전 실패           |
| 기기 키와 다른 인증서 연결    | 거절                     |
| 인증서 없이 접속(호스트 curl) | 서버가 거절              |

에뮬레이터는 보안 하드웨어가 없어 키 보관 위치(TEE/StrongBox)는 실기기에서 따로 확인해야 한다. Caddy 단일 지문 비교와 실제 서버 인증서 체인은 확인하지 않았다.

## 4. 결제일 미확보 표시안 (제안)

청구서 `dueDate=null`은 이미 읽힌다. 앱에 청구서 화면은 없으므로 **카드 대금이 보이는 기존 지출 정보 줄**에 표시한다. 서버가 그 청구에 대해 어떤 예정 지출을 주는지는 성현님 확인 전이라, 아래는 표시 위치·문구만 제안한다. 금액·포함 여부·계산 규칙은 바꾸지 않는다.

- 계좌·카드 탭 카드 목록과 계산 내역의 카드 대금 줄: 날짜 자리에 회색 `결제일 미확보`(날짜를 추정해 채우지 않음).
- 같은 줄의 보조 문장: `카드사에서 결제일을 아직 받지 못했어요.`
- 기간·시간축 화면에서는 점을 찍지 않고, 화면 규칙 05-3의 "결제일을 모르는 카드 소비" 안내를 그대로 쓴다.

## 5. 성현님 확인 결과 (2026-11-02)

- 테스트 서버 주소(성현님이 Git 밖으로 전달, 로컬 빌드 설정에만 둠) 뒤에 prefix 없이 계약 경로를 붙인다.
- CSR 주체 `CN=PAYSE-Test-Phone`, 추가 필수 항목 없음. 발급물은 `client.pem`·`chain.pem`·`enrollment.json`과 발급 인증서 DER 지문·유효기간·Caddy 등록 여부.
- 배포 서버는 금융 v4·급여 안내 API가 켜져 있고 서버 쪽 로그인·조회 검증은 끝났다. 폰 인증서 미등록이라 실기기 연결 검증은 남아 있다.
- 토큰 유실 시 계정명·발생 시각을 성현님께 알린다. 전용 운영자 복구 기능은 없으며, 앱에서 기존 세션을 우회하는 흐름을 넣지 않는다.
- 설치 DB에는 `dueDate=null` 청구가 없다. 실제 사례 확인은 별도 준비가 필요하며 앱은 null을 허용하고 날짜를 채우지 않는다.
- SQL 반영 테스트는 계좌 별칭 1개 변경과 `dataVersion` 증가를 같은 트랜잭션으로 하고, 복원도 버전을 올린다. 앱은 거래 페이지 409를 받으면 새 Snapshot부터 다시 받는다(구현됨).

## 7. 인증서 대기 중 앱 보완 (2026-11-02)

- 로그아웃 최소안: 내 정보 탭 '로그아웃' → 확인 창 "로그아웃 하시겠습니까?"(아니오/네). 서버 세션 종료가 확인(성공 또는 이미 무효)된 뒤에만 기기의 세션·PIN을 지우고 첫 화면으로 간다. 실패하면 토큰을 유지하고 연결·보안 연결 문구로 알린다. 약관 동의와 기기 인증서 키·인증서는 지우지 않는다. 디자인 시안을 거친 화면이 아니며 03-6 정식 화면은 후속이다.
- 인증 화면 저장 실패: PIN 만들기는 확인 단계에 머물고, PIN 확인은 잠금을 풀지 않으며, 약관 동의·처음부터 다시 하기는 화면에 머물며 알린다. 동의 기록을 읽지 못하면 약관을 다시 보인다.
- 저장 정보 읽기 실패 화면: 안내 "다시 시도해 주세요. 문제가 계속되면 이 기기의 로그인 정보를 지울 수 있어요."와 '다시 시도'·'이 기기의 로그인 정보 지우기'. 지우기 전 확인 창 "이 기기에 저장된 로그인 정보만 지워져요. 서버의 로그인 상태는 유지되어 다시 로그인이 제한될 수 있어요." 이때는 담당자(성현님)의 세션 종료가 필요할 수 있으며 계정명·발생 시각을 알린다. 지우는 범위는 기기의 세션·PIN뿐이며 서버 세션을 끝내거나 우회하지 않는다.
- 문구: 로그인 응답 유실·보안 연결(인증서) 문제·그 밖의 연결 실패를 나눠 보인다.
- `salary_notice_store.dart`와 테스트를 지웠다(앱·테스트 참조 없음). 이전 빌드가 남긴 기기의 `salary-notice-folded.*` 값은 읽지 않으며 앱 데이터에 남는다.
- 결제일 미확보: 지금 앱에는 청구서나 그 결제일을 보이는 화면이 없다(`Statement.dueDate`는 읽기만 함). 01-2 '카드 결제일'은 카드 일정 근거·계획 결제일을 쓰는 다른 필드다. 표시할 화면이 생길 때 "결제일 정보가 아직 확인되지 않았어요."를 쓰며, 지금은 화면을 추가하지 않았다.
