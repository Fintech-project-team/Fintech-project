# 금융 계산 규칙

상태: 정책 초안. 계산 구현 전에 팀 검토가 필요하다. 아래 예시를 확정 정책으로 사용하지 않는다.

## 반드시 지킬 것

- 같은 입력과 계산 버전은 같은 결과를 만든다. 기준 시각을 인자로 받는다.
- 금액은 원화 정수이고 JavaScript Number의 안전 범위를 검사한다.
- 배분은 계획이고 What-if는 가정이다. 원본 잔액과 실제 거래를 바꾸지 않는다.
- 같은 예정지출을 확보 금액과 함께 두 번 차감하지 않는다. 카드 이용과 청구를 구분한다.
- 내부 이체는 전체 자산의 소비가 아니다. 계좌별 부족에는 반영한다.
- AI 후보와 사용자 확정 지출을 구분한다. 결과에 근거·데이터 시각·계산 버전을 표시한다.

## 팀에서 결정할 정책

| 항목      | 초기 제안                                                     | 결정 전 처리                       |
| --------- | ------------------------------------------------------------- | ---------------------------------- |
| 기간      | 기준일부터 다음 급여 입금 직전, Asia/Seoul                    | 경계 테스트 사례만 준비            |
| 예정 수입 | 기간 내 확정 수입만 별도 반영, 다음 급여는 미리 포함하지 않음 | 후보 수입을 자동 합산하지 않음     |
| 보호 금액 | 예정지출·저축·비상금 제외, 생활비/용돈은 가용금액 안에서 분류 | 차감 규칙을 확정 표시하지 않음     |
| 가변 지출 | 사용자 확인 금액, 예측 오차 여유분 별도 표시                  | 임의 10%를 확정 규칙으로 넣지 않음 |
| 일별 예산 | 남은 일수·반올림·당일 포함 방식 결정 필요                     | 결정 후 구현                       |
| What-if   | 즉시 출금 1건, 카드/할부는 이후                               | 지원 결제 수단을 표시              |

## 논의용 예시

현금 1,800,000 - 예정지출 750,000 - 보호 저축 300,000 - 비상금 150,000 = 사용 여유 600,000원.
생활비 450,000·용돈 150,000으로 나눠도 사용 여유는 600,000원이다. 즉시 소비 200,000원을 가정하면 400,000원이다.
이는 추가 수입·지출과 계좌별 부족이 없다는 단순 사례다. 실제 계산은 기간 중 최저 잔액과 출금 계좌별 부족도 확인한다.

정책 결정 시 docs/decisions에 근거를 적고 이 문서 상태·calculationVersion·contracts·합성 데이터·기대값을 함께 갱신한다.
초안 예시로 테스트가 통과했다고 정책까지 확정됐다고 보고하지 않는다.

## 검사할 사례

정상, 음수 여유, 월급일 경계, 카드 이용/청구 중복, 내부 이체, 같은 obligationId 중복 확보, 계좌별 부족,
오래된 스냅샷, 소비 0/음수/상한 초과, What-if 실행 후 원본 유지.
