# 금융 계산 규칙: 확정과 논의 구분

현재 상태: **정책 초안 — 계산 구현 전 검토 필요**. 이 문서는 계산 사양을 몰래 확정하지 않기 위한 기준이다.

## 구현에서 지킬 불변 조건

- 동일 입력·동일 규칙 버전은 동일 결과. 기준 시각을 인자로 전달한다.
- 금액은 원화 정수이며 Number 안전 범위를 검사한다.
- 배분은 계획, What-if는 가정이다. 원본 잔액·실제 거래를 바꾸지 않는다.
- 동일 예정지출을 확보 금액과 이중 차감하지 않는다. 카드 이용과 청구를 구분한다.
- 내부 이체는 전체 자산의 소비가 아니다. 계좌별 현금 부족에는 반영한다.
- AI 후보와 사용자 확정 지출을 구분한다. 결과에 계산 근거·데이터 시각·버전을 남긴다.

## 금융 담당자가 결정할 정책

| 항목      | 초기 제안                                                   | 미결정 시                                 |
| --------- | ----------------------------------------------------------- | ----------------------------------------- |
| 기간      | 기준일부터 다음 급여 입금 직전, Asia/Seoul                  | 경계별 테스트 사례만 준비                 |
| 예정 수입 | 기간 내 확정 수입만 별도 반영, 다음 급여 미리 포함 금지     | 후보 수입을 가용금액에 자동 합산하지 않음 |
| 보호 금액 | 예정지출·저축·비상금 제외, 생활비/용돈은 가용금액 안의 분류 | 차감 정책을 UI에 확정 표시하지 않음       |
| 가변 지출 | 사용자 확인 금액, 예측 오차 여유분은 별도 표시              | 임의 10%를 확정 규칙으로 넣지 않음        |
| 일별 예산 | 남은 일수·반올림·당일 포함 규칙 필요                        | 정책 확정 후 구현                         |
| What-if   | 즉시 출금 1건, 카드/할부는 이후                             | 결제 수단 범위를 명시                     |

## 합의용 예시, 확정 사양 아님

현금 1,800,000 - 예정지출 750,000 - 보호 저축 300,000 - 비상금 150,000 = 사용 여유 600,000원.
생활비 450,000·용돈 150,000으로 나눠도 사용 여유는 600,000원이다. 즉시 소비 200,000원을 가정하면 400,000원이다.
단, 기간 내 추가 흐름이 없고 계좌별 부족도 없다는 단순 사례다. 실제 엔진은 기간 중 최저 잔액과 출금 계좌별 부족을 별도로 계산한다.

정책을 확정할 때 docs/decisions에 근거를 남기고 이 문서 상태·calculationVersion·contracts·fixture·검증 기대값을 함께 갱신한다. 초안 예시를 테스트 통과만으로 제품 정책이 확정됐다고 표현하지 않는다.

## 필수 경계 사례

정상, 음수 여유, 월급일 경계, 카드 이용/청구 중복, 내부 이체, 같은 obligationId의 중복 확보, 계좌별 부족, 과거 스냅샷, 소비 0/음수/상한 초과, What-if 원본 불변.
