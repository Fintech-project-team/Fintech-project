# 3인 운영과 에이전트 문서 정합성 수정

- 날짜: 2026-10-08
- 결정 근거: 사용자의 3인 기준 수정 요청, 기존 Markdown과의 충돌 확인·수정 및 이유 기록 요청.
- 합의 범위: 사용자가 승인한 운영 기준 정정이다. 다른 두 기여자의 별도 검토·승인까지 받았다는 의미는 아니다.
- 현재 팀: 개발 관리자 포함 3명. 활성 개인 브랜치는 sunghyun-dev, hyeyeon-dev, seonghwan-dev.
- 후속으로 남긴 것: 기능별 고정 담당 배정, 실제 팀원 세션 확인, GitHub 공유·권한·보호 규칙·비활성 브랜치 정리.

## 문제와 결정

공통 문서 11개에 4인 기준이 남아 있었고 Claude 스킬이 이를 참조했다. 계정·브랜치 정리 보류를 운영 문서 정정까지 보류하는 것으로 잘못 해석한 것이 원인이다. 현재 운영 문서는 3인으로 정정하고 원격 권한·브랜치 정리만 별도 후속 작업으로 남긴다.

사람은 3명이지만 integration·data·cashflow·allocation은 기능과 수정 경로를 나누는 네 역할이다. 3명이 겸임하며 작업마다 담당자를 별도로 기록한다. 사람 수에 맞추기 위해 기능 영역이나 하네스 정책을 삭제하지 않는다. 개인별 기능 배정은 합의되지 않았으므로 추측해 채우지 않는다.

기존 문서에는 매번 계획 확인·의존성 설치를 요구하는 표현과 유효한 결과 재사용 규칙이 함께 있었다. 같은 입력·설정·의존성·환경에 유효한 근거가 있으면 재사용하고, 바뀐 부분에 필요한 절차만 수행하도록 표현을 맞춘다. 필수 검사를 줄이거나 기존 실패 기록을 덮어쓰는 변경은 아니다.

형식 검사 PASS만으로 ‘3인 운영’ 같은 내용 요구를 확인할 수 없다. 문서·설정 작업은 바뀐 주제에 한해 최신 요구·완료 조건·연결 문서를 대조한다. 관련 없는 모든 문서를 매 작업마다 읽거나 재검사하는 절차는 추가하지 않는다.

## 수정하지 않은 부분과 근거

점검 대상은 현재 저장소의 Markdown 47개다. 이 기록 추가 후에는 48개다. 앱·패키지 README와 architecture/contracts/calculation-rules는 인원 고정이 아닌 기능 경계를 설명하며 네 작업 역할과 일치했다. CODE_SPEC, toolchain, demo, decisions 안내에도 이번 운영 기준과 충돌하는 내용은 확인되지 않았다. 관련 없는 제품 정책과 버전은 수정하지 않는다.

scripts/harness/policy.json의 네 역할은 그대로 유지한다. 제품 코드·의존성·CODEOWNERS·GitHub workflow와 권한도 변경하지 않는다. 과거 FC-DOCS-002 등 작업 명세와 PASS/FAIL/BLOCKED 기록은 당시 사실로 보존한다. 이번 수정으로 과거의 4인 기록이나 오류가 없었던 것처럼 만들지 않는다.

이전 작업의 allowedPaths를 넓히지 않고 사용자 승인으로 새 정정 작업 범위를 정한다. 설치 패키지는 공통 문서와 Claude 구성의 22개 파일이며 검증 사본의 임시 작업 명세는 포함하지 않는다. 검증·적용 상태는 작업 종료 기록에 별도로 남긴다.

## 발견 사건과 검증 기준

이번 정정의 원인이 된 운영 지침 위반 재작업은 1건이며, 이전 완료 판단에서 놓친 ‘3인 요구와 참조 문서 일치’ 확인은 필수 검사 누락 1종으로 기록한다. 같은 원인으로 여러 문서를 고쳤다는 이유로 파일 수만큼 집계하지 않는다. 수정을 완료해도 이 사건은 0으로 바꾸지 않는다.

확인할 근거는 활성 문서의 인원·역할·절차 일치, 공통 두 지침 동일성, 상대 링크, 설정·스킬 구조, 개인 파일 제외, 작업별 공통 검사, 범위 밖 파일과 이력 보존, ZIP 내용 일치다. 검증 사본의 PASS와 실제 저장소 적용, 팀원 세션, GitHub 반영은 각각 구분한다. 현재 하네스가 네 지표를 자동 수집하거나 의미 일치를 자동 판정한다는 뜻은 아니다.
