## 바뀐 요구와 적용

예전 문서는 3계좌·3개월 합성 거래 수집, 사용 여유/배분 화면, 분석 후보·What-if를 첫 구현에 포함했다. 새 기준은 급여 통장 1개, 수동 입력, 가입 후 첫 월급일 전, B−F−미지급 P다. [MVP 범위](../mvp-scope.md)를 기능·화면·용어의 기준으로 사용한다.

F01/F01-a/F02/F03/F04/F05/F08/F09/F10을 현재 Must로 연결한다. F07·F12는 Should이며 F07은 최종 제품의 Must라는 원문 의도를 유지한다. F06·F11은 표의 Could와 별도로 명시된 현재 MVP 제외를 우선 적용한다. F13 별도 기능 제외가 F03 비상금 입력까지 금지하지는 않는다. P01~P13은 과거 이력이다.

03-1 지급 처리는 입력 잔액 B−x와 예정 지출 제외를 함께 수행한다. 02-3은 현재 잔액 N으로 덮어쓰고 체크한 지급 항목을 제외한다. 체크 금액을 N에서 다시 빼지 않는 것은 원문의 두 설명을 일관되게 구현하기 위한 해석이며 별도 프로토타입 검증을 마쳤다는 뜻은 아니다. [계산 규칙](../calculation-rules.md)에 구분과 수치 예시를 적는다.

원문 '미확정' 표는 인터뷰·사용성 테스트로 검증할 기획 가설을 포함한다. 이번 개발 기준과 아직 명시되지 않은 날짜·지급 후 편집 정책을 구분한다. 개발자나 에이전트가 결과식을 임의로 바꾸지 않되, 미결정 정책은 관련 구현 전에 정한다.

MVP 다음 LLM은 입력·분류 후보를 만들고 사용자가 확인한 뒤 기존 F02 저장과 F09 계산으로 연결한다. 거래 수집을 먼저 구축하지 않아도 된다. 모델이 확정 입력·지급 상태·잔액·최종 계산값을 직접 변경하는 기능은 아니다.

## 기존 구조를 유지한 부분과 제안의 경계

Flutter, 서버의 확정 입력 저장, 기기의 읽기 캐시, 앱 측 순수 계산은 기존 설계 원칙을 유지했다. 새 MVP 원문이 서버 저장을 새로 요구한다고 해석한 것은 아니다. API의 잔액/지급 상태 변경과 앱의 순수 계산을 구분한다.

[contracts](../contracts.md)의 API 경로·필드·version/operationId 상세는 아직 구현 전 제안이다. 초기화 때 필요한 만큼 확정한다. 현재 TypeScript 골격을 Flutter에서 import하거나 계산을 두 언어로 중복 구현하지 않는다. 실제 Dart 경로·역할 정책·검사는 초기화 범위에서 함께 정한다.

3명과 4개 작업 역할, 동일한 30줄 공통 규칙, 최초 범위·사건 기록·필수 검사·유효 PASS 재사용을 유지했다. 역할명 allocation/recurring이 옛 배분/자동 탐지 기능을 다시 요구하지 않도록 설명만 맞췄다. 기존 실행 정책·JSON 작업 이력·공유 권한·설정·소스·잠금 파일은 수정하지 않았다.

## 보류·미검증

월급일 29~31일/휴일/당일, 첫 월급일 도달 안내, 지급 후 편집·삭제·취소, 입력 0원·상한·잔액 초과 저장 제한은 관련 구현 전에 결정한다. 음수 결과를 0으로 바꾸거나 F11 이월을 몰래 구현하지 않는다.

별도 MVP 검증 계획·와이어프레임 V3·링크된 프로토타입 화면은 확인하지 못했다. 이번 정합성은 제공된 본문·저장소 문서에 한정한다. Flutter 앱·API·LLM 구현, 실제 에이전트 세션, Android 시연, GitHub 반영, E2E와 디자인 시스템 구축을 완료로 표시하지 않는다.

과거 두 결정 기록은 당시 사실로 보존하고 이 문서와 현재 기준 문서가 최신 제품 범위를 설명한다. 앞선 3인 정정의 계약 재작업 1건·필수 내용 검사 누락 1종은 삭제하거나 이번 작업의 수치로 덮어쓰지 않는다.
