# 개발 문서 작성·공유 기준

2026-10-19 사용자 결정. 기존 MD는 수정하지 않고, 개발에 필요한 세부 명세를 담당 폴더의 새 MD로 작성한다.

| 문서 종류         | 위치                                    | 작성 범위                                                |
| ----------------- | --------------------------------------- | -------------------------------------------------------- |
| 공동 작업 기준    | `docs/`                                 | 두 개발자에게 영향을 주는 작성·공유 기준                 |
| 백엔드·DB·API     | `apps/api/docs/`                        | 해당 구현의 필드, 관계, 저장·검증 규칙                   |
| 더미 생성         | 실제 생성기를 두는 폴더의 `docs/`       | 자료 생성 규칙과 검증 사례. 별도 서버를 먼저 만들지 않음 |
| Flutter 공통 구현 | `apps/mobile/docs/`                     | Repository·모델 변환 등 모바일 공통 경계                 |
| Flutter 개별 기능 | 실제 담당 기능 폴더의 `docs/`           | 그 기능의 입력·출력·동작                                 |
| AI                | 구현 위치를 정한 뒤 해당 폴더의 `docs/` | 담당자·폴더가 미정인 상태에서 별도 영역을 확정하지 않음  |

- 문서는 **목적·필드/동작·다른 영역과 연결점·미확정·검증**만 짧게 쓴다. 실제 작업이 생긴 폴더에만 만들고 같은 명세를 여러 곳에 복사하지 않는다.
- 기존 공통 문서는 링크로 참조한다. 새 문서에서 달라진 내용은 사용자 결정인지 구현 제안인지 구분한다. 기존 기준을 조용히 덮어쓰지 않는다.
- 현재 두 사람 모두 공동 PM·개발자다. 사용자는 백엔드, 팀원은 Flutter·프론트 방향이며 AI 담당은 미정이다. 기존 문서의 고정 AI 담당 표기를 최종 배정으로 사용하지 않는다.
- 공유할 새 파일은 해당 개발 변경과 같은 PR에 포함하고, PR 설명에 **문서 경로·변경된 입력/출력·상대 담당자가 확인할 사항**을 적는다. 구현보다 먼저 작성한 초안도 공유 대상이다.
- 공동 계약에 영향을 주면 두 담당자가 확인한다. 상대 담당 코드·문서를 함께 수정할 권한이 자동으로 생기지는 않는다. 기존 Git·검사 절차는 유지한다.
- 문서의 저장소 등록과 팀원의 내용 확인은 별개다. GitHub 업로드 전 파일을 만들었다는 이유로 공유 완료라고 표시하지 않는다.

## 이번에 공유할 내용

[데이터 명세 초안](../apps/api/docs/data-model-draft.md)은 GitHub #17의 필드·타입·필수 여부·수정 권한·관계를 구체화한 검토본이다. DB DDL과 API 구현은 포함하지 않는다.

팀원 확인 범위는 ① 화면에 필요한 필드, ② 미상/누락 표시, ③ 원천 읽기 전용과 사용자 설정의 분리, ④ 월간 반복 계획·회차의 Dart 계산 입력, ⑤ 동일 자료 버전의 Repository 전달이다. 금액 계산은 Flutter, 서버는 데이터·설정 저장 검증이라는 경계를 유지한다.

최신 확정 사항: 반복 후보 승인 시 월간 계획을 저장하여 이후 회차에 적용한다. 없는 29·30·31일은 해당 월 말일을 **예정일**로 사용하고, 확인된 개별 일정이 있으면 우선한다. 예정 회차를 실제 거래·지급 완료로 바꾸지 않는다.

이번 검증에서 확정한 추가 사항: 월간 계획 수정은 개별 미지급 회차와 선택한 미래 월 이후 계획을 구분한다. 기존 회차·부분 정산 기록은 보존한다. 급여 입금 완료는 더미의 근거 거래+confirmed 사건으로 판단하는 **임시 기준**이며 프론트 구현에 필요할 때 재검토한다. 팀원은 이 두 상태의 화면 표현을 확인한다.
