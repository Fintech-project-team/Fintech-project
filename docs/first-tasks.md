# 현재 MVP의 첫 개발 작업

개발 관리자 포함 3명이 [MVP v0.3](mvp-scope.md)의 Must부터 개발하고, 이어서 예정 지출 입력·분류 LLM을 붙인다. 아래 이름은 작업 역할이며 고정 인원 배정은 아니다. 실제 담당은 [ownership](ownership.md)에 기록한다.

1. **integration 초기화:** Flutter SDK·앱·실제 Dart 계산 위치·JSON 계약·서버 저장 기반을 준비한다. lib/test 역할 경로와 Dart 검사를 함께 연결한다. 기존 Node 잠금 파일·현재 변경을 보존한다.
2. **관련 담당자 계약 확인:** 기본식과 03-1 지급 처리/02-3 잔액 보정 차이를 공유한다. 월급일·지급 후 편집 등 미결정 정책은 필요한 작업 전에 결정하고 합성 사례를 고정한다.
3. **첫 작은 흐름:** 월급일·급여 통장 잔액 입력 → 저장 → 모아둘 돈/예정 지출 입력 → 홈·계산 내역을 연결한다. 화면 개발은 같은 계약의 합성 데이터로 병행한다. mock-bank·자동 분석을 먼저 만들지 않는다.
4. **cashflow / data:** 예정 지출 CRUD·미리보기·이미 나갔어요·잔액 다시 입력을 같은 상태 변경 계약으로 구현한다. 중복 처리·저장 실패·409를 함께 확인한다.
5. **allocation / data:** 모아둘 돈 CRUD와 재계산을 연결한다. 독립 배분 탭·계좌별 부족·은행 링크·What-if는 추가하지 않는다.
6. **integration과 관련 담당자:** Must 화면 이동, 같은 version의 표시, 앱 재실행 후 확정 입력 조회, 계산·화면·저장 검사를 확인한다. Flutter 준비 전 Node 하네스 PASS로 기능 완료를 보고하지 않는다.
7. **MVP 다음 작업:** 사용자 문장으로 예정 지출 입력·분류 후보를 만들고, 확인한 후보만 기존 저장 경로에 넣는 LLM 보조를 구현한다. 제공자는 그때 하나를 선택하고 F07 거래 수집을 기다리지 않는다.

E2E 체계·디자인 시스템 구축은 별도 후속 요청까지 미룬다. 그 때문에 현재 기능의 필요한 검사를 빼지는 않는다. F07/F12 Should, F06/F11/F13 제외와 나머지 확장은 [확장 기준](EXTENSION_POINTS.md)에 따라 독립 작업으로 선택한다.

작업마다 실제 F 기능 ID·화면·담당자·허용 경로·완료 조건을 적는다. 새 Flutter 경로는 초기화 명세가 승인·반영되기 전까지 기존 역할에서 자동 허용되지 않는다. 같은 폴더에서 두 에이전트가 동시에 수정하지 않는다. Android 실제 기기 시연은 이후 제품 준비에 맞춰 확인한다.
