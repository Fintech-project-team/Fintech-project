# 코드 핵심 명세와 주석 규칙

## 필수 형식

클래스·메서드·생성자·이름 있는 함수(변수에 담은 화살표 함수 포함)에 바로 붙인 JSDoc으로 생성일·용도·매개변수·반환값을 짧게 기록한다. 익명 콜백마다 형식적 명세를 복사하지 않는다. 클래스는 생성자 인자와 반환 인스턴스를 설명하고, 생성자는 @returns에 인스턴스 초기화 의미를 적는다.

```ts
/**
 * @created 2026-09-28
 * @description 확정 지출을 반영한 가용금액을 계산한다.
 * @param input - 기준 스냅샷과 확정 계산 정책.
 * @returns 가용금액과 차감 근거. 원본을 변경하지 않는다.
 */
```

예시 날짜는 이 문서를 만든 날짜이며 모든 미래 코드에 복사할 상수가 아니다. 새 코드는 실제 작성 날짜, 기존 코드는 확인된 원래 날짜를 유지한다. 이력으로 확인 불가하면 @created unknown - 이력 확인 불가처럼 명시하고 리뷰 대상으로 남긴다. 수정 날짜·작성자·Issue 번호·완료 보고는 Git/Issue에 남긴다.

인자가 없으면 @param 없음, 반환이 없으면 @returns void - 부작용 설명으로 적는다. TypeScript 타입을 긴 문장으로 반복하지 말고 단위·경계·null·오류·부작용 등 사용에 필요한 의미를 적는다. 구조 분해 인자는 JSDoc의 논리 이름 input/options 등과 필드 설명을 명확히 연결한다. 오류가 중요한 API는 @throws를 추가한다.

## 금지와 보존

- 코드 그대로의 해설, 섹션 장식, AI에게 내리는 지시, 과거 작업 기록, 미사용 코드를 주석으로 보관하는 행위를 금지한다.
- 중요한 이유·도메인 제약·외부 API 한계·단위·실패 조건은 짧게 남긴다. 라이선스와 필요한 도구 지시문을 삭제하지 않는다.
- 주석만 바꾸는 작업에 함수 이름·로직·타입 변경을 섞지 않는다. 다른 담당자 코드의 주석을 일괄 보충하지 않는다.
- 명세는 보통 5~8줄로 충분하다. 긴 설명은 설계 문서로 옮기되 호출에 필요한 핵심을 링크만으로 대체하지 않는다.

## 검사 범위

코드 명세 검사는 TypeScript AST로 변경된 apps/packages의 JS·TS 파일에서 이름 있는 함수·클래스·메서드·생성자의 필수 태그와 인자 문서를 확인한다. 테스트 파일·생성 코드·타입 선언·익명 콜백은 자동 검사에서 제외한다. 테스트 helper 등도 사람이 읽을 수 있는 핵심 설명을 유지한다. 생성일의 진실성·주석이 코드 의미와 일치하는지·쓸데없는 설명인지는 리뷰가 확인한다. 검사 통과만으로 내용이 정확하다고 주장하지 않는다.
