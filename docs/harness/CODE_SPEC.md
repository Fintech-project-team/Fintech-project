# 코드 명세와 주석

## 작성 대상

- JS/TS 함수·메서드·클래스·생성자 바로 위에 JSDoc을 쓴다. 이름 있는 화살표 함수도 포함한다. Dart는 `///` 문서 주석으로 같은 생성일·용도·인자·반환 의미를 짧게 적고 JS 태그를 기계적으로 강제하지 않는다.
- 생성일·용도·매개변수·반환값을 짧게 설명한다. 익명 콜백마다 같은 형식을 복사하지 않는다.
- 클래스에는 생성자 인자와 반환 인스턴스를, 생성자의 @returns에는 초기화 결과를 설명한다.

## 예시

```ts
/**
 * @created 2026-09-29
 * @description 확정 지출을 반영해 가용금액을 계산한다.
 * @param input - 기준 시각, 계좌 잔액과 확정 지출.
 * @returns 원 단위 가용금액과 차감 근거. 원본은 바꾸지 않는다.
 */
```

- 예시 날짜를 그대로 복사하지 않는다. 새 코드는 실제 작성일, 기존 코드는 확인된 생성일을 쓴다.
- 생성일을 확인할 수 없으면 @created unknown - 이력 확인 불가로 표시한다. 날짜를 추측하지 않는다.
- 인자가 없으면 @param 없음, 반환이 없으면 @returns void - 부작용 설명을 쓴다.
- 타입을 반복하지 말고 단위·허용 범위·null·오류·부작용을 설명한다. 필요한 경우 @throws를 쓴다.
- 구조 분해 인자는 input/options 같은 이름과 필드 설명을 연결한다. 매개변수 이름만 나열하지 않는다.

## 남길 것과 뺄 것

- 필요한 이유·금융 규칙·API 제한·실패 조건을 짧게 남긴다. 보통 5~8줄이면 충분하다.
- 코드의 단순 해설·장식·AI 지시·작업 이력·미사용 코드를 주석으로 쌓지 않는다.
- 수정 이력·작성자·Issue 번호는 기본적으로 Git/Issue에 기록한다. API Java의 필수 수정일·목적 주석은 아래 예외를 따른다. 라이선스와 필요한 도구 지시문은 보존한다.
- 긴 설명은 문서로 옮기되 호출에 필요한 정보는 코드에 남긴다.
- 주석 수정에 로직·타입·함수 이름 변경을 섞지 않는다. 다른 담당자 코드를 일괄 수정하지 않는다.

## 자동 검사

검사기는 변경된 apps/packages의 JS·TS에서 필수 태그와 인자 설명을 확인한다.
테스트·생성 코드·타입 선언·익명 콜백은 자동 검사에서 제외한다. 테스트 보조 함수에도 필요한 설명은 남긴다.
날짜의 정확성, 설명과 코드의 일치, 불필요한 주석은 사람이 검토한다. 검사 통과만으로 설명이 정확하다고 보고하지 않는다.

Dart 문서 주석은 현재 Node 검사기의 자동 검사 대상이 아니다. Flutter 분석 통과만으로 위 설명 기준도 자동 검증됐다고 보고하지 않는다. 이번 변경 대상의 필요한 주석만 검토하며 전체 앱에 주석을 일괄 추가하지 않는다.

## API Java에만 적용하는 주석 규칙

2026-10-20 사용자 요청에 따라 API 개발은 [API 필수 규칙](../../apps/api/src/AGENTS.md)을 따른다. 공통 개발 원칙은 `apps/api/` 전체, Java 주석 의무·자동 검사는 `src/main/java`·`src/test/java`·`tools` 아래 직접 작성한 Java 코드에 적용한다.

- 모든 이름 있는 클래스·인터페이스·annotation·enum·record, 직접 작성한 메서드·명시적 생성자에 목적·생성일·주요 사용처를 기록한다. DTO/VO의 필드·타입·의미·검증 조건 변경과 기존 메서드의 구현·시그니처·계약 변경에는 수정일·목적을 남긴다.
- 작업 기준 커밋에 없는 선언을 완성하는 편집은 생성 작업이다. 기준 커밋에 있던 선언의 위 변경에는 수정 이력을 남긴다. 신규 작업의 기준을 바꿔 기존 선언을 신규로 취급하지 않는다.
- 생성일이 확인되지 않는 기존 코드만 `@created unknown - 이력 확인 불가: 구체적 사유`를 허용한다. 새 코드의 실제 날짜, unknown 허용 사유, 목적·사용처·수정 이력 누락은 diff 리뷰로 확인한다.
- 자동 생성 코드·record 자동 접근자·람다 본문에는 주석을 복제하지 않는다. 익명 클래스에 직접 선언한 메서드는 포함한다. 기재된 모든 `@modified`에는 유효한 날짜와 목적이 있어야 한다.
- 자동 검사는 API Gradle `apiDocsCheck`로 연결한다. 이 예외는 Flutter/Dart·JS/TS에 적용하지 않는다.
