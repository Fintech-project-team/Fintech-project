# 현재 MVP 범위 — 기능 정의서 v0.3

기준은 사용자가 제공한 **MVP 기능 정의서 v0.3(2026-10-07)**와 2026-10-08 후속 요청이다. 예전 P01~P13은 변경 이력이며 현재 구현 ID는 F01~F13과 F01-a다. 이번 문서는 구현·검증할 기준을 정리한 것이며, 기획 가설의 사용자 검증 완료를 뜻하지 않는다.

## 목적과 현재 범위

정기 월급생활자가 전체 자산 대신 **다음 월급일까지 쓸 수 있는 돈**을 쉽게 파악하고 소비 판단에 활용할 수 있는지 검증한다. 급여 통장 **1개**, 사용자의 수동 입력, 가입 후 **첫 월급일 전까지**를 기준으로 한다.

쓸 수 있는 돈 = 급여 통장 잔액 − 모아둘 돈 − 아직 안 나간 예정 지출.

금액·상태 변경은 [계산 규칙](calculation-rules.md), 저장·요청 경계는 [데이터 계약](contracts.md)을 따른다. 개발·테스트·시연 데이터는 합성 사례를 사용한다. 제품의 수동 입력 기능을 자동 계좌 연결이나 거래 수집으로 설명하지 않는다.

| ----- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |

이번 최소 구현은 Must부터 진행한다. F07·F12는 Should 지위를 보존하며 별도 작업으로 선택할 수 있다. 다음 사용자 지정 단계는 **예정 지출 입력·분류를 돕는 LLM**이며, F07 완료를 기다릴 필요가 없다.

## 화면과 완료 동작

| 화면                     | 필요한 동작                                                                                   |
| ------------------------ | --------------------------------------------------------------------------------------------- |
| 01-1 온보딩 1/3          | 월급일과 급여 통장 잔액 입력                                                                  |
| 01-2 온보딩 2/3          | 모아둘 돈 등록과 현재 계산 미리보기                                                           |
| 01-3 온보딩 3/3          | 예정 지출 등록과 쓸 수 있는 돈 미리보기                                                       |
| 01-4 설정 완료           | 첫 쓸 수 있는 돈과 계산 요약                                                                  |
| 02-1 홈                  | 쓸 수 있는 돈, D-day, 계산 요약, 급여 통장 잔액, 두 항목 요약                                 |
| 02-2 계산 내역           | 급여 통장 잔액 → 모아둘 돈 → 아직 안 나간 예정 지출 → 쓸 수 있는 돈                           |
| 02-3 잔액 다시 입력      | 새 잔액, 이미 나간 예정 지출 체크, 변경 미리보기                                              |
| 03-1 예정 지출 목록      | 앞으로 나갈 돈·이미 나간 돈 구분과 이미 나갔어요 처리                                         |
| 03-2 예정 지출 추가·수정 | 이름·금액·예정일·매월 반복 입력, 변경 미리보기, 삭제                                          |
| 03-3 모아둘 돈 목록      | 합계·항목·현재 계산                                                                           |
| 03-4 모아둘 돈 추가·수정 | 이름·금액, 변경 미리보기, 삭제                                                                |
| 03-5 내 정보             | 월급일·급여 통장 잔액 수정 진입. F07/F12 진입점은 선택 구현 상태와 구분                       |
| 04-1 계좌 연결           | F07 Should 화면. 연결 잔액·최근 출금·예정 지출 자동 연결. 현재 Must 완료 조건에 포함하지 않음 |
| 04-2 전체 자산           | F12 Should 화면. 계좌 1개의 잔액·합계. 현재 Must 완료 조건에 포함하지 않음                    |

매월 반복 입력은 메타데이터다. 이번 기간에 등록한 예정 지출 1건을 다루며 다음 기간 자동 생성·중복 생성은 구현하지 않는다. 월급일 변경·첫 월급일 도달 시 동작은 [미결정 정책](calculation-rules.md#구현-전에-결정할-경계)에 남긴다.

## 필수 동작의 차이

- **03-1 이미 나갔어요:** 아직 안 나간 지출을 이미 나간 상태로 바꾸면서 같은 금액을 앱에 입력된 급여 통장 잔액에서 한 번 차감한다. 쓸 수 있는 돈은 유지된다. 실제 은행 출금 기능이 아니다.
- **02-3 잔액 다시 입력:** 사용자가 입력한 현재 잔액으로 덮어쓴다. 그 잔액에 이미 반영된 지출을 체크하면 상태만 변경하고 같은 금액을 다시 차감하지 않는다.
- **항목 변경 미리보기:** 임시 계산이다. 저장 실패 시 확정 데이터에 적용된 것으로 표시하지 않는다.
- **F07 이전:** 실제 소비 자동 수집·사용액 집계는 없다. 현재 잔액을 다시 입력해 보정하며 이를 소비 이력 통계로 추정하지 않는다.

## 화면 용어

제공 문서의 UX Writing Guide v1.0 표를 적용한다. 기획·내부 모델의 '목적자금'은 화면에서 '모아둘 돈'으로 표현한다.

| 쓸 수 있는 돈                | 사용 가능 금액, 가용금액, 사용 여유, 남은 금액 |
| 급여 통장 잔액               | 통장 잔액, 현재 잔액                           |
| 모아둘 돈                    | 목적자금                                       |
| 예정 지출                    | 출금 예정, 다가오는 예정 지출                  |

| 계산 내역                    | 산출 근거, 계산 근거                           |
| 전체 자산                    | 총 자산                                        |

## 직후 LLM과 이후 확장

Must 흐름 다음에 **예정 지출 입력·분류 보조 → 사용자 확인 → 기존 F02 저장·F09 재계산**을 연결한다. 자동 거래 분석, 자동 확정, LLM의 최종 금액 계산을 이 기능과 혼동하지 않는다. 세부 연동과 후속 범위는 [확장 기준](EXTENSION_POINTS.md)을 따른다.

독립 배분 화면·What-if·계좌별 부족·은행 이동 안내·3계좌/3개월 거래 수집·Google/Kakao 로그인은 새 정의서의 Must가 아니다. 과거 계획을 이유로 이번 완료 조건에 되살리지 않는다. 실제 금융기관 연결·자동이체는 계속 현재 범위 밖이다.

E2E 체계와 디자인 시스템 구축은 사용자 요청에 따라 보류한다. 해당 기능의 필요한 계산·저장·화면 검사를 생략한다는 뜻은 아니다. 기존 Android 실제 기기 시연 목표는 유지하지만 이번 문서 정합성 작업의 완료 조건은 아니다.

제공된 본문을 기준으로 정리했으며, 별도 MVP 검증 계획·와이어프레임 V3·링크된 프로토타입의 화면 동작은 확인되지 않았다. 불일치가 확인되면 최신 결정과 관련 문서를 함께 갱신한다.
