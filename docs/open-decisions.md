# 남은 설계 작업 — 확정 사항 재질문 금지

개정일 2026-10-15. 현재 사용자에게 즉시 다시 선택을 요청할 제품 항목은 없다. 최신 업무표와 충돌하는 과거 기준은 [검토 보고](reconciliation-report.md)에 기록하고 최신 기준으로 진행한다. 아래는 개발 중 채울 값·산출물이며 이미 결정한 정책의 보류가 아니다.

## 과거 C 항목의 처리

- C01~C03은 확정 유지: 기존 세션 PIN 복구, 급여 입금 후 지출 반영, 선택 잔액 합산.
- C04는 복원 직후 연결0·선택0·미계산 → 지정 계좌 선택 후 기준 금액 검증으로 단계 분리한다. 새 제품 정책 선택이 아니다.
- C05는 연결 전 목록/건수/버전, 연결 후 금융 자료, 의무 출금/급여 입금 계좌를 데이터 계약에 보완했다. 물리 테이블 수를 자동 증가시키지 않는다.
- C06은 총 2명·공동 PM으로 해결했다. C07의 과거 계정 수·HMAC 이력은 현행 요구가 아니다.
- C08은 결과에 최초·최대·종료 부족 의미를 명시했다. C10은 우발 입력 수신 가능성과 폐기를 구분하고, C11은 일중 순서를 만들지 않는다.
- C12의 구현 패키지는 담당자 선택이다. C14는 토큰 종료/소실 시 식별 입력부터 새 로그인, 유효 토큰이면 기존 세션 재확인이다.
- C09의 모호한 `category`는 v0.6 계약에서 제외한다. v0.7에서는 기존 네 거래 분류의 `transactionType`을 쓰는 **설계 권장안**으로 한정하고, 반복 후보는 ID·이름·이유·근거로 표현한다. 별도 소비 카테고리를 추가한 결정이 아니다. API/화면 담당자가 의미·응답 계약을 확인한다.
- C13은 실패 연출을 **계정의 연결 흐름별 최초 시도 1회**로 관리하는 재현 가능한 구현 권장안이다. 실제 서버 실패와 구별하며 같은 흐름 재시도에서 재추첨하지 않는다. 사용자가 이 세부 구현안을 직접 선택했다고 기록하지 않는다.

M2·M3·M4·M5·M6·인증 입력 수명·API 비용은 확정돼 [제품 기준](product-baseline.md)과 [계산 기준](calculation-rules.md)에 반영했다. 검증 미실행, 기술 선택 미완료, 사용자 정책 미결정은 같은 상태가 아니다.
