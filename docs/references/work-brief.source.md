**2. 개발 시 확정 사항**

- 실제 금융기관 연동 없이 **서버에서 준비된 더미 금융 데이터를 제공**합니다.
- 서버는 데이터를 제공하고, **사용 가능 금액 계산은 Flutter에서 수행**합니다.
- 사용자가 추가·수정한 예정 지출, 모아둘 돈 등은 앱 종료 및 재로그인 후에도 유지되어야 합니다.
- 이미 출금된 거래와 향후 출금 예정인 항목은 구분하여 중복 차감되지 않도록 합니다.
- v0.6 기능을 우선 설계하되, v0.7\~v1.0 확장 가능성을 고려합니다.

3\. **사용자 식별 및 데이터 저장 구조 설계**PAYSE는 실제 본인인증을 진행하지 않습니다. 이름과 전화번호는 사용자 식별을 위한 입력값으로만 활용하며, 금융 거래 데이터는 서버에서 더미 데이터로 제공합니다.다음 사항을 검토해 주세요.

1. 이름·전화번호 기반 사용자 매핑 및 내부 사용자 ID 발급 방식
2. 동일 사용자 재접속 시 기존 데이터 유지 방법
3. 별도 로그인 수단 및 세션 관리 방식
4. 사용자별 예정 지출·모아둘 돈 저장을 위한 DB 구조
5. 사용자 간 데이터 접근 차단 방법
6. 개인정보 최소 수집 및 보관·삭제 기준

**실제 본인인증 기능은 개발 범위에서 제외합니다.**&#xC774;름·전화번호만으로 기존 사용자 계정에 접근할 수 있는 구조는 피하고, 데모 환경에 적합한 간단한 인증 방식을 제안해 주세요.\
