# 작업 명세 작성

1. TEMPLATE.json을 새 작업 ID의 JSON으로 복사한다.
2. 실제 기준 커밋·브랜치·역할·허용 경로·완료 조건·필수 문서를 적는다. 역할은 사람 수가 아닌 작업 범위이며 담당자는 Issue/PR 또는 작업 기록에 따로 적는다. 배정 기준은 docs/ownership.md를 따른다.
3. 수정 범위는 역할에 허용된 경로와 allowedPaths가 겹치는 부분이다. integration도 작업별 범위를 따른다.
4. 역할 이름만 바꿔 범위를 우회하지 않는다. 명세 변경은 PR에서 검토한다.
5. 다른 작업의 명세는 유지한다. 연속 작업으로 승인된 범위는 새 명세에 명시한다.

작업 시작·종료 기록은 [AGENT_REVIEW.md](../harness/AGENT_REVIEW.md)를 따른다. 작업 명세 JSON은 수정 범위와 완료 조건을, PR 본문은 네 지표와 근거를 관리한다.
PR 생성 전에는 .harness/reviews/<작업ID>.md에 기록한다. 기록을 남기기 위해 다른 담당자의 명세나 공통 문서를 수정하지 않는다.
