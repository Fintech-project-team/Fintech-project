## 금융사 표시 연출

- 첫 금융사 연결 때 기관별 10% 확률로 실패 연출, 한 흐름에서 최대 2곳. 순차 처리 지연은 1~1.5초다.
- 실패 행의 다시 시도는 2~3초 뒤 표시상 완료하며 재실패하지 않는다. 진행 중인 기관이 남으면 제외 계속하기 버튼을 보이지 않는다.
- 최종 실패 1곳이면 ‘○○ 제외하고 계속하기’, 2곳 이상이면 ‘N곳 제외하고 계속하기’. 계산할 은행 계좌가 없으면 진행을 막는다.
- 최종 목록은 동의한 기관−제외 기관. `POST /institution-links`를 한 논리 작업으로 실행한다. 실제 API 오류는 09-3 등 실제 오류로 안내한다.
- 모두 표시상 완료된 경우도 API 성공 후에만 자동 이동한다. 와이어프레임 화면 목록의 12-3 ‘쓰기 없음’은 동작 설명의 POST와 불일치하므로 이 기준으로 보완한다.
- 진행자의 개발 설정에서 연출을 켜고 끈다. 사용 화면에 노출하지 않는다. 구현 권장안은 계정의 연결 흐름마다 최초 시도 한 번 추첨하고 동일 흐름 재시도에서 재추첨하지 않는 방식이다. 개발자가 seed/기관 순서를 고정해 재현성을 검증한다.

잠금 중 보존과 화면 이탈 시 폐기는 서로 다른 사건이다. 상세 계획의 ‘초안은 이탈 시 폐기’가 10분 잠금에서 입력을 지우는 동작으로 구현되지 않도록 한다.

후속 사용자 답변이 와이어프레임보다 최신이다. 따라서 09-7의 ‘계속 E 포함’에는 급여 미입금 대기 예외를 두고, 09-12 복구는 일반 신규 세션 발급으로 구현하지 않는다. 선택한 예금·적금 합산은 01-1/D9와 일치한다.

## 예시와 한계

와이어프레임 예시는 B=2,000,000, R=400,000, 월급 전 E=500,000, O=0으로 U=1,100,000이다. 삼성카드 10/27 150,000원은 10/25 전 E에 포함되지 않는다. 현대 사용내역 6,800+48,200+70,000+175,000=300,000이다. 이 숫자는 최종 데모 확정값이 아니다.

‘할부 2/6’은 거래 원문에 있는 정보의 조회 표시다. 가상 신규 할부·이자 계산을 v1.0에 추가한 것으로 해석하지 않는다. UX Writing Guide 원문은 별도 미열람이므로 해당 가이드 전체 준수를 확인했다고 보고하지 않는다.

디자인 담당자는 화면 색·폰트·간격 등을 정하되 공통 계산 의미·저장 경계·오류 규칙을 바꾸려면 관련 담당자와 확인한다. 최신 화면 규칙이 나온 부분까지 ‘디자인 전부 보류’로 되돌리지 않는다.

## 이번 변경과 와이어프레임의 의도적 차이

- 10-2/10-3/09-12: 네 필드 화면을 합성 이름·전화번호와 별도 코드 흐름으로 축소한다. 최신 업무표가 우선이므로 기존 와이어프레임의 주민번호·통신사 UI를 구현 근거로 쓰지 않는다.
- 인증 실패 시 같은 흐름 입력은 유지하고 성공·취소·이탈·프로세스 종료에만 폐기한다.
- 03-1/03-2: v0.9에서 자동 지급 연결의 확인 필요 표시와 사용자 수동 정정을 추가한다. 03-1은 근거가 부족한 예정 지출에 '확인 필요' 칩과 상단 안내, 이미 나간 돈에 연결된 출금을 표시한다. 03-2는 '지급 연결' 행에서 06-4 시트로 연결·해제한다. 같은 출금 이중 연결은 09-31, 연결 해제 시 보호 배정 복원 안내는 09-32로 표시한다. 새 화면이 원래 와이어프레임에 이미 있었다고 주장하지 않는다.
- 연간 분석은 v0.7에서 02-4 상단 '최근 1년 소비' 요약과 02-7 월별 소비로 거래 흐름에 연결한다. 구매·이용일 우선/출금일 대체와 환불 반영일 기준, 대상·누락(09-30)·근거를 표시한다. 소비 카테고리나 새 AI 보고서 화면을 임의 추가하지 않는다.
- 01-3/02-1/03-2/03-5의 모든 금액 산출은 Flutter다. 서버 저장 응답의 새 스냅샷을 받은 뒤 로컬 계산값을 표시한다.
